# 绯月桌面精灵项目约定

所有新增和修改的应用弹窗都沿用现有月印标题栏。正常面板通过 `desktop/panel-window.mjs` 的 `createPanelWindow` 建窗，页面使用 `feiyue-surface.css`、`fy-titlebar` 和 `fy-caption`，仅保留一行窗口标题。Windows 窗口按钮复用原生覆盖层，为按钮预留空间，业务控件可以独立点击。

头顶气泡和消息确认框保留透明外形与原有交互，同样走共用建窗入口，使用 `fy-compact` 紧凑标题栏。新页面在 `desktop/source-updates.mjs` 登记共享样式，确保构建与热加载均可用。文件选择器等操作系统提供的界面沿用系统外观。

修改后运行 `tools/test-panel-titlebar-electron.mjs`，核对浅深色、窄窗口、标题栏数量和按钮避让。

新增或修改菜单弹窗时，按[开发注意点](docs/DEVELOPMENT.md#windows-重启后菜单弹窗首击可见性)复用主动显示逻辑，并从正式自绘菜单做冷启动首击验证。

右键菜单（自绘窗口，`menu-layout.json` 的 `icon` / `tone`）、面板组件（`.fy-panel` 的卡片、页签、徽标、分页等）、记录列表分页与动效规则见 [桌宠界面开发说明](docs/DESKTOP_UI_GUIDE.md)；新增或修改菜单和面板时先读它，改完用 `tools/capture-menu-panels-electron.mjs` 截浅深色图对照。

## 本机桌宠功能更新

开发工作区与本机实际安装目录分开管理。桌宠功能在正式安装版更新并受控重启后生效。每次本机功能更新按以下顺序执行，具体路径、验证方法和恢复步骤按当次安装基线确定。

1. **识别安装版。** 读取桌面快捷方式的应用参数、登录启动项和运行中主进程实际加载的应用目录。多个版本可能共用同一个 Electron 可执行文件。
2. **准备候选。** 在开发工作区开发和测试，以实际安装版为基线合入本次已确认的改动，保留用户资料及其他工作区的改动。隔离验证后，在实际待发布项目根目录的 `RELEASE_REVIEW.md` 追加差异、验证结果与恢复步骤，并按既有规则取得本次部署确认。
3. **安装、重启和验收。** 按授权更新安装目录，通过应用自己的重启流程等待在途任务，核对新进程加载的目录、快捷方式及登录启动目标，从实际入口验证本次功能。在开发纪要和发布纪要记录版本、实际结果及待核对项。
4. **最后向重启后的绯月 API 交付已确认的更新。** 重启前可以在调用方保存草案。按下节规则向用户展示最终登记清单并取得明确确认后，读取新实例的 `GET /infoguide`，将已确认的清单作为一批提交。发布纪要记录入队回执及批次编号，整批登记结果以绯月的最终核对回执为准。接口未就绪或回执丢失时保留清单与批次标识，恢复后先查询原批次，再按原确认内容续办。

正式安装版、基线和候选验证树共用本机 GGUF 模型。复制安装树时排除 desktop/models，需要真实推理时，将验证树的 desktop/models 用目录联接指向正式安装版使用的公共模型目录。

## 通过绯月提交花园登记

所有调用方均须在向绯月提交登记批次之前，向用户展示实际准备登记的完整清单，取得对该清单的明确确认。用户同意部署或表示愿意登记后，仍须核对具体内容。未确认时，草案保留在调用方；确认后才可进入绯月的待处理任务列表。若目标、字段值、版本或实际发布结果有变化，向用户展示差异并重新确认，再提交或继续执行。

API 沿用现行花园登记内容、字段含义和填写规则。清单按原有口径列出项目和功能归属、各项新增或修改、变更前后值、版本变化及实际发布结果。不适用的类别沿用现行“无需更新”规则。绯月只执行已确认清单中的变更；批次编号、步骤进度和执行回执属于本地任务记录。

在「网页角色组件」下，绯月（桌面精灵）、语言学习对练、题库代行、绯月知识库、报纸模块各自作为同级功能登记。按实际发布内容归属：桌宠本体和通用入口的更新记入绯月；四个独立功能及其专用服务端更新记入相应功能。共用绯月入口本身不产生额外版本。一次发布确实改变多个功能时逐项列入，每个功能只计一次。保留既有部署明细及其当时的归属和版本。

正式安装验收后使用 `http://127.0.0.1:8765/infoguide` 核对实例和调用契约。每次调整 REST 的路由、字段、认证、状态或恢复方式，同时更新 `desktop/local-rest.mjs` 的调用说明、[调用手册](docs/LOCAL_GARDEN_API.md)及相应契约测试。本机升级的发布纪要保留实际安装版本、重启核对、用户清单确认、批次编号和最终回读结果。

角色动画默认使用固定展示尺寸。只有用户或已确认的动作规格明确指定尺寸时才能切换。气泡、进度、结果、面板、工作区空间和普通状态切换均不得挤压或缩放角色；调整提示自身的位置。显示像素密度沿用现有 DPI 对齐规则。
