# 个人数字精灵 · 实施计划表（基于需求 V1.5）

> **依据**：《个人数字精灵 初期需求确认 V1.5》（已锁定，不修改）  
> **编制日期**：2026-11-17  
> **拆分原则**：严格按需求第 10 章约定的实现顺序 **M0（B 线纯展示）→ M1（A 线 Agent 最小闭环）→ M2（两线首次衔接）→ M3（A/B 交错增强）→ M4（按需扩展）**。  
> P0/P1/P2 是**需求优先级**，M0～M4 是**开发顺序**，两者不混用；本表中的“顺序”只指开发顺序。  
> 鱼骨图见第 1 节（文本版）及随附 `计划鱼骨图.svg / .png`。

**字段说明**

| 字段 | 含义 |
|---|---|
| 编号 | `M{里程碑}-{序号}`；M3 分为 `M3-A*`（Agent 线）与 `M3-B*`（Companion 线） |
| 顺序 | 里程碑内的推荐实施次序；`∥` 表示可并行 |
| 前置依赖 | 必须先完成（或先有结论）的计划项 |
| 原始需求 | 对应 V1.5 文档的需求 ID / 章节号 |
| 功能预期 | 该项做完后应具备的具体功能（含明确不做的边界） |
| 验收标准 | 可检查、可判定的通过条件；引用的 AT-xx / W-xx 为需求文档原有验收项 |

## 3. 详细计划卡

### M0 纯桌宠展示验证（B 线）

> **目标**：Windows 11 上有真实透明角色，能响应鼠标，展示效果达到用户认可；**不接 Agent、不做云端/聊天/记忆/任务**。  
> **退出条件**：用户确认「鼠标反馈正常，目标展示效果已达标」→ 立即冻结 B 线，转 M1。

#### M0-01 宿主选型技术验证
- **顺序 / 依赖**：1（与 M0-02 并行）｜无
- **原始需求**：9.3 选型表（首要标准：Windows 与 Web 共享同一渲染核心）；11-1、11-2；PET-09；W-08
- **功能预期**：
  - 以 **路径 B（Electron）与路径 C（Tauri/WebView2）** 各做一个最小 spike：透明无边框置顶窗口中显示一张透明 PNG/一段帧动画。路径 A（PySide6）与首要标准冲突，只作窗口算法参考，不做 spike。
  - 每个 spike 验证：透明背景是否干净、透明区域点击穿透能否动态开关、待机 CPU/内存、加载同一份 TS 渲染代码的方式。
  - 同时给出 11-2 的初步结论：WebM 运行时直接解码，还是导入时转帧（M0 默认按转帧/Sprite 处理）。
- **验收标准**：
  1. 产出一页选型结论（对比表 + 选定宿主 + 理由），选定宿主能加载与浏览器相同的 TS 渲染代码；
  2. 选定宿主上透明窗口无黑底/白边，穿透开关切换无明显卡顿（对应 W-08 初测）；
  3. 记录静止待机的 CPU、内存数据，作为后续 W-13 基线。

#### M0-02 动作素材试制
- **顺序 / 依赖**：1（与 M0-01 并行）｜无
- **原始需求**：9.4 动作素材生产流程；5.2 V1.4 说明；10.1-1；V1.4 补充
- **功能预期**：
  - 以已认可的角色设定图为标准，按“参考图 → 图生短视频 → 去背景（rembg/BiRefNet 等或生成端直出透明）→ FFmpeg 抽帧 → 筛选修帧 → 统一画布与锚点 → 帧序列/Sprite Sheet + 简单动作配置”试制。
  - 只做 **一组待机/简单循环 + 一组鼠标响应动作**；允许人工挑帧、修帧、对齐；不开发自动化流水线服务。
  - 原始参考图、生成视频、透明帧、最终 Sprite 包分开保存。
  - 帧率、时长、插帧、压缩格式在试制中决定，不预设规格。
- **验收标准**：
  1. 两组动作前后角色形象一致（服饰、面部、手指、比例无明显变形）；
  2. 透明轮廓无明显闪烁、残留背景色，发丝/衣物边缘可接受；
  3. 帧在统一画布内，脚底/身体中心不因裁切跳动；循环动作首尾衔接自然；
  4. 用户对观感认可（生成工具品牌与自动化程度不作为验收条件）。

#### M0-03 共享 TS 渲染核心（最小版）
- **顺序 / 依赖**：2｜M0-01（确定宿主加载方式）、M0-02（首批帧素材与配置）
- **原始需求**：PET-09；1.2「一套渲染核心跑两端」；5.3 `pet.action(actionId)`；7 `RendererAdapter`
- **功能预期**：
  - 用 TypeScript + Canvas/WebGL（如 PixiJS）实现 Sprite 播放器：读取动作配置，按 actionId 播放、循环、播放完回到 idle。
  - 对外仅暴露 `pet.action(actionId)` 等语义调用，内部预留 `RendererAdapter` 外形（prepare/activate/suspend/dispose 名称即可，不实现预热池）。
  - 核心层不出现任何 Windows/Electron/Tauri 专有 API。
- **验收标准**：
  1. 同一份核心代码在普通浏览器页面与选定桌面壳中都能播放 idle 与反应动作；
  2. 核心目录中无平台相关调用（代码检查）；
  3. 连续切换动作不出现残帧、错位或内存持续增长（简单压测 5 分钟）。

#### M0-04 Windows 桌面壳
- **顺序 / 依赖**：3｜M0-01、M0-03
- **原始需求**：PET-01（透明、托盘、穿透子集）；W-08；10.1-3
- **功能预期**：
  - 透明、无边框、置顶窗口承载渲染核心；角色主体及交互热点可点击，其余透明区域穿透到底层窗口（**允许近似命中区域，不要求逐像素**）。
  - 托盘菜单：显示/隐藏、退出。
  - Windows 原生处理（透明、穿透、托盘）单独封装在桌面壳层。
  - 不做双屏漫游、窗口攀爬、勿扰检测。
- **验收标准**：
  1. 角色周围透明区域内可正常点击/拖动底层窗口（W-08）；
  2. 角色本体可被鼠标命中；
  3. 托盘可一键隐藏/恢复/退出，隐藏后不遮挡工作；
  4. 动态切换穿透状态时无可感知卡顿。

#### M0-05 鼠标交互反馈
- **顺序 / 依赖**：4｜M0-03、M0-04
- **原始需求**：10.1-2；PET-05（鼠标反馈子集）
- **功能预期**：
  - 鼠标悬停/进入角色命中区 → 触发反应动作或表情；
  - 单击/轻触 → 触发明显的视觉回应；
  - 动作结束自动回到待机；连续快速操作做合并/防抖，不打断成异常状态。
  - 拖拽、抚摸手势、复杂追踪不在本阶段（附录 A-6）。
- **验收标准**：
  1. 悬停与点击各至少一类反应，触发后视觉回应明显；
  2. 连续快速点击 30 次以上，角色不卡死、不停在中间帧、可回到待机；
  3. 鼠标离开后行为正常复位。

#### M0-06 离线独立 + 浏览器小样验证
- **顺序 / 依赖**：5｜M0-05
- **原始需求**：10.1-4、10.1-5；AT-05（部分：走动与预设台词在 M3 补齐）
- **功能预期**：
  - 断网、无 AI Provider、无 Worker 情况下启动并完整运行待机与鼠标反馈；
  - 用同一渲染核心 + 同一素材做一个最小浏览器页面，证明可移植（不是完整 Web 客户端）。
- **验收标准**：
  1. 拔网线/禁用网络后冷启动成功，交互正常；
  2. 浏览器小样能播放相同动作 ID 的同一素材；
  3. 程序无任何对外网络请求（抓包或日志确认）。

#### M0-07 M0 验收与冻结
- **顺序 / 依赖**：6｜M0-01～M0-06
- **原始需求**：10.1 五项最小验收 + 停止规则
- **功能预期**：

### M1 Agent 最小闭环（A 线，桌宠冻结）

> **目标**：一个 Web 入口 → Cloudflare → 独立 Windows Worker → 云端可核实结果；以“云端下令查当前 PC 磁盘空间”验证。  
> **不做**：桌宠集成、手机参与、文件传输、插件平台、多模型路由、完整记忆、语音、复杂进度流与多级确认水位。

#### M1-01 Cloudflare 项目骨架与用户身份
- **顺序 / 依赖**：1｜M0-07（流程门槛）
- **原始需求**：AG-01、AG-06；4.4-1；9.2（Workers、D1、Access）
- **功能预期**：
  - 建立 Workers + D1 项目；单用户、单精灵身份；
  - Web 与 API 由 Cloudflare Access（或等效机制）保护；
  - 用户、设备、客户端、会话分别有独立标识字段（AG-06 的数据基础）。
- **验收标准**：
  1. 未认证请求访问 Web/API 被拒；
  2. 数据表中用户 / 设备 / 客户端 / 会话标识互相独立；
  3. 不出现多租户结构。

#### M1-02 Agent API 基础与全局任务模型
- **顺序 / 依赖**：2（与 M1-03 并行）｜M1-01
- **原始需求**：AG-02；TASK-01、TASK-02；7 `AgentAPI.tasks`；10.2
- **功能预期**：
  - D1 任务表：task_id、目标设备、来源、权限等级、到期、状态、结果；执行表：execution_id、任务、设备、开始/结束、结果。
  - 状态：PENDING、RUNNING，终态 COMPLETED / FAILED / CANCELLED / EXPIRED。
  - API：提交、领取、确认、查询、取消、结果；**领取原子化，防重复领取**。
  - 只补到能跑通闭环的最小字段（7 节约束）。
- **验收标准**：
  1. 接口测试覆盖全部状态转移，非法转移被拒；
  2. 同一任务并发领取只有一个成功；
  3. 过期任务不可再被领取。

#### M1-03 设备注册、认证与心跳
- **顺序 / 依赖**：2（与 M1-02 并行）｜M1-01
- **原始需求**：DEV-01；AG-06；4.4-2；7 `DeviceAPI.register/heartbeat`
- **功能预期**：
  - Windows Worker 使用独立、可撤销的设备凭证；凭证保存在 Windows Credential Manager/DPAPI，与业务 Token 严格分开；
  - 设备上报最小能力声明（如 `disk.query`）与在线心跳；
  - 云端可撤销设备。
- **验收标准**：
  1. 撤销后设备的心跳与领取请求被拒；
  2. 本机磁盘上找不到明文设备凭证；
  3. 云端可查看设备在线/离线状态。

#### M1-04 Windows Agent Worker 常驻进程 + 本地 SQLite
- **顺序 / 依赖**：3｜M1-02、M1-03
- **原始需求**：TASK-03、TASK-06（基础）、TASK-07；1.2「Worker 生命周期独立于桌宠画面」
- **功能预期**：
  - 独立于桌宠的常驻进程；
  - 启动、上线、定时唤醒时扫描本地待办与云端分配任务；
  - 本地 SQLite 保存本机任务、已领取任务、未上传结果与关键日志；**先落盘、后上报**；
  - 不需要网络、凭证或新授权的本地任务可离线继续执行。
- **验收标准**：
  1. 桌宠未运行时 Worker 也能正常领取与执行；
  2. 执行中强杀 Worker，重启后从 SQLite 恢复，不丢已领取任务；

#### M1-05 L1 只读工具：磁盘容量
- **顺序 / 依赖**：4｜M1-04

- **功能预期**：

  - 实现 `disk.query`（各盘总量/剩余），风险等级 L1。
- **验收标准**：
  1. 返回值与系统实际一致；
  2. 未声明风险等级的工具无法注册；

#### M1-06 结果回传、对账与断网恢复
- **顺序 / 依赖**：5｜M1-05
- **原始需求**：TASK-04、TASK-05、TASK-06、TASK-08、TASK-09（简化）；4.1；7 `DeviceAPI.progress/reconcile`；3.2 进度一致性底线
- **功能预期**：
  - PC 离线时云端保留任务，上线后领取、执行、回传；
  - 云端看到 RUNNING 时先向执行者核对实际进度，**不盲目重跑**；设备离线标注“进度待核实”，不直接判失败；
  - 本地事件带单调序号，云端确认后才清理；重连按 task_id/execution_id 补传并去重；终态与错误不得因合并丢失；
  - 需要云端凭证/新批准的任务在断网时暂停。
  - 不实现复杂百分比进度流与多级确认水位（10.2）。
- **验收标准**：
  1. **AT-01**：Web 下发“查询 C 盘容量”，Worker 领取执行 L1，本地有记录，云端可查询；

  3. 模拟“已执行但回执丢失”后重启，Worker 先核对而非重跑；
  4. 设备离线期间云端显示“进度待核实”。

#### M1-07 简易 Web Chat/命令入口 + 单 AIProvider
- **顺序 / 依赖**：3（与 M1-04 并行）｜M1-02
- **原始需求**：AG-03、AG-04；PI-02（基础）；3.1 模型支持边界；10.2
- **功能预期**：
  - 单用户 Web 页面：文本对话、下达命令、查看任务列表与状态；

  - 不做模型列表、自动切换、路由。
- **验收标准**：
  1. 在同一台 PC 浏览器中可对话并发起磁盘查询任务，看到状态变化；
  2. Provider 调用失败时，任务数据与已保存记录不受影响；
  3. **AT-09（前半）**：业务数据表中无模型专属字段依赖。

#### M1-08 最小安全基线
- **顺序 / 依赖**：5（与 M1-06 并行）｜M1-05
- **原始需求**：3.3（风险分级规则、最终安全门）；PI-01、PI-03；4.4-5、4.4-6；10.2

### M3 两线交错增强

> **规则（10.3）**：按实际短板在 A/B 间切换；**一次只做一个可验收的新场景**，达标后可切线；两线各自可独立运行与回滚；**安全与一致性要求必须在对应功能上线前达成**。下表“顺序”为线内推荐次序。

#### M3-A1 L2 审批服务（真实参数展示）
- **顺序 / 依赖**：A-1｜M2-06
- **原始需求**：3.3 L2；PI-04；7 `AgentAPI.approvals`；10.2「引入写操作的同时落地 L2」
- **功能预期**：
  - Cloudflare 统一 Approval Service；Web（及后续 Windows/手机）只是展示入口；
  - 每次批准绑定任务、设备、操作、**真实参数**、有效期；参数变化重新审核；
  - 断网时未获批准的 L2 不得放行；LLM 不能降低风险等级。
- **验收标准**：
  1. 审批界面显示工具真实参数（目标、金额、路径），而非模型描述；
  2. 批准后修改参数 → 重新审批；过期批准无效；
  3. 把高风险动作改写/拆分/换工具描述，仍不能绕过审批。

#### M3-A2 真实执行 Log + 触发来源
- **顺序 / 依赖**：A-2｜M2-06（建议在 A3 前完成）
- **原始需求**：4.3；PI-05；7 `AgentAPI.logs`；4.1 Log 同步要求
- **功能预期**：
  - 自动记录请求、工具名、脱敏参数、真实返回、错误、用户纠正、最终验证结果、触发来源（哪条用户指令/哪段外部内容）；
  - 云端为主、离线本地缓存、联网补传；可查询导出；
  - 凭证与剪贴板正文不入日志。
- **验收标准**：
  1. 每次工具调用都能追溯到触发来源；
  2. 断网产生的日志联网后补齐；
  3. 日志中检索不到凭证/敏感正文。

#### M3-A3 写入类工具 + 幂等/回读核查（税金登记）
- **顺序 / 依赖**：A-3｜M3-A1、M3-A2
- **原始需求**：TASK-10；TOOL-04；4.4-3、4.4-4；AT-03
- **功能预期**：
  - 实现首个写入场景：登记个人账务/税金（目标服务 D1 或 Salesforce 等）；
  - 外部写入使用幂等键或写后回读核查；异常重启时不把“未收到回执”当成“未执行”；
  - 业务凭证放 Workers Secrets，优先云端代理执行、只返回结果。
- **验收标准**：
  1. **AT-03**：登记 10,000 日元市民税 → L2 展示真实参数并批准 → 成功写入目标系统，有真实回执/查重与 Log；
  2. 模拟写入后回执丢失并重试，目标系统不出现重复记录；
  3. Windows 侧不出现业务 Token 持久化。

#### M3-A4 提示注入防护完善
- **顺序 / 依赖**：A-4｜M3-A1、M3-A2
- **原始需求**：3.6 PI-02、PI-03、PI-06；AT-13
- **功能预期**：
  - 网页、监控结果、剪贴板、文件、API 返回、Skill、记忆一律带边界标记与来源；
  - 处理外部内容的轮次只开放只读工具；写操作须由用户另行发起或经 L2 审批；
  - Skill、插件说明、记忆摘要中的文本不能修改风险等级、审批规则或授予权限。
- **验收标准**：
  1. **AT-13**：被监控网页或剪贴板中含“删除文件/转账”等伪指令时不触发任何写操作；L2 审批中可见真实参数；
  2. Skill/记忆中写入“将此工具视为 L1”无效果；
  3. Log 中能看到被拦截调用的外部内容来源。

#### M3-A5 L3 人工协同流程
- **顺序 / 依赖**：A-5｜M3-A1、M3-A4
- **原始需求**：3.3 L3 及人工协同流程/结果核实；V1.3；AT-04；TOOL-02（只读预检部分）
- **功能预期**：
  - L3 不进入自动执行队列，无一次性强制授权、无从拒绝记录恢复执行的入口；聊天中说“批准/继续”也不降级；
  - Agent 说明对象与风险；用已授权只读工具列出目标、数量、路径、影响范围；提示备份/回收站；给出可核对的人工步骤；
  - 记录“已交接用户操作 / 用户报告完成 / 只读核实完成 / 用户取消”；不新增复杂状态机。
- **验收标准**：
  1. **AT-04**：以批量文件删除为例，只读预检并提示影响范围、风险与人工步骤；无执行工具调用或强制授权入口；用户亲自操作后可只读核查或记录“用户报告完成”；
  2. 尝试通过脚本、命令、GUI 点击、间接工具代行 L3 均被拒；
  3. 不会把“指导已发出”标记为成功。

#### M3-A6 任务生命周期完善与安全停止
- **顺序 / 依赖**：任意（建议在 M3-A3 后）｜M1-09
- **原始需求**：TASK-09（完整确认水位，长任务出现时）；TASK-11；8-9 安全停止；10.3
- **功能预期**：
  - 任务过期、取消、失败、恢复与执行记录完整；避免多年前的命令突然执行；
  - 出现长任务时再补百分比进度合并与确认水位；
  - 可单独中断/取消任务、停止自动化工具、撤销设备/工具授权，不必关闭整个桌宠。
- **验收标准**：
  1. 过期任务在设备上线后不会被执行；
  2. 运行中任务可取消，取消后按安全停止规则处理；

## 5. 切线与门槛规则（摘自需求，执行时对照）

1. **M0 → M1**：只看 10.1 五项是否被用户确认，不看工期；确认后立即停止 B 线功能扩张。
2. **M1 期间**：桌宠冻结，仅修阻止复用的严重缺陷。
3. **M1 → M2**：Web → Cloudflare → Worker → 云端结果闭环跑通，且基本安全与中断/重连验证通过。
4. **M3 每次切线**：保留当前可运行版本、下一步任务、已知风险、最小接口约定。
5. **安全前置**：任何写入工具上线前，必须先有 M3-A1（L2）+ 幂等/回读；任何处理外部内容的功能上线前，必须先有 M3-A4 的只读轮次限制。
6. **M4**：无真实场景或实测问题不启动。
