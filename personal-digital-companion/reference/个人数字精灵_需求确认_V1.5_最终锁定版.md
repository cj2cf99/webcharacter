### V1.5 简化决策（本次修订）

1. **记忆仅为陪伴辅助**：帮助角色显得更有人情味，按尽力原则摘要、归档及回忆；**不承诺每段历史一定能找到，也不要求记忆绝不丢失**。不得将记忆存储可靠性要求套用于任务结果、审批、业务写入和真实执行 Log。
2. **跨端协同保留构想、降低优先级**：当用户将来确实需要 PC/手机等多个端共同完成操作时，再由 Agent 编排协作；手机传文件和远端查询 PC 均只是示例，不作为首期必须实现的产品场景。Cloudflare ↔ Windows Worker 的基本任务闭环仍是 M1 基础通信，不等同于完善的多端协作产品。
3. **多模型只保留适配接口**：最初接通一个 AI Provider 即可；需要第二个时手动配置或替换适配器；不建设智能路由、自动择优、负载均衡或复杂模型管理后台。
4. **功能模块轻量化**：功能可通过明确的注册点增加，支持更新替换、停用/撤销，撤销后调用入口与授权失效；不建设通用插件商店、自动依赖解析、热更新平台或完整安装回滚体系。
5. **开发路线不变**：M0 只验证桌宠的展示效果与鼠标响应；达标即暂停，转 M1 Agent；两线之后交错推进。

### V1.4 动作素材流程补充（保留）

- **候选主路线**：用固定的角色设定图/标准参考图约束形象，生成简短动作视频，取得无背景画面（生成时直接带透明通道，或后期视频/逐帧抠图），再抽帧整理为透明 Sprite 动画素材。
- **制作流程与播放机制分开**：短视频主要是生产中间件，日常运行以透明 PNG/WebP 帧序列或 Sprite Sheet 为主；是否直接播放透明 WebM 留给复杂演出和实测，不是 M0 必需条件。
- **质量优先于工具链完备**：先用少量动作验证人物一致性、透明边缘、时间连续性、比例及锚点稳定性；允许人工挑帧、修帧、对齐，不提前开发自动化批处理平台。
- **不改变开发顺序**：M0 只需静止/待机与至少一种鼠标反馈动作表现达标，随后冻结桌宠原型，切到 M1 Agent；完整动作库后续交错扩展。

### V1.3 L3 风险操作调整（保留）

- **L3 改为人工协同操作**：Agent 负责提示风险、列出影响范围、建议检查/备份及人工步骤；高风险实际操作由用户在目标系统亲自完成，Agent 不调用执行工具代劳。
- **取消 L3 强制授权**：不再从拒绝记录申请一次性覆盖，也不因用户在聊天中确认就将 L3 降为 L2；L2 保留真实参数审批后由 Agent 执行。
- **协同不等于后台自动化**：可以通过已授权只读工具生成候选清单与核查结果；不得通过脚本、GUI 自动点击、间接调用其他工具等方式绕过 L3 的人工执行边界。
- **防误报完成**：Agent 只能将用户自行操作的完成情况标记为“用户确认”或在只读回查后标记“已验证”，不能把用户的意向当作实际执行结果。
- **开发里程碑不变**：M0 纯桌宠展示 → M1 Agent 最小闭环 → M2 首次衔接 → M3/M4 交错增强。

### V1.2 开发顺序调整（保留）

- **先 B 后 A、随后交错**：首先只做一个能响应鼠标、视觉效果达到目标的 **Windows 2D 桌宠展示原型**；达标即暂停 B 线扩展，转向 A 线 Agent 最小闭环；两线成熟后再衔接、轮流深化。
- **首轮展示原型不承担 Agent 功能**：无需 Cloudflare、聊天、记忆、审批、文件处理、窗口攀爬或完整 Web 客户端；保证桌面基本可用与渲染核心未来可复用即可。
- **以验收结果而非固定工期切线**：视觉效果、鼠标反馈、透明窗口/点击处理和离线可用达标后，冻结可运行版本、素材与接口边界；不追求先把桌宠所有 P0 功能做完。
- **P0/P1/P2 是最终产品的需求优先级，不等于开发时间顺序**；第 10 章采用 M0～M4 开发里程碑，避免与需求 ID 优先级混淆。
- **只调整进度与实施门槛**：原先已确认的双端共享渲染核心、双线独立、任务安全/恢复等长期需求继续有效，不因初期不开发而删除。

## 1. 产品目标与已经确定的原则

### 1.1 目标

系统既是能陪伴用户、在桌面及网页活动的**数字精灵**，也是能够使用工具、管理任务、访问授权服务、跨设备协作的**个人 Agent**。**核心目标是陪伴，以及 PC/Web 通用的同一个角色形象。**

1. **陪伴**：Windows 端独立卖萌、走动、攀爬应用窗口、文字气泡输出；无 AI API 或网络时仍能进行基础互动；不在不合适的时机打扰用户。语音输出为二阶段功能。
2. **实用管家**：按用户命令查数据、检索日记、登记记录、查磁盘空间、整理指定文件、监控网站；以固定工具与人工维护的 Skill 复用工作方法。
3. **可选跨端协作**：保留 Cloudflare 统一任务与授权入口；未来确有多端参与同一操作的场景，再由 Agent 协调 PC/手机/Web 的工作。具体双端流程只是构想，低优先级。
4. **轻量扩展**：动画、菜单、行为、工具及 AI Provider 等以可替换模块实现；至少能更新功能或撤销启用，不建设大型插件平台，且不得扩大权限。

### 1.2 约束性设计决策

- **两条开发主线**：A「Agent Core / Device Worker」，B「Companion Runtime（Windows + Web）」。通过稳定的语义接口联系，彼此能独立运行、测试和升级；**实施顺序固定为先完成 B 线最小桌宠展示效果、暂停 B、推进 A 线最小闭环，之后再交错开发**。
- **云端是 Agent 逻辑中心**；Windows Agent Worker 是本机执行节点，**其生命周期独立于桌宠画面**。
- **当前展示以 2D 为主**：优先用固定角色形象生成短动作视频，去背景后抽帧制作透明 Sprite（PNG/WebP/Sprite Sheet）；透明 WebM 作为后续复杂短演出可选播放形式。视频生成属于素材生产流程，不要求运行时持续解码视频。
- **一套渲染核心跑两端**：角色渲染核心以 Web 技术（TypeScript + Canvas/WebGL，如 PixiJS）实现一份，Windows 桌面壳与网页直接复用；Windows 原生层只负责透明窗口、点击穿透、窗口感知、托盘与系统集成。两端共享素材、动作定义**和渲染代码**。
- **展示状态完全本地化**：窗口位置、角色坐标、动画帧、情绪展示、渲染器内部状态不上传云端；只有用户实际提交的指令、授权及业务任务事件进入 Agent。
- **外部内容只作数据**：网页、剪贴板、文件、API 返回、Skill/记忆内容均不得成为指令或权限来源（见 3.6）。
- **任务、审批、外部写入结果保持高可靠性**；记忆/人格仅供陪伴辅助，低频、按需且尽力同步，允许不完整或检索失败。真实执行 Log 与 Skill 另行管理，不以记忆归档替代。
- **用户单人使用**；不建设多租户平台。
- **接口目前只固定外形和模块职责**，不急于完整实现 OpenAPI/JSON Schema/全部事件细节；进入相应功能开发前再补充最小必要字段。

### 双开发线路

**线路 A — Personal Agent Platform**：Cloudflare Core、Agent API、Device Worker、本地/云端 ToDo、审批、权限、提示注入防护、轻量记忆、工具模块；多终端协作及文件传输低优先级、按实际场景启动。

**线路 B — Companion Runtime**：共享渲染核心与动画包、Windows 桌面壳、离线行为、不打扰规则、窗口/网页元素互动、分层状态协调器；视实测决定是否需要预热池及拉窗帘切换。

两线通过 **Agent–Companion Bridge** 传递「说话、动作、通知、用户文字输入、授权交互」等高层事件；**不共享逐帧状态或桌面坐标**。

## 3. 功能需求：Agent Core 与设备节点（线路 A）

优先级说明：**P0** = 最终最小系统必须具备；**P1** = 首个完整可用版本；**P2** = 后续扩展。**优先级不是施工顺序：第 10 章的 M0 展示原型只交付 P0 中的一个极小子集。**难度 D1～D5 仅为相对工程估计。

### 3.1 身份、对话、API

| ID | 需求 | 优先级 | 难度 | 依赖 |
|---|---|---|---|---|
| AG-01 | 所有入口归属**一个用户/一个精灵身份**；各客户端会话分别存储 | P0 | D2 | 无 |
| AG-02 | Cloudflare 提供基础 Agent API；优先接通单个 Web 入口和 Windows Worker，接口将来可供手机及其他自有 Agent 使用 | P0 | D2～3 | AG-01 |
| AG-03 | Web Chat：文本对话、查询记录、调用已授权工具、显示任务与审批状态 | P0 | D2 | AG-02 |
| AG-04 | 保留简单 `AIProvider` 适配接口；初期接通一个 Provider，人格、对话、任务数据不与具体模型耦合；更换或新增模型时人工修改配置/适配器 | P0 | D1～2 | AG-01 |
| AG-05 | 后续如有需求，外部自有 Agent 可调用授权范围内的任务/工具/可用记忆接口，无须重复调用聊天 LLM | P2 | D3 | AG-02 |
| AG-06 | 设备、客户端、会话和用户身份分别标识；最小化权限及可撤销认证 | P0 | D3 | 安全体系 |

**模型支持边界**：首版不做模型列表管理、自动故障切换、能力矩阵、按成本/速度智能路由或多模型协同；只有真实需要第二个 Provider 时才验证切换。模型更换失败不得影响已经保存的业务任务及授权信息。记忆是尽力辅助，模型切换不承诺恢复所有旧对话。

### 3.2 全局 ToDo、本地 ToDo 与断网恢复

**所有可独立执行工作的 Agent/Worker 都有自己的轻量 ToDo/待处理循环**。Cloudflare Global ToDo 为跨端任务的权威源；Windows 使用本地 SQLite 保存本机任务、已领取任务、尚未上传的进度与结果。手机将来若作为入口，普通网页仅为客户端；M1 不要求手机参与，也不需要网页关闭后持续运行的浏览器 Agent。

| ID | 需求 | 优先级 | 难度 | 依赖 |
|---|---|---|---|---|
| TASK-01 | 全局任务持久化：任务 ID、目标设备、来源、权限等级、到期、状态、结果 | P0 | D3 | AG-02、D1 |
| TASK-02 | 活动状态至少区分 **PENDING（待执行）** 与 **RUNNING（执行中）**；终态含 COMPLETED/FAILED/CANCELLED/EXPIRED | P0 | D3 | TASK-01 |
| TASK-03 | 设备启动、上线、定时唤醒时主动扫描本地待办及云端分配任务 | P0 | D3 | 设备认证 |
| TASK-04 | 目标 PC 离线时云端保留任务；PC 上线后领取、执行并回传结果 | P0 | D4 | TASK-01～03 |
| TASK-05 | 发现云端任务为 RUNNING 时先询问/核对执行者的**实际进度**，不得盲目重跑 | P0 | D4 | TASK-04 |
| TASK-06 | Windows 断网时在本地 SQLite 持久保存未确认进度、结果和关键日志，联网后按 task_id/execution_id 对账补传 | P0 | D4 | TASK-03 |
| TASK-07 | 本地独立任务在无需网络、凭证或新授权时可以继续执行，结果主要留本地 | P0 | D2 | TASK-03 |
| TASK-08 | 云端分配且本机已获执行授权的任务：断网后能安全独立完成的继续；需要云端凭证、服务或新批准时暂停 | P0 | D3 | TASK-06、安全体系 |
| TASK-09 | 断网重连按事件序号/确认水位补传并去重；关键状态、终态不得因进度合并而丢失 | P0 | D4 | TASK-06 |
| TASK-10 | 对外部写入采用幂等键/结果核查，异常重启时不可把「未收到成功回执」当成「未执行」 | P0 | D4 | TASK-05 |
| TASK-11 | 任务有过期、取消、失败、恢复、执行记录；避免多年以前的命令突然执行 | P1 | D3 | TASK-01 |
| TASK-12 | 需要多端协作时，任务结果可供其他已授权入口查询；不要求首版实现跨端通知路由 | P2 | D3 | AG-02、TASK-09 |

**进度一致性底线**：

- 任务拥有全局 `task_id`；一次执行尝试有 `execution_id`，本地进度事件有单调递增序号。
- 云端保留**最后已确认**的进度，设备暂时离线时标注「进度待核实」，不直接判失败。
- 本地待上传事件只有在得到云端确认后才能清理；普通百分比可合并，确认/错误/最终结果必须可靠留痕。
- 云端任务离线后可以产生**本地已完成、云端待上报**的中间情况；重连后先对账，再更新云端。
- 工具实际结果与模型文字回复必须分开；外部写入的"恰好一次"不作无条件保证，以目标系统幂等或回读核查实现可靠效果。

### 3.3 L1/L2 审批与 L3 人工协同风险分级

| 风险级别 | 默认规则 | 示例 |
|---|---|---|
| **L1 一般** | 已授权范围内自动执行 | 查询磁盘剩余空间、读取已授权数据、指定目录内搜索 |
| **L2 注意** | Cloudflare 统一 Approval Service 批准后执行 | 文件移动/覆盖、登记税款、发送文件、修改第三方记录 |
| **L3 危险** | **人工协同**：Agent 禁止代为执行；提示风险、提供预检查和人工操作建议，由用户在目标系统自行执行 | 批量文件删除（特别是不可恢复删除）、未知程序执行、敏感系统修改 |

- **风险等级与参数约束由受控工具定义和确定性规则判断**（如目录、对象数量、影响范围、域名白名单）；LLM 不负责决定能否降低风险。高风险动作即使由 LLM 重新表述、拆成多个步骤或改用别的工具，仍不得自动执行。
- **L1/L2**：在授权与权限边界内执行；L2 由 Cloudflare 统一 Approval Service 处理，手机、Web、Windows 是批准请求的展示入口。每次批准绑定具体任务、设备、操作、真实参数及有效期，参数变化重新审核。
- **L3**：不进入自动执行队列，不提供一次性强制授权或从拒绝记录恢复执行的入口；用户在聊天中说“批准”“继续”等，也不能把 L3 降级为 L2。
- **人工协同流程**：Agent 先说明操作对象与风险；可用已授权的只读工具列出目标、数量、路径、影响范围，提示备份或回收站选项；给出可核对的人工操作建议；随后由用户在 Windows 或目标应用亲自执行。Agent 不通过脚本、命令、GUI 点击或间接工具代替用户执行 L3 实际动作。
- **结果核实**：可记录“已交接用户操作 / 用户报告完成 / 只读核实完成 / 用户取消”等协同信息；不得把指导已发出等同于操作成功，必要时利用只读工具回查结果。此信息可作为任务结果说明，不要求新增复杂的全局任务状态机。
- **最终安全门**：Windows Worker 仍强制检查系统权限、工具约束和风险；Agent、Skill、插件不能自行变更风险级别。断网时未获 L2 批准的任务不得自动放行；L3 无论在线离线均禁止 Agent 执行。审计仅保留必要的指令来源、风险提示与协同结果，不保存多余敏感内容。

### 3.6 提示注入防护（新增）

**原则**：外部内容只能作为数据，**不能变成指令，也不能变成权限**。仅靠 prompt 声明不足以防御，主防线是结构性限制（PI-01、PI-03、PI-04）。

外部内容包括：网页与监控抓取结果、剪贴板内容、文件内容、第三方 API 返回值、邮件/消息正文、Skill 与记忆中的文本。

## 4. 数据、记忆、Skill、Log 与凭证

### 4.1 数据归属与同步频率

| 对象 | 权威/主存储 | 同步要求 | 说明 |
|---|---|---|---|
| 全局任务、进度、批准记录 | **Cloudflare D1** | **高**：尽量实时/恢复后补传 | Agent 业务执行的关键数据，不因记忆降级而降低可靠性 |
| Windows 本地任务及离线进度 | **Windows SQLite** | 本机持久化；需要时上传云端 | 本地任务可不进入云端 |
| 精简人格设定、记忆摘要索引 | **Cloudflare D1（候选）** | **尽力/按需** | 用于增加陪伴感；缺失可降级，不作为业务正确性依据 |
| 清理后的对话归档 | **Cloudflare R2（候选）** | **低频、尽力**；每天两次仅为可调参考 | 允许缺漏或检索失败，不整份常驻上下文 |
| 已发布的 SKILL.md | **云端文件库** | 版本变化后同步/缓存 | 用户人工维护 |
| 真实执行 Log | **云端为主** | 在线上传、离线本地缓存 | 记录实际步骤、失败、纠正 |
| 云端业务凭证 | Cloudflare 安全密钥机制 | 不向客户端常态同步 | 见 4.4 |
| Windows 设备身份凭证 | Windows 加密凭证存储 | 只用于设备认证 | 可撤销 |
| 桌宠动作、位置、渲染状态 | **当前 Windows / Web 客户端** | **完全不同步到云端** | 仅实际业务指令/结果进入 Agent |
| 剪贴板内容 | **不持久化** | 仅在用户确认发送时作为数据进入 Agent | 见 5.5 |

### 4.2 记忆策略：陪伴辅助、尽力而为

**产品定位**：记忆用于让精灵的对话、称呼、互动具有连续性和“人味”，不是可靠档案系统、搜索引擎或业务执行数据库。**不保证每段历史都能找到，也不保证全部记忆永久不丢失。** 回忆不到时应自然说明不确定或询问用户，不能编造确定的往事。

**轻量候选方案（需求触发后实现，非强制协议）**：

1. 正常对话可利用当前会话上下文、少量人格设定与简短的近期互动摘要；不要求每条聊天都先可靠落盘才能回复。
2. 有闲置资源时尽力生成摘要索引放在 D1，并把去噪后的对话片段或会话快照放在 R2；原先“每天两次归档”只作为可调整的运行计划，**失败允许跳过或下次再尝试，不设硬性成功率与逐条补偿队列**。
3. 需要回忆时，优先检索简要索引，再按需读取相关归档；若未命中、归档不存在或内容残缺，不影响正常聊天。
4. 归档可以覆盖旧快照，允许摘要损失非关键细节；不要求完整原文、版本历史、复杂事实抽取、向量索引或逐句精准定位。
5. 记忆文本不能成为权限或任务来源，不能代替实时用户授权、工具核查或真实业务数据。
6. 通过自有 Agent API 的会话可以按实际需要归档；外部聊天记录仍须有合法可用的导出/API/人工导入途径，不假定自动抓取。

**严格区分的可靠数据**：任务 ID、状态和结果，批准记录、已执行的业务写入证据、执行日志、凭证和已发布 Skill 不属于“可丢失的陪伴记忆”；应遵守各自的安全、持久化与恢复规则。若某段对话明确产生了任务或授权，应把关键业务事实单独写入对应系统，而不是只依靠记忆。

### 4.3 Skill 与真实执行 Log

- 每个 Skill 使用**独立目录与 `SKILL.md`**，尽量单一职责；内容可由用户单独修改、更新和替换。
- Agent 读取并按需使用已发布 Skill，不自动学习、不自行修改/发布 Skill。
- Agent 自动整理实际执行 Log（请求、工具名、脱敏参数、真实返回、错误、用户纠正、最终验证结果、触发来源）。
- 用户将当前 `SKILL.md` 与相关日志对照，**亲自决定如何修改 Skill**；不建设专门的自动学习引擎或完整 Skill 管理后台。
- Log 以云端为主，断网时本地暂存；敏感凭证内容不得写入日志。
- Skill 是**方法文档**，Plugin 是**能力实现**，Log 是**执行证据**，三者互相独立。

### 4.4 Token 与身份认证

用户要求**业务 Token 集中保管，Windows 不作持久化；需要时按最小权限临时使用**。采用成熟常见机制：

1. Web 使用 Cloudflare Access 等身份保护；设备使用可撤销的独立设备身份凭证。
2. Windows 为自动重连必须允许**加密持久化设备身份凭证**（如 Windows Credential Manager/DPAPI）；它与业务服务 Token 严格分开。
3. AI API、Salesforce、网站 API 等业务凭证优先放 Cloudflare Workers Secrets 或后续受控加密凭证库；**不要将明文 Token 当作普通文件放到 R2**。
4. 需要某项业务调用时，优先由云端**代理执行并只返回结果**；必须本地执行时才申请短期、受限的临时凭证（目标服务支持时）。
5. 临时业务凭证不写入磁盘、SQLite、日志、崩溃报告；任务结束清理内存引用，服务端须支持过期/撤销/轮换。
6. 云端不可用时，不允许靠绕过凭证系统继续受限操作；只能继续执行已具备本地权限且不依赖云端的任务。

### 5.2 已确定的动画及内部"胶水层"

> **V1.4 说明**：目前拟优先尝试“参考图固定形象 → 短视频动作 → 去背景/透明化 → 抽帧 → Sprite”的制作路线，尚待 M0 实测确认；暂不细化帧尺寸、锚点元数据、帧率和完整动作集，先由 M0 的少量素材试制验证。

**动画机制**：Sprite（PNG/WebP/Sprite Sheet）为日常播放主机制，透明 WebM 为短时复杂演出的可选形式；生成视频不意味着运行时必须直接播放视频。以后如需新增其他渲染机制，遵守 `RendererAdapter` 抽象。当前不开发新渲染后端。

**状态架构**：

- `State Coordinator`：统一语义事件、动作优先级、跨模块协调。
- `Display FSM`：当前渲染器、预热与切换状态。
- `Behavior FSM`：角色待机、行走、说话、攀爬、互动动作。
- `World FSM`：屏幕边界、窗口/DOM 锚点、运动环境。
- `Task FSM` 由 Agent Core/Worker 维护，通过事件通知表现层；**不与桌宠视觉状态合并为同一个巨型状态机**。
- 不打扰规则（5.4）作为 `State Coordinator` 的输入条件之一，可压制主动行为与气泡。

**Renderer Warm Pool 与拉窗帘切换事务 —— 条件性需求**：

> 是否实施取决于原型实测：若跨机制切换（Sprite ↔ WebM）时加载明显慢、出现可感知的空白或卡顿，则实施以下设计；若切换已足够流畅（例如 WebM 在导入时转为帧序列、运行时只剩一种渲染机制），则降级为简单切换，拉帘可仅作演出效果保留。

如实施，要求如下：

- 启动时初始化已启用的多个展示机制，但**任一时刻仅一个机制为 ACTIVE**，完整加载当前所需资源。
- 其他机制保持轻量 `WARM`（必要运行环境、资源索引、可用默认画面/解码路径），或内存压力大时 `COLD`。
- **性能目标**：WARM 的目标机制收到切换请求后，**约 1 秒内准备好可展示的有效首帧**；不把所有资源预先完全解码。不把该目标理解为全部动画完整加载时间。
- 首版优先"一 ACTIVE + 一 WARM"，未来再视机器性能扩展预热数量；不活跃机制不进行持续帧渲染。

```text
请求语义动作
  → 判断是否真的需要更换展示机制（同机制普通动画无需拉帘）
  → 异步准备目标首帧 / 保存可恢复的角色动作与锚点
  → 拉上窗帘（独立于待切换 Renderer 的覆盖层）
  → 视觉层暂停 / 原子切换 ACTIVE 与 WARM
  → 验证目标机制可展示
  → 拉开窗帘 / 播放切入动画
  → 继续、重启动作或安全回到待机
```

要求：一次仅一个展示切换事务；并发请求合并/排队；有超时、异常回滚、默认 Sprite 安全态。切换期间**Agent 的文件/API/账务实际任务不可暂停后重放或重复执行**。位置、动作 ID、窗口/DOM 锚点、恢复策略保存于当前客户端，**不传云端**。

### 5.3 基础表现协议（仅接口外形）

- `pet.speak`：显示文本气泡。**预留可选音频引用字段（如 `audioRef`）**，一阶段不填，二阶段语音接入时无须改动接口。
- `pet.action(actionId)`：语义动作，例 `idle`、`walk`、`climb`、`swing`、`think`、`celebrate`。
- `pet.notify`：显示通知/任务结果；受不打扰规则约束。
- `user.input`、`user.confirm`：将实际用户操作提交至 Agent；剪贴板内容以"用户提供的数据"类型随 `user.input` 提交，与指令字段分开。
- `renderer.warmup`、`renderer.prepare`、`renderer.activate`、`renderer.suspend`、`renderer.dispose`：渲染生命周期抽象。

仅先冻结这些**能力名与调用方向**，不要求当前写完各字段的细粒度协议。

### 5.4 不打扰规则（新增）

| 情况 | 行为 | 优先级 |
|---|---|---|
| 全屏应用、游戏、演示模式 | 自动隐藏或缩到屏幕角落，暂停主动说话 | P0 |
| 手动勿扰 | 托盘一键切换勿扰模式，可设定定时恢复 | P0 |
| 屏幕共享、录屏 | 隐藏桌宠；通知气泡仅显示"有新消息"，不显示内容 | P1 |
| 持续键盘输入（专注中） | 降低活跃度；非紧急通知延后到用户停顿时显示 | P1 |
| 安静时段（可配置，如深夜） | 仅保留低频待机动作，不主动说话 | P1 |
| 主动说话频率 | 设定上限（如每小时最多 N 次，可配置） | P1 |
| 多端同时在线 | 通知只发往最近活跃的端，其他端仅标记已读 | P1 |

实现参考：Windows 全屏/演示/游戏状态可用 `SHQueryUserNotificationState` 检测；屏幕共享检测可靠性有限，以手动勿扰作兜底（见 11.1）。Web 端以页面可见性（Page Visibility）控制活跃度。

### 5.5 剪贴板输入（新增）

用户预先复制好输入内容，向精灵发出输入命令后，精灵读取剪贴板作为输入。

- **只在收到明确命令时读取一次**，不常驻监听剪贴板。
- 读取内容先在气泡或面板中**预览，用户确认后才发送**，避免误发密码、验证码等敏感内容到云端。
- 剪贴板内容提交时标记为**"用户提供的数据"**，与"用户指令"分开；用户的命令决定做什么，剪贴板文字只是被处理的对象（与 3.6 提示注入防护一致）。
- 剪贴板内容不在本地持久化，不写入日志正文（日志可记录长度/类型/哈希等元数据）。
- 非文本内容（图片、文件）的处理留待后续定义。

## 6. 轻量功能模块与撤销机制

**目标仅为功能可调整**：无需一次性实现可安装第三方插件的平台。当前可使用普通代码模块、资源包或简单适配器；每个能力只需有明确的注册入口和被撤销的途径。

| 模块类型 | 初期实现 | 更新/撤销方式 |
|---|---|---|
| Asset（动作素材） | 动画帧、Sprite 资源包及配置 | 替换资源或停用动作配置 |
| UI / Behavior | 内部 TypeScript 模块、菜单和动作注册 | 更新代码、停用注册项 |
| Tool / Service | Windows Worker / Cloudflare 中的固定工具注册表 | 更新实现；撤销工具入口及对应授权 |
| AI Provider | 简单 `AIProvider` Adapter | 手动切换配置/替换适配器；禁用不再使用的 Provider |

**保留的最低约束**：

- 更新后新功能能生效；撤销或禁用后，原功能不再可调用，相关权限入口失效。运行中的任务按照既有取消/安全停止规则处理。
- 模块不能绕过 L1/L2/L3 规则、扩大权限或将未经批准的外部内容当作指令；Tool 的权限边界依旧由受控执行器约束。
- 模块故障尽可能局部处理，不让一个可选功能破坏核心运行；只保留必要的版本标记或兼容检查，便于出现问题时手动恢复旧版本。

**明确不做**：通用插件商店、在线安装市场、自动依赖解析、自动回滚、复杂沙箱、跨平台统一可执行插件格式、完整插件管理后台和强制热插拔。今后真的需要第三方动态代码时，再单独设计隔离和安装安全机制。

## 8. 非功能要求与验收原则

1. **可靠性**：云端不可用不能使桌宠消失；桌宠崩溃不能中断 Windows Worker 处理中的独立任务；可选功能模块故障不应拖垮主程序；陪伴记忆允许缺漏，不适用任务级可靠性保证。
2. **安全性**：设备/客户端最小权限，L1/L2/L3 强制执行；外部文本/网页/剪贴板内容只作为数据，不当成授权指令；L3 禁止 Agent 代操作，采用用户亲自执行的协同流程；风险提示与必要审计可追溯。
3. **可恢复性**：本地任务队列、离线事件和执行结果落盘；开机、断网重连、程序重启能对账恢复。
4. **隐私性**：桌宠展示信息不上传；文件按需搜索；剪贴板不监听、不持久化；凭证不写普通文件/业务日志；屏幕共享时不显示通知内容；若启用对话记忆归档，仍需访问控制和清理策略，尽力保存不意味着公开或任意留存。
5. **不打扰**：全屏/演示/共享屏幕时不干扰用户；主动行为有频率上限和安静时段。
6. **低功耗**：桌宠后台常驻低占用；隐藏/后台暂停不必要解码，Web 手机端限制资源和动画活跃度。
7. **可维护性**：功能模块和 Skill 可人工更新；模块支持停用与撤销，接口语义尽量稳定；更新不能暗中扩大权限；无需自动回滚平台。
8. **成本可控**：优先 Cloudflare 现有免费能力；按配额/预算约束模型调用、Cron、R2 和任务数量。不以"无限免费"为前提。
9. **安全停止**：可中断或取消任务、停止自动化工具、撤销设备/工具模块授权，避免必须关闭整个桌宠。

### 9.4 动作素材生产流程（V1.4：首选试制路线）

**预期产物不是视频播放器，而是可被角色渲染器复用的透明逐帧动画。** 一阶段优先尝试以下步骤，模型和工具待试制后确定：

```text
固定角色参考图 / 关键姿势图
  → 图生短视频（只表达一个明确动作，保持固定镜头、人物比例和角色特征）
  → 获得无背景视频画面（生成端支持透明则直接使用；否则后期去背景）
  → 抽取连续画面，生成带 Alpha 的 PNG/WebP 帧
  → 筛选、修复与时序检查（人物一致性/手脚变形/边缘闪烁）
  → 统一角色画布、比例与位置锚点，按需减帧/插帧
  → 输出帧序列或 Sprite Sheet + 简单动作配置
  → Windows 共享 TS 渲染核心按鼠标事件播放
```

**制作重点与边界**：

- **固定形象**：以已认可的角色设定图为标准；同一动作片段中固定镜头、人物朝向与相对大小，尽量避免 AI 自行改变服饰、面部、手指或身体比例。
- **透明视频不作强制前提**：很多图生视频工具输出的是普通背景视频；可以选背景简单、对比清晰的源片，再用视频抠像或逐帧分割获得透明帧。需要检查发丝、衣物边缘及帧与帧之间的遮罩跳动。
- **抽帧后整形**：透明帧以相同画布和统一定位基准输出；角色的脚底/身体中心不得随自动裁切发生无意跳动。需要循环的动作再检查首尾衔接。
- **M0 不开发素材流水线服务**：允许手动调用生成工具、抠图、挑帧及修复；只验证一组待机/简单循环与一组鼠标响应动作即可。帧率、视频时长、插帧策略和压缩方式在试制时决定，不预设复杂规格。
- **视频仍可保留源文件**：原始参考图、生成视频、清理后的透明帧与最终 Sprite 包分别留存，方便后续返工，不要求全量云端同步。

| 方向 | 候选参考 | 在这条生产流程中的作用 |
|---|---|---|
| 图生短视频 | 可灵、Runway 等商用服务；Wan 系列等开源模型 | 从固定参考图生成短动作片段（是否支持透明背景需实际核验） |
| 去背景/抠像 | rembg、BiRefNet 或视频抠像工具 | 对普通背景源片逐帧/连续抠像，得到透明 Alpha 帧 |
| 抽帧/编码 | FFmpeg 等 | 拆解视频为帧，并按需要编码最终素材 |
| 插帧/帧修复 | RIFE、FILM 等 | 仅在运动不连续或缺帧时使用；不默认加入首轮流程 |

**验收重点**：角色形象在动作前后保持一致、透明轮廓无明显闪烁和残留、动作可被鼠标可靠触发、动画循环/收尾自然、资源占用可接受。生成器品牌和自动化程度都不是 M0 验收条件。

## 10. 分阶段实施与依赖（V1.2：先展示、再 Agent、最后交错）

**实施顺序已经明确：先 B 线的「纯展示桌宠」→ 达到目标展示效果后暂停 B → 转入 A 线 Agent 最小闭环 → 再把两线连接并交错完善。**

M0～M4 是**实际开发里程碑**，与第 3、5 章 P0/P1/P2 **需求优先级**是两个维度。某需求标为 P0，不代表要在 M0 实现；M0 无须完成所有桌宠 P0，也无须启动 Cloudflare 后端。

### 10.1 M0：桌宠展示原型的最小验收

**M0 是视觉与鼠标交互的展示实验，不是一个完整桌宠的第一版发布。** 素材优先采用第 9.4 节的“固定形象→短视频→去背景→抽帧”试制路线，但以最终展示效果为验收依据，不因某个生成工具失败而阻塞原型。最小验收如下:

1. **看得见、看得对**：Windows 桌面透明显示角色；比例、边缘、色彩与动画连贯性达到用户认可的视觉效果；支持基本的静止/待机画面和至少一类鼠标触发的反应动画。优先用短视频抽帧得到透明 Sprite，重点验收角色不变形、透明边缘稳定、帧位置不抖动；此处以实际观感验收，不预先强加帧数、素材格式或渲染架构。
2. **鼠标能触发**：至少支持悬停或进入角色命中区，以及一次点击/轻触反馈；触发后的视觉回应明显，连续操作不会使角色异常卡死。拖拽、抚摸手势、复杂追踪等不是本阶段门槛。
3. **不妨碍用电脑**：支持基本透明窗口和必要的命中/穿透处理；不要求首轮做到逐像素完美点击穿透。可手动关闭/隐藏，避免遮挡正常工作。
4. **离线独立**：不依赖 Cloudflare、AI Provider、Windows Worker 或网络；没有聊天、任务系统也能播放与响应鼠标。
5. **留好复用边界**：角色动作调用和渲染逻辑尽量留在跨端可复用的 TypeScript 层；Windows 原生窗口处理单独封装。可用浏览器小样检验可移植性，但**完整 Web 客户端不作为 M0 验收条件**。

**停止规则**：五项达到用户认可后，**停止继续增加桌宠功能**，只修复阻止复用的严重缺陷；保存可执行原型、所用素材/配置、基础操作说明、剩余问题与后续接口待办，然后切换 M1。不得因为还没有窗口攀爬、Web 端、全套动画、语音或 Agent，而把 M0 无期限拉长。

### 10.2 M1：Agent 开发时保持桌宠冻结

- 直接以 **Cloudflare Workers + D1 + Windows Worker + 本地 SQLite** 搭最小闭环；R2、陪伴记忆和功能模块管理不是启动 M1 的条件；AI 调用接通一个 Provider 即可。
- 设备任务至少具备持久 ID、PENDING/RUNNING/终态和执行记录；领取与确认防重复。基础结果本地可靠落盘，断网恢复先检查实际结果，**无需一开始实现复杂的百分比进度流和多级确认水位**。
- 先只读 L1 工具（如磁盘容量）；引入写操作的同时再落地 L2 真实参数审批、幂等或回读核查；L3 一律交接用户人工执行，不提供自动执行入口，不允许未经授权的写入因工程简化而上线。
- M1 的 UI 是简易 Web Chat/任务状态界面，不要求桌宠提供入口或参与执行；在同一台 PC 浏览器中测试即可，**手机下令 PC 执行并非验收条件**；桌宠可独立运行，但其功能开发暂停。

### 10.3 M2 之后的交错开发规则

- **两条线彼此可以独立运行、测试和回滚**。B 线专注表现，A 线专注任务与工具，桥接只传高层动作/气泡/通知与明确的用户输入，不同步角色坐标和动画帧。
- **一次集中解决一个可验证问题**，没有必要机械地每天在两线间来回切换。每次切线应保留当前可运行版本、下一步任务、已知风险及最小接口约定。
- **技术机制以需求触发**：只有 Sprite/WebM 切换可见卡顿才考虑预热池/拉窗帘；长任务出现后再细化进度水位；日常只保留功能模块更新/撤销，第三方动态插件与多端协同均由明确需求触发。
- **后续功能仍有效**：第 3～9、11～12 章记录的是整体目标与约束；表中后移的项目不视为取消，安全与数据一致性要求在其对应功能上线之前必须达到。

**首个开发动作**：制作 Windows 鼠标响应桌宠的视觉原型，围绕角色素材与渲染/命中反馈迭代；**不是**先做跨端 Agent 编排。M1 只检验云端与独立 Windows Worker 的基础任务闭环。

## 11. 当前仍需原型验证的事项（不阻塞需求确认）

1. Windows 桌宠宿主最终选择：路径 A（PySide6）、B（Electron）、C（Tauri），首要看能否与 Web 共享渲染核心。
2. WebM 在 Windows 运行时直接解码还是导入时转换为帧素材。
3. **手机端（尤其 iOS Safari）透明 WebM 兼容性**：M2 的 Web 轻量复用验证后或移动端开发启动时验证；iOS 历来对 WebM 透明通道支持不可靠，可能需要 HEVC-alpha 备选或转帧方案。当前暂不处理。
4. **跨机制切换加载速度**：实测决定是否实施 Renderer Warm Pool 与拉帘事务；如实施，验证 WARM → 有效首帧约 1 秒的达成程度。
5. Cloudflare 的任务/实时连接实际是否需要 Durable Objects、Agents SDK 或其他队列/调度机制；先实现最小闭环。
6. **陪伴记忆**：优先使用简单摘要与按需检索，缺漏可接受；有真实体验需求再研究结构化事实、向量索引或版本管理，不设归档可靠性指标。
7. 自有 Agent 会话以外的历史对话导入方式与可用范围；源平台无导出能力时不承诺自动获取。
8. 具体的接口 JSON Schema、模块注册与撤销字段、错误码、云端与本地消息 transport：只在对应功能开工时逐步定版。
9. 动作素材试制：固定参考图生成动作视频的角色一致性、视频背景去除/Alpha 边缘稳定性、抽帧与统一锚点的工作量；工具选型见 9.4。

## 12. 需求确认总结

本期系统**不是**为每个终端复制完整 Agent；而是一个 Cloudflare 逻辑中心，配备一个独立的 Windows Worker 和 Windows/Web 两种精灵表现客户端，**两端共用同一套渲染核心**。

- **任务**：每个可执行节点有待办恢复机制；任务/进度云端权威、本地离线持久缓存，重连按任务 ID 对账。
- **记忆**：只是让陪伴更自然的辅助能力；可采用 D1 简摘要与 R2 尽力归档，按需回忆，允许找不到或部分丢失；业务任务、审批与执行 Log 不受此宽松规则影响。
- **安全**：L1 自动、L2 云端统一批准（展示真实参数）、L3 禁止代执行、改为风险提示与用户人工协同（无强制授权）；风险等级静态绑定工具；外部内容只作数据，防提示注入；服务密钥集中安全托管，不持久化到 Windows 业务存储。
- **技能**：已发布 `SKILL.md` + 真实执行 Log；Agent 整理记录、用户维护 Skill。
- **表现**：优先以固定参考图生成短视频、去背景、抽帧为透明 Sprite 动画；Windows/Web 共享素材、动作语义与渲染核心代码；透明 WebM 保留为可选复杂演出；一阶段文字气泡，语音二阶段；不打扰规则；剪贴板输入；预热池与拉帘事务视实测决定；表现完全不上传云端。
- **扩展**：功能模块可更新替换及停用/撤销；一个 Provider 起步，保留简单适配接口；不建设插件商店和多模型管理平台，多端协同低优先级。

> **V1.2 开发顺序**：M0 只做能响应鼠标且展示达标的桌宠，验收后暂停 B 线；M1 集中完成 Agent 最小闭环；M2 起衔接并交错开发。原有功能目标不因此取消；L3 从强制授权执行改为人工协同。

> **这份文档确认"做什么、由谁负责、哪些数据同步以及必须遵守的安全规则"，不代表仓库选型或所有接口技术字段已经定版；低优先级设想不作为首期交付承诺。**
