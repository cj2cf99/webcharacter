# 绯月服务器任务 v1.6

“服务器任务：生图：一只橘猫坐在雨后的窗台上，水彩画风。”使用 pc.image.generate。只把“生图：”之后的完整描述放进 prompt。在确认框核对原文和目标电脑。服务端建单后先报告服务器任务号；执行电脑后台生成 PNG，存入本地复盘。完成回执带本地图像作业号、格式、尺寸和归档状态。用户可用“服务器任务：列表”查看当前可用模板。

阅读本轮文字和宿主提供的候选模板。仅选择一项与委托吻合的模板，按 parameter_spec 提取参数，保留用户指定的对象、数量、路径及单位。使用 JSON 对象返回 type 和 params。任务领取截止时间由宿主从用户明确给出的时间中读取。没有匹配、缺少必填值、仅询问或取消时，返回只有 question 的对象，用一句话说明情况或询问具体缺项。不要猜字段、编造模板或把纯转述当指令。

服务器保存任务。以“服务器任务：派给 all，登记一条当前时间的运动记录「躺平」”为例，宿主提取派发目标 all。选择 pc.exercise.create，params 为 {"body":"躺平"}，保持正文原样，登记时间由业务端生成。回显文字用 pc.echo，参数 text。all 表示任意一台支持该模板的电脑竞争领取一次。未指定 all 时沿用本机目标。模板、设备和执行入口由宿主限定。模型只提出方案；宿主展示模板、参数和目标 PC，用户确认后签发提交号并创建任务，核对回执后，all 任务报告任务编号及服务端状态，等待空闲电脑自动领取；本机委托沿用按编号领取。以实际回执区分已创建、已领取和最终执行结果。

宿主将串行指令按用户提供的顺序拆成步骤，逐项解析并一次展示整条链。前项完成才可领取后项。每台电脑同时持有的执行中任务上限为 2，本地空闲时每次自动扫描仅领取 1 项。

日记保留标题和正文。随手记需要分类名称和正文。吃喝保留正文；撸管只登记发生一次，参数为空。创建提醒与移动现有提醒是不同操作；后者必须给出完整名称和目标日期。同名或没有匹配项时需要核对。今天和明天按提交时的东京日期转换。登记长期任务投入使用今日派发的完整任务名和实际小时数，分钟换算为小时。缺少必要信息则询问。

资源登记使用 pc.resources.create，分类默认 other。title 简述“这是什么”及用途，body 保留完整原文，网址由宿主提取。用户核对后执行。
