# 开心挥手 V2 · 全身参与

2026-11-18（JST），本版取代被用户否决的 V1 方向；V1 留存作历史，不能作为验收基线。

## 用户原始要求及后续明确变更

1. “身体其他部分缺少动作，显得僵硬，另外基准动作不是正面，是q版4头身等待基准400X600.png这张，我需要她从基准开始，最后回到基准，动作一定是全身参与的，要有活人感。”
2. “q版人物，动作接受略微夸张的幅度和表现，以情绪表达为最优先”。
3. “必要时可以考虑单腿站立，跳跃这些更浮夸的动作”。

采用的源图：`G:/picsample/q版4头身等待基准400X600.png`，副本 `waiting-source.png`。虽然文件名含400X600，实际像素为1024×1536；输出等比例缩为400×600，不使用正面标准图替换。

本次动作选择：原等待 → 发现用户并开心 → 屈膝蓄势 → 小跳 → 单脚支撑挥手、侧倾歪头 → 双脚落地缓冲 → 收手、交叉腿、回到原等待。情绪、头肩腰膝、头发和衣袖均有变化；动作选择、具体节拍仍属小样实现，不是用户已确认的完整动作规格。

## 制作与输出

- 使用内置 image_gen 编辑工具，唯一参考为指定等待图，实际提示词见 `PROMPT.txt`。
- `wave-sheet-green.png`：1024×1536，16个生成关键姿态；不是16张从视频抽出的真实连续帧。
- `tools/build-wave-v2.mjs`：FFmpeg拆帧、去绿、统一缩放和位置。所有生成姿态采用同一比例变换，不逐帧锁脚抹除跳跃。
- 首尾由指定源图缩放去绿得到的同一PNG承担，不用生成的近似等待姿态代替。
- 最终：`output/feiyue-click-wave-v2-final/feiyue-happy-wave-v2.gif`，400×600、78播放帧、3.12秒、透明背景；25fps仅为播放时间线，包含重复帧。
- 同目录 `feiyue-happy-wave-v2-preview.gif` 为浅米色预览。
- 同目录 `poses/`、`keyframes/`、`smooth/`、`checks.json` 保留过程记录。`smooth/` 是脚本历史命名，最终仅重复采样关键姿态，不做光流补间。

光流实验在 `output/feiyue-click-wave-v2-r2/`，因大动作产生明显重影已否决，不交付该GIF作为最终版。首次目录 `output/feiyue-click-wave-v2/` 的拼图导出失败，也不是最终版。

重建（项目根目录执行，输出目录须不存在相应文件）：

```powershell
node tools/build-wave-v2.mjs output/feiyue-click-wave-v2-rebuild
```

## 限制与待确认

生成姿态仍有局部人物/服装细节变化，进入和退出生成姿态时可感知重绘差异。清晰版避免光流重影，但16个关键姿态仍有逐帧感，不宣称已达到连续视频的自然度或用户要求的“活人感”。关键帧与时间采样不能等同于真实运动物理、逐帧手工动画或图生视频。

三轮复核后停止，真实主观观感待用户确认；没有实现点击入口、桌面壳、部署或Git同步。详细结果见 `docs/reviews/FEIYUE_WAVE_V2_REVIEW_2026-11-18.md`。
