# 绯月人格接入 · 手记、念叨、轮询、发言与登记

2026-11-21 JST，程序设计补充。已确认的依据见[人格需求](FEIYUE_EMOTIONS.md)及[手记需求](FEIYUE_PERSONALITY_MEMORY.md)。每次只保留一个当前欲求、每个主动轮次只做一个选择、已开始的追问优先续办。本文把这些要求落实到现有入口；同级候选的取舍顺序、登记快照与事件归属细节是设计建议。

## 1. 同一轮出现多个想做的事

**区分欲望和行动。** 一个欲望记录她盼什么、针对谁或哪件事、怎样算满足。查旧账、查正文、选择一句措辞等多个步骤可以服务同一个欲望。当前执行位有一个欲望 ID，本轮只交付一个行动及其反馈；其余有事实依据的独立欲望进入本地池。普通轮次可从池中取回仍合适的欲望；已有执行位的事项优先接续。

| 顺序 | 宿主及 skill 怎样取舍 |
|---|---|
| 先让出前台 | 用户正在发言、确认登记、处理任务，或桌宠不满足当前闲时／可见条件时，主动发言暂缓。已发起业务的进度与结束反馈继续走业务入口。 |
| 承接已有事项 | 有可续的念叨时，本轮只允许续原事项或等候；有独立手记质问在等回答时，交还其原有入口。用户明确结束的事项从候选中排除。 |
| 去重和现实筛选 | 按“动作目的＋来源对象＋有效内容版本”合并同一机会。排除已问／已告知、事实尚未核实或能力不可用的动作。仅持有上传回执时，“分享已成功”不合格；有可用核查入口时，“核查正文”仍可入选。 |
| 选一个意图 | 第一次 Aggressive 9B 调用只看欲求、周倾向和现实材料。建议先选能直接推进当前欲求的事项；若有几件都能推进，优先承接上轮且已有新证据的一件，再看时机是否合适、和本周倾向是否贴合。仍相当时按有效候选等待时间、稳定 ID 排定，便于复盘。全部弱相关时可以不做。没有新增数值或掷骰。 |
| 情绪决定做法 | 第二次 Aggressive 9B 调用只在选定意图上决定开口、核查、暂缓或收住。她可以因为疲惫暂缓分享，不能顺便换个话题去讨陪伴。交付前宿主再次核对对象、状态和轮次名额。 |

**负 5 时的行动优先级。** 已选定的具体欲望优先于安静整理的倾向。若普通分享已具备条件，就展示对应内容；只有实际展示才记已分享。当前没有具体行动时，可以就已有材料安排一次本机整理。整理单独占用本轮名额，回执只归这次整理。

**未选中的去向。** 本轮形成的其他独立欲望持久入池，并引用原专题、问题或事项。仅有候选素材、尚未形成具体欲望的，留在原记录。已显示、交付失败、结果不明或被前台打断的轮次均不递补第二项。漏过多个周期恢复时最多执行一轮。

**示例。** 贪婪周，她正盼你评价雨夜图；同一刻有三条线索：这张图的对比结论刚核实、一笔游戏消费符合念叨条件、你昨天提到的旧游戏还有个疑问。若没有进行中的追问，她可选分享已核实的对比，请你评一句。若消费已经问出口、还在等你回应，则续消费或等候。若你正在确认登记，她先把登记说清楚。三条线索相同，实际状态不同，选择也不同。

**复盘要看得见落选原因。** 沿用 roundId 本地文件，观察段记合并后的候选 ID 和来源引用，并给受阻候选记一个实际原因，如“原事项等待回答”“已告知”“尚无正文”。决定段记选中 ID、欲求 ID、关键依据及执行回执。原因取自宿主检查或 skill 实际返回，未知留空。候选与比较过程只供本机审核。

## 2. 本机循环及抢占

### 欲望累计池与强制指定

每轮只取一个欲望实现和反馈。每个欲望登记时根据来源确认一个七大罪分类，同一罪名的有效在池项达到 100 件及以上即触发。

1. **如何入池。** 候选具有对象、所求结果、满足条件及事实来源，才算一个欲望。宿主用规范化的对象 ID、欲求类型及目标事项／成果版本生成稳定键。同一件事换句话说、隔天想起或应用重启，只补充证据和最后想起时间。相同主题里“想听他讲童年”和“想让他评价我的整理”有不同满足条件，可以分别计数。登记来源及分类依据。暂时无法确定主罪名的候选等待补证。直接执行项离开池，挂回后以原 ID 恢复一件。
2. **怎样算满。** 分罪名统计当前有效、未清除且仍在池内的不同欲望。有效性或归属不明、已执行、失效、重复或已清除的项均不占件数。每系列达到 100 件及以上时登记一个待执行编号；同系列在此次清池前继续增加也合并为这次触发。换周沿用登记时的罪名。 有效性按来源核查：已满足、用户已结束或目标失效即退出候选；长时间未被提起本身不改变有效性。达标频率取决于实际使用，应用隔离的 99／100／101 件边界样本验收。
3. **怎样指定。** 达到门槛时即登记待执行触发。建议由绯月内核在触发罪名的池内仍有效、可执行的欲望中，优先选有多次独立事实支持的主题，再选较早入池者，平局用稳定 ID。宿主确定命题和来源；Aggressive 9B 据此生成一个具体可执行的愿望、满足条件和行动指引，沿用该欲望身份。无可行对象时保留触发，等到有合适材料。生成和派发占用下一个可用的主动名额；如果本轮已选过普通欲望，不能再弹一次。多个门槛触发按编号等候。
4. **强制的含义。** 就绪的指定欲望优先于普通新欲望。一个尚未展示的普通欲望可以挂起，保留 ID 和满足条件；已经在等待用户回答的事项先收尾。前台忙、缺少能力或证据时等待；用户已经结束的对象不得再次选中。达到门槛只保证绯月认真尝试其可行行动，用户仍可以拒绝。工作照常，情绪决定措辞与时机。
5. **如何结束和恢复。** 一个触发只绑定一个已派发欲望。先保存门槛编号、欲望 ID 和行动编号，再执行；重启先查原回执。已展示后等待同一项反馈；拒绝记为结束、实际满足才按原规则正向满值并加 3。需要重试的动作沿用原编号。记录本轮结果后才释放执行位。进入强制执行事务前若目标失效，保留待执行门槛，仅在原罪名内重新选取；一旦进入强制执行并完成清池，就固定目标。后来取消、拒绝或失败均保留实际结果，不重复清池。

6. **触发强制执行时清池。** “系列”按登记时从来源确认的七大罪分类确定，每项入池时固定一个主系列；同一主题跨周仍沿用原项系列。执行前校验通过后，先把选中欲望转入唯一执行位，随后清除池内所有同系列候选。将其余系列的池内候选合为一组，设总数为 N，等概率、无放回抽取 ceil(N/2) 条清除。当前在执行或等待反馈的事项及已归档项均不在抽样集合内。以上变更、抽中 ID 和门槛回执同一事务提交，再派发行动。清除表示退出候选池，本机审核保留原因和引用；后来真实新增的欲望另按既有去重规则处理。
7. **边界例。** 选中贪婪系列，即使本周已切到其他骰面，仍清贪婪系列。其余系列合计 0、1、2、5 条时分别清 0、1、1、3 条；五条可能来自多个系列，同一条只抽一次。同一触发重试或跨周重启，使用原抽样结果；事务提交后才入池的条目不受上次清理影响。

**派发中断的恢复。** 执行事务再次检查空闲执行位及触发状态；并发领取只有提交成功者能派发。对同一 actionId，确认尚未发送时可以续发，可按编号幂等受理的入口可重试。已展示则只等回应；若可能已经展示而接收方无法回查，记“结果待核实”，保留原执行位。后续真实展示或反馈回执到达后从原项收尾。以上分支均沿用首次清池清单。尚未进入执行事务且没有可行目标的触发保留待办，其他已就绪的系列仍可使用这个名额。

**验收推演。** 贪婪 99 件、嫉妒 1 件时均不触发；贪婪再登记 3 个独立有效欲望，102 件只触发一次，重启或重复登记不再触发。已归档 99 件、现只有 1 件同罪候选时计 1。两个罪名同轮达标时，按入队顺序（同轮平局按罪名编号）等待唯一执行位。设计取值为保留已达标的触发：前一系列清池使后一系列跌破 100，后者仍从本系列剩余有效项指定一个；若已没有合适候选则等待。确认拒绝结束原行动，不会重复清池。

| 本机入口 | 调用与结算 |
|---|---|
| 启动、显示、跨周、自动恢复 | 恢复持久状态，东京周键缺失时补本周骰面。查看、显示、动作动画、跨周及唤醒本身均不消耗情绪。 |
| 现有轮询器 | 按各作业已配置的周期调度。第二期由 memoryJob('nag') 驱动主动决策，沿用念叨名额；diaryAudit、写日记、补评、天气、任务获取各走原入口。调度器到点或检查空队列只算一次检查。 |
| 前台到来或多个作业同时到期 | 沿用 shell 的 memoryIdle、interruptMemory 和在途作业检查。建议共用展示占用状态：独立质问、普通念叨和主题分享不能各自弹出一个主动气泡。正在执行的业务保有回报通道，后台 Aggressive 9B 让出前台。持久轮次键防止睡眠恢复、重复回调或重启后再次派发同轮动作。 |
| 防止自己触发自己 | 读旧日记、回读统计、生成私语、记录决策、刷新气泡、写审核日志均不会生成新的用户交流事件。已有事实进入日记或进入历史摘要，不据此再次领奖或扣次。有独立终态的工作按原业务 ID 结算一次；同一工作的查询、上传、回执和重试共用其归属。 |

现有接点见[桌面 shell](../desktop/shell.mjs)、[轮询器](../desktop/poll-scheduler.mjs)和[念叨会话](../desktop/personality-nags.mjs)。一期仍用基础念叨；多机会的两层选择在二期接管主动名额。

## 3. 发言、登记与情绪的时间点

| 场景 | 发言倾向和登记口径 |
|---|---|
| 用户主动聊天 | 从同一已提交快照取态度，先回应用户这次说的事。疲惫时可短些，得意时会想展示成果，事情未核对就如实说明。一次完整交流只结算一次，新的情绪影响后续表达。 |
| 普通消费／日记悬念念叨 | 开口前取当前情绪，若展示前已变，重新核对语气。以真实显示为“已问”。收到解释后登记原话、直接回复、当时对该事项的评价与情绪。完整互动另由情绪内核按交互 ID 结算。气泡超时继续等，用户点击结束则记录“老公闷闷的不理我了”并尊重收尾。 |
| 业务登记的草案、确认 | 保留当前心情作为表达背景。草案说明准备登记什么，待确认只询问实际字段。用户对字段、金额、对象的选择由其输入决定。onRegistration() 是进入登记动作的提示；仅由此不能断言成功、发放满足奖励或生成成功日记。 |
| 业务登记执行与回报 | 建议在本机用原业务 ID 关联发起时情绪版本，以及结果发生时可用的情绪版本。实际回报先说结果、对象及核验状态，再选择一句合适的私语。已入队／待核对／暂停照实说，已核验成功才说办妥。中断后恢复沿用原 ID。同批各步通知不重复扣档，不重复索评。只有独立完成的工作才走 work 结算；有实质用户往返才另走 chat 结算。 |
| 登记本身碰巧满足欲求 | 欲求为“他肯让我试一次”，明确许可可满足；欲求为“我想自己成功办完”，必须等到实际结果。业务完成与欲求满足属于同一个结算事件时先领奖，当次不再扣工作档或消耗一次维持。 |

例如花园批次在第一步 checking 暂停。她可以带着懊恼说“我还在核对第一步，后面的三步还没动”；不得写成“四步登记完成”。只有当时有效的本地情绪及其依据能进入审核记录，主站按[存储边界](FEIYUE_EMOTION_STORAGE.md)接收既有业务内容。

## 4. 手记与七天质问怎样受影响

**误会澄清后的补记。** 已写过误会时，在澄清发生日追加后续段，引用原事项并写明后来核实的事实与绯月修正后的评价。旧段保留原文。若后来才实际向用户改口，直接回应按真正送达的日期入册。澄清及回应各按其来源去重；同次对话中完成的可以写在同一段。

- **写手记。** 增加可写的真实经历，包括正式问答、已核查的专题事实、确有结果的登记。每段保留当时评价，篇首及新段语气依该篇全部评价汇总。今天的当前心情不能覆盖昨天的旧段。补写仍追加，满 5000 字开续篇；查阅成功确无素材才写“无所事事的一天”。仅有内部候选、模拟内心话或复盘文件不算可发表事实。
- **手记反过来影响当前情绪。** 手记和念叨分别贡献最近最多十条历史倾向，每组最新占一半。历史摘要只在一次真正的情绪事件中作为输入。一次念叨即使随后写入日记，也不会因读旧、补写和刷新列表再触发三次状态变更。
- **七天手记质问。** 保留一个主对象、跨篇原文核实和已用篇目排除。资格由现有质问规则决定，开口机会受现有待续与前台占用约束。收笔用当天最近一篇手记的情绪，当天没有则走原有后备规则。当前全局情绪、单个事项评价、手记篇首情绪分别记录。
- **对外可见内容。** 主站能看到已发表手记、段末私语和正式念叨互动。未选中的欲求、决定过程、登记发起时的内部快照及未发言内容只进本机复盘。专题核查与真正展示给用户的日期可以不同，各按实际发生时间登记。

## 5. 联动验收

1. 从未标欲望的用户原话、任务结果、待整理记录起步，给一次有效主动名额。检查有事实支撑的候选分别带所求结果、满足条件、来源和罪名，选择与其余有效项入池一起提交，每轮至多一个主动动作并共用一个 roundId；同轮回调、展示失败、睡眠恢复均不出现第二个气泡。
2. 用相同候选依次改变一个条件（有待续消费／登记待确认／分享已告知／仅上传未读回）。核对每次被排除或当选的真实依据，未选事项下轮重新判定。
3. 用户要求暂停追问后开启登记。登记反馈可以有情绪，必须给出实际进度，不能捎带重问刚结束的消费。一次解释在聊天、念叨上传、次日补写三处可查，情绪结算只认同一完整交互一次。
4. 补写昨天手记时绯月当下生气，昨日篇章仍按昨日材料汇总。只重放轮次审核文件不生成新日记、已问标记或奖励。
