# 绯月语言对练与题库陪练详细设计

2026-11-23 JST。以[已通过自审的需求及后续知序接入决定](../REQUIREMENTS.md#语言对练与题库陪练)为基线。用户已确定绯月演 A、自己作 B，使用现有材料，在本机记录和强化；首版中继取回材料、交回正式考试作答，语言进度留在本机。下文的权重、交互细节和数据处理是设计选择。开发树已有学习面板和考试中继，文中明确标出需要补齐的行为。

## 从入口到复盘

右键「陪我学习」与明确的同名对话指令打开同一月印面板，再次进入聚焦原窗口。页面沿用「语言对练」「题库练习」「复盘记录」。首屏读缓存材料的名称与进行中场次；仅当用户选「从来源取材」时请求远端目录。先显示一页，翻页再读；选定材料才取正文及相关题图。正文准备好后原子替换该材料的缓存。离线或中途失败仍可打开旧缓存，空目录和筛选零结果分别显示「导入材料」「调整筛选」。历史按结束时间倒序、每页 20 条，时间显式使用 Asia/Tokyo。

| 用户选择 | 一次完整操作 | 结束时得到什么 |
| --- | --- | --- |
| 照剧本练 | 显示身份、目标、A 当前台词，B 手打、拼词或跳过；当前轮处理完才推进剧本。展开参考或拼词记作辅助。 | 场景目标、逐轮原答及依据、一处可改进表达。点原句可单练，下一次完整剧本仍按原顺序。 |

## 材料进入本机的契约

1. **语言。** 同一来源有完整剧本和仅含背景、角色、话题的场景两种对象。完整剧本可演、可抽句；纯场景只启动自由对练。保留来源编号、修订号、场景号与步号。导入来源备份时只读取学习材料。基础剧本来自 LanguageStudy 的版本化初始化包，云端自建剧本与场景来自其资料库，目录按类型和来源编号排重。基础包第一次选用时校验版本再缓存，不在首页预载。
2. **语言线上取材接线（设计补项）。** 正式桌面连接当前只接知序。建议在现有 `subscriptions-api` 增加仅供已核对的绯月服务身份使用的 `GET /api/companion/language/{dialogues|scenes}` 及相应的单项 GET；桌面仅增加这四类读操作。复用 LanguageStudy 的目录游标、对象校验和 R2 前缀，Worker 以已有 `myR2` 读取同一 `mystorage`。目录返回类型、编号、标题、修订及下一页游标，正文返回原剧本或场景。桌面适配来源目录差异，归档场景不进入新练习。错误身份、未配置、对象不存在或响应结构不符分别显示授权、配置、资料已移除或重试提示。只把选定条目的材料缓存在本地。语言回答、信心标记、练习进度和复盘均无上传操作。
3. **知序。** 明确选择一个库后读取启用题、选项与配对行、答案、解析、标签和复习状态，用于本机缓存练习。完整下载完成后替换缓存；分卷 JSON 按稳定题号合并，含明确停用标记时从新练习排除。图片限已有支持的本机缓存类型；缺图显示占位和可重试来源，不把缺图产生的跳过计为知识错误。考试进行中只向页面提供题干所需图片，解析图在结算后显示。
4. **缓存与历史。** 本次练习使用开场快照。新版题干、选项、配对或标准答案改变时产生新版本，旧成绩仍可按原试卷查看。复盘显式标注历史版本，进入新练习时匹配当前启用版本；来源已停用或不可验证时可回看原题，有当前候选才开始新的强化场次。

**「未见」的数据口径（设计补项）。** 知序为所有结算题写 `attempts`，首次答对的题可以没有 `review_state`。现有下载把复习名单同时当作已作答名单，不能识别这种情况。建议在知序来源的桌面题目分页响应上，按原账户及本页题号从作答记录计算 `attempted` 布尔值；沿用原读请求和现有表。缓存上次完整取材时点，再与本机场次已提交的首次作答按稳定题号并集筛选。未交卷的正式草稿不作为已结算记录。刷新前只代表截至缓存时的线上记录。导入或旧缓存缺这个字段时明确显示「仅按本机已知记录筛选」，保留普通抽题。单独用“网页首次答对、复习名单为空”的夹具验收。

基础包沿用来源文件 `app/data/initial-dialogues.v1.json` 和 `fixed-initialization.js` 的版本校验。建议随桌面构建带入同一份正式基础包，按需打开“基础剧本”时再读取。自建剧本与场景目录各自维护来源游标，切换类型不串页；重复游标中止并保留已显示页。云端脚本列表返回摘要，场景列表原协议返回含场景的对象，由读端裁成目录行。有缓存时断网可重开；同编号不同种类始终分开。

## A/B 的判定与原句验证

| 输入与证据 | 教学反馈 | 对强化的影响 |
| --- | --- | --- |
| 固定句首次独立手打，规范化后匹配参考 | 标记完成。规范化限 Unicode NFKC、首尾空白和尾部句末标点，保留句中词序、否定及助词。 | 原句可记独立正确；仅使用材料中有原文片段依据的考点。 |
| 与参考写法不同 | 本机判定读取当前情境、目标、原句、参考和已有考点；能成立的替代表达可通过。确错需能指回用户原文并给具体改法；无充分依据或模型不可用就记待核对。 | 错句可单独升频；考点必须与该错处相符。自动日语分词只供拼词操作。 |
| 自由交流或听写有疑问 | 实际问句和 B 的原答作为复盘来源；点「验证这个表达」仅列同场景内能对应实际提问、且有可核对答案的材料。无候选就保留疑点。 | 自由聊天不直接改变权重。完成定向验证后按新场次的首次作答结算。 |
| 模型忙、返回不完整或中途关窗 | 本机先保存 B 的草稿。重试针对原场、原轮；接受回复时再核对轮次，只推进一次。可保存并结束，或选已缓存的文字剧本。 | 模型失败不计错。复盘能区分已完成的问答及尚未提交的草稿。 |

例如在改预约场景中，B 只说了「金曜日に変更したいです」。A 可以继续问几点。总结可以写「你说明了日期，时间由店员追问后才补上」，并引用两轮原话。只有验证题明确要求说明时间时才据该目标评价。若绯月误判，用户可挂起反馈、核清后恢复原判或改判；重算受影响场次的证据，保留原始作答和后来的有效练习。

## 强化抽取与结算顺序

练习池先按来源、启用状态、范围和版本筛选。普通模考使用原随机规则；强化池再排除疑问题。优先安排范围内标「没把握」的目标，其余名额按相对权重无放回抽取；同一题同时命中原句和多个已标注考点时取最高档。一道候选只能入卷一次。无候选给出改筛选入口。相对权重只改变机会，候选数小于等于请求数时全部入卷。

| 一个已结束场次对同一目标的证据 | 汇总规则 |
| --- | --- |
| 至少一次有效确错 | 级别升一档，最多为 7；有效正确连次数归零。辅助、当场订正、挂起争议均从判定输入排除。 |
| 无有效错误，有「没把握」 | 得分按客观答案计算。设置优先再测标记，已有有效连次数保持。下次独立回答或确错后清除该标记。 |
| 有首次独立答对，且无上述两种情况 | 同场同目标最多加一次。建议连续三场独立答对开始降一档，之后每独立答对一场再降一档，最低 1。 |
| 仅辅助、未答、跳过、待核或重复回执 | 保留作答事实，既有进度保持。 |

示例：跨场确错两次，权重 1→3→5。订正或猜对仍为 5。接下来四场独立答对后依次为 5、5、3、1，再错回到 3。同标签题仅供对照验证，各题分别计数。原题达标后才能显示「原题已掌握」；没有换情境作答证据时显示「换题待验证」。上述档位和次数是首版建议值。

「没把握」在作答时可选。固定对练与刷题应允许在首次反馈处补标，再进入下一题；正式卷只记个人信心，考中不显示对错。评分、首次答案和本机自评分别保存。对于具体的一对易混概念，先看原解析及反复选错的稳定选项 ID；证据只到标签时，按钮显示「同标签再练」，不声称已找到对应混淆对。原始判定、用户争议原因、当前有效判定分别留在原条目，复核恢复能追溯；历史列表显示原场事实与当前掌握度各自的含义。

自由对练另在 B 的原答旁提供可选「没把握」，写入该轮，不中断 A。收尾时优先列出标记过的原句；匹配原场景与实际提问后开一场验证，并在新场保存来源场号、轮号。无材料时原句保持待验证，不凭信心标记创造考点。渲染层现有信心控件排除了自由模式，需补此操作。学习总结由本机事实生成底稿（练了什么、会什么、下一步练哪项）；模型补充表达建议时逐条带回原轮引用。客观题的分数、是否掌握和未答数由程序计算，模型不可用时仍有完整的基础复盘。

## 状态、持久化与中继

桌面沿用 `study-host.mjs` 的 IPC 白名单和单窗串行操作、`study-materials.mjs` 的来源校验、`study-store.mjs` 的本机结算、`study-relay.mjs` 的知序收发。页面仅拿当前操作所需字段。本机模型只处理语言接话或有证据的解释。使用既有 `study.sqlite` 与 Windows 系统保护：材料及场次正文、作答、草稿和回执用受保护字段保存；用于查找的编号、状态、时间仍为索引。保护服务不可用时保留原库并提示恢复后再开。

| 保存对象 | 稳定依据与写入时机 | 恢复后的行为 |
| --- | --- | --- |
| 材料、场次 | `materials` 按来源保存；`sessions` 以场次编号保存冻结的题目、顺序、当前题号、首次答案、提示、自评、订正及时间。输入交主进程保存。 | 回到原场次，重开不增加独立验证次数。本地定时卷暂停时冻结剩余时间；运行中退出继续计时，回来先检查到期。 |
| 学习证据与疑问 | 每场完成时在同一事务保存场次和 `evidence`。同场单记录，按原完成时间折算；争议改判时替换原记录再重算。题目疑问通过 `doubts` 控制强化候选。 | 可以查到原作答和当前解释。标疑不改正式成绩，核清后恢复抽取。 |
| 正式场次 | `relay` 保存原场号、写入设备与实例、修订号、写入代次、待发动作及幂等键、逐题草稿和最近服务端状态；`formal_history` 存已结算索引。 | 按同一正式场号归档。结算回执、学习证据、历史索引同事务保存，重复回执不会增加一次学习。 |

**正式考试。** 桌面主进程经 `subscriptions-api /api/companion/study/v1/` 使用既有服务身份；Worker 以服务器配置的网页账户标识调用知序修正版。网页端与 Worker 分别经 `mymaindb`、`APIDB` 写同一 `stockanalysis`。正式考试由知序控制时钟及判分，普通网页刷题留在网页。这条链沿用现有表及写入契约。

| 时点 | 桌面动作及用户可见结果 |
| --- | --- |
| 开考／续考 | 先查原场次。已有正式卷则显示同卷和当前题号；其他端持有写权时先只读，由用户显式接管。存在网页刷题时提示回网页处理。开考响应丢失时保留原操作编号，重放后再读该场最新状态。 |
| 作答／同步 | 客观题按稳定 ID 传输，配对使用现有成对 ID 编解码。写入携带修订号、写入代次和设备实例。只清除与接收回执相符的草稿；另一端接管后提示重新读卷，未同步作答可核对。 |
| 暂停／恢复／到时 | 暂停或交卷随最后一批待提交答案和题号一起处理；暂停时先恢复才能提交新的答案。断网保留本机草稿，重连先查原场、区分待提交、已接收和已到期。到时只采用服务端已接收答案，保留迟到草稿供复盘。 |
| 交卷／复盘 | 新旧幂等回执均按场号和当前状态核对；旧回执不得将完成倒退为进行中。交卷前单选、多选和配对均隐藏答案、解析及解析图，也不交给模型点评。完成后两端显示同一正式成绩，桌面自评仅供强化。 |

**从正式错题开始本地重练（设计补项）。** 完成态回执已含题目来源键和版本证据，当前正式复盘分支只有题目疑问开关。新增的复盘动作接收场号与条目号，由主进程从已完成回执解析来源，按库号及稳定题号核对缓存。版本相同且启用就启动本机 `practice`；版本改变则说明差异，以用户选择的当前版本开启新练习。无缓存时可选择下载原库，缺题或停用时保留原题查看。普通本地历史的「再练原题」与批量重练也须经过同一份资格检查。复练得到独立本机场号，原正式回执和分数保留。历史里仅有旧版缺来源的回执显示「仅回看」。

跨端冲突时按场号、题项号和字段对照「服务端已收」与「本机草稿」，选择集合按稳定 ID 比较，题号和标记单独核对。一致的字段才清除待提交状态；不一致保留双方值。显式接管只取得写权。用户核对后可保留服务器答案，或在仍可作答时提交本机选择。正式复盘分别显示最终计分答案与到期草稿，进入本机强化的证据只取已结算结果。
