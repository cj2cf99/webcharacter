# 随手记与提醒任务模板模拟

用户要求摘录：

> 借用主站的设计，试着给task模板里加一个随手记的新增登记的任务模板和提醒登记的任务模板，然后试着模拟任务流程，确保模板可以被正确解析且不是每增加一个模板就要多个程序入口
>
> 大概率要挨个开发，但是你需要先预想可能的解决方案，尽量减少开发工作量，尤其是减少主程序流程的修改量。可以考虑代理模式或者其他设计模式进行简化开发。后面肯定还会扩展任务对象范围。同时需要考虑参数，状态，备注，同账户跨终端协同的问题。

本轮只演练两个模板。模板定义和任务实例分别使用现有 D1 `tasklist` 与 `tasks`。其他类型和真实业务接线留后续。

查阅 WebCharacter CLAUDE.md、根和子项目开发指南、AGENT_MINIMAL_DESIGN.md、AGENT_CHAIN_DESIGN.md、AGENT_BACKLOG.md，主站 AGENTS.md、docs/design/api.md、`src/features/records/api.js`、`src/features/reminders/routes.js` 与 `model.js`，以及全局 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md`。在全局资源、子项目及主站文档索引未发现独立设计备忘录。按单人同账户、静态注册和日本时间原则设计。沿用 [D1 绑定接口](https://developers.cloudflare.com/d1/worker-api/d1-database/) 的参数绑定，测试用隔离 SQLite 模拟 D1。

## 本轮三项实现

1. `agent/seeds/tasklist-preview.sql` 保存类型、参数规则、执行位置、操作及报告说明。共用 `GET /api/tasklist`、`POST /api/tasks`、`GET /api/tasks/:id`。重复载入不覆盖既有定义。该文件仅供模拟，不参与正式初始化。
2. `agent/host/main-site-task-adapter.mjs` 按固定类型选业务操作，转换参数并提取回执。预检返回实际提交字段，可供确认展示。可信宿主注入支持按键找回原回执的 `writeOnce`，适配器自身没有默认网络行为。普通模板只新增类型定义和适配表条目，特殊校验写在对应条目里。数据库说明不用于决定请求路径或执行代码。
3. 专项测试通过真实任务接口和隔离 SQLite 模拟状态、执行尝试和结果，两个浏览器终端使用同一模拟账户。重复启动拒绝，PC 入口也拒绝领取云端任务。模拟执行器只在测试中接线，现有 Worker 创建云端任务后仍停在 PENDING。

| 模板 | JSON 参数 | 主站映射 |
| --- | --- | --- |
| `records.create` 新增随手记 | 正文 `body`、已有主分类 `category_id` | POST /api/records，补空 Tag 和图片数组，读取 `id` |
| `reminders.create` 登记提醒 | 标题 `title`，可选正文 `content`、日本日期 `deadline`（YYYY-MM-DD）、等级 `level` | POST /api/reminders，缺内容、日期或级别按空、null、中处理，读取 `item.seq` |

例。手机提交「下周整理资料」提醒，电脑可凭同一个任务标识看到任务状态。模拟登记成功但回执丢失后，第二次调用仍用原标识，找回原提醒编号 17。登记拿到编号便完成，提醒到期由主站处理。业务参数 `deadline` 与任务领取截止 `deadline_at` 含义独立。

随手记先测纯文字，提醒先测单次登记与日期。无效日历日期在执行前拦截，分类存在与否、日期是否已过等业务规则由目标模块验证。现有参数解析支持标量，遇到正式模板需要 Tag 数组或循环规则再加对应能力。

## 扩展路线

| 后续任务 | 接入方式 |
| --- | --- |
| 主站日记、待处理事项、随手记、提醒、项目改进与 Bug 登记及更新、鱼与熊掌资源登记 | 优先复用目标模块已有服务。新增和更新用不同模板类型，更新携带目标记录 ID，沿用已有版本校验。逐项核对字段、权限和回执 |
| 个股数据、板块热力图及 GitHub Actions 状态检查 | 接只读查询，结果列数据日期、检查结论及可核查依据。热力图「正常」的标准待该项展开 |
| Salesforce Paylog | 使用独立 Salesforce 适配器，复用任务入口、状态和报告。单独确定外部字段、授权及目标端查重 |

同系统的业务只加静态映射及必要转换，目标系统不同再加适配器。继续共用任务创建、查询和状态处理。

- **状态与归属。** 云端登记归云端，手机发起和电脑查看用同一个任务 ID。PC 继续按固定设备 ID 显式领取和限制两项；本机面板按用户口径，已领取到回传前显示「执行中」。
- **参数与备注。** 参数只放业务数据，结果留业务记录 ID 和必要摘要，强制接取的终端切换沿用已有操作记录。用户任务备注建议后续作为任务实例的单个可选字段，和模板流程说明分开。此轮不加数据库字段。
- **正式写入条件。** 当前主站两个新增接口直接分配业务 ID，模拟去重不能代表生产能力。真实接入需确认提交参数，并用目标端唯一键、同库原子写入或可靠回查识别原登记。无法判断是否已经写入时，交用户核对。接管或恢复同一次登记仍用原业务键，只有确认做一条新登记才换键。本轮只演练同任务 ID 的重试。
