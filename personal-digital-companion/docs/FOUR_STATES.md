## 状态切换约定

以下是为保护基准衔接的实现解释，用户可在网页验收后调整；没有自动新增业务任务或Agent。

- 默认待机循环；鼠标首次进入可见角色像素区域时排队一次悬停，离开则取消未播的悬停。持续悬停不循环重播反应。
- 点击人物或点击预览按钮排队一次点击，优先于未播的悬停；连续点击合并，不从头反复打断动作。
- 当前片段播到末尾才交接；因此输入到实际动作可等待当前片段剩余时长。界面立即显示已接收/等待切换，不将这种等待描述为立即播放。
- 工作模式：待机边界进入 → 进入段 → 中段循环 → 收到结束后在当前段末播放退出 → 待机。
- 工作中点击：先在当前工作段结束后退出工作场景，再播放点击，工作模式仍开启时重新进入工作；不在桌子/眼镜姿态中硬切挥手。悬停不打断工作。
- 暂停/继续是用户播放控制；后台隐藏暂停绘制，恢复时尊重用户暂停选择。错误有可见反馈和重试，不把未开始播放说成已播放。

## 文件与最简设计

- `src/companion-state.ts`：无DOM、Windows、网络依赖的状态选择，供不同宿主复用。
- `src/companion-player.ts`：Canvas、视频帧绘制、Alpha命中、加载/释放；无Windows API或Agent耦合。
- `tools/four-states.template.html.in`：网页测试界面，扩展名区别于可直接打开的成品。
- `tools/prepare-four-states.mjs`：六个播放片段及素材哈希清单，结果在忽略的 `output/four-states-v2/`。
- `tools/build-four-states.mjs`：调用已有Node.js的类型擦除功能，生成自包含HTML，无npm安装/新依赖。该Node API有ExperimentalWarning，实际已执行通过；不是完整TypeScript类型检查。
- `tools/test-four-states.mjs`：共享状态逻辑、真实页面脚本初始化和生命周期执行回归。
- 成品 `绯月四状态测试_直接打开.html`：22,078,663字节，单文件离线使用；内嵌媒体按需创建Blob并加载，首屏仅解码待机。单文件全部编码字节仍需读取，不将此说成真实网络懒加载或性能达标。

没有新增框架、依赖、服务、消息总线、预热池或插件平台。WebM是当前单一播放机制，不涉及Sprite/WebM跨机制切换。未沿用旧Rigby2D或3D项目。

在项目目录执行：

```powershell
node tools/prepare-four-states.mjs
node tools/build-four-states.mjs
node tools/test-four-states.mjs
```

素材转换脚本复用已有输出；本次实际输入与输出哈希记录在manifest中。源片变更时使用新输出版本或重新转换受影响片段，不能依赖旧输出缓存宣称新版已接入。本次 `工作三段2` 使用全新v2输出目录，无旧工作文件混用。
