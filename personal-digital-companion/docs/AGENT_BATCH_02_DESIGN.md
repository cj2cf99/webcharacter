# 第二组：设备识别与命名

2026-11-18 JST。用户授权见AGENT_BATCH_01_DESIGN.md；原文与决定见AGENT_MINIMAL_DESIGN.md。参考同一批次已查阅的CLAUDE、开发指南、V1.5及全局FRAMEWORK_PREFERENCES，独立备忘录缺失记录不变。按单用户、无负载压力、固定标识与可标注通用名最简实现。

## 三个细任务

1. agent/devices/identity.mjs：提供Node侧getDeviceIdentity(directory)函数，调用方显式传入应用数据目录。首次写device-identity.json保存随机UUID前缀pc-，以后复用；返回本机hostname作辨认信息。不使用MAC，不存凭据。不接线/重启现有桌面应用。
2. agent/devices/api.mjs：依赖第一组D1 devices表，实现已认证请求下的登记、列表和改名模块，主会话最后挂到第一组Worker认证之后。
3. agent/tests/devices.test.mjs：临时目录与真实SQLite测试身份持久化、名称规则、SQL注入参数、列表与任务归属；完成复核记录。

## 数据与接口

共用第一组devices表，不重复迁移。设备ID不是认证凭据。API模块接收已经认证的Request和DB；路由前必须经过第一组认证。第一组的单用户API_TOKEN仅为开发接口，不直接写入桌面，也不冒充未来设备认证。

- PUT /api/devices/:id：请求{computer_name}，ID必须是pc-加完整UUID；登记一台设备，已存在则仅更新电脑名，不覆盖用户alias和created_at。201新建/200更新。
- GET /api/devices：返回{devices:[{device_id,computer_name,alias,display_name,created_at}]}，未标注显示device_id，已标注显示alias。单人少量设备一次返回，不做分页。
- PATCH /api/devices/:id：请求{alias}，null或去空白后空字符串表示取消标注；非空最多64字符（Unicode码点），避免控制字符；NOCASE唯一约束处理ASCII大小写重复，冲突409，未知ID 404。不开发合并或删除。
- computer_name去首尾空白、1..255 Unicode字符，无控制字符。请求只接受本接口字段；无效JSON/字段400，不泄露SQL。

例：pc-UUID第一次出现时显示原ID，同时展示系统名称方便辨认；用户改名homepc后显示homepc。任务始终引用device_id，改名或再次上报系统名称不改变归属。

身份文件损坏时明确报错，不悄悄换ID制造新设备。用独占创建避免两个首次调用互相覆盖；本机身份文件仅写非秘密ID，不额外建配置框架。重装恢复不在本轮。

## 测试大纲与验收标准

| 编号 | 场景 | 标准 |
| --- | --- | --- |
| D01 | 首次与再次读取身份 | ID为pc-UUID，重读不变，目录仅含非秘密身份文件 |
| D02 | 文件损坏 | 明确失败，不覆盖原内容、不生成新身份 |
| D03 | 登记与再次上报 | 仅一条设备，系统名称更新，别名与创建时间保持 |
| D04 | 标注、取消、重复标注 | 展示切换正确，重名409，原值保持 |
| D05 | 非法JSON/名称/未知设备 | 正确400/404，不产生额外数据 |
| D06 | 设备改名后查询关联任务 | task_id与target_device_id不变，当前展示名更新 |
| D07 | 真实Worker路由未认证调用设备接口 | 401，不允许绕过第一组认证 |

使用Node内置测试、临时SQLite适配。D06/D07在第一组交付后由主会话集成验证。未连接真实桌面、生产D1、Access或凭证系统，不宣称这些验收通过。实际应用数据目录由后续桌面主进程接线时传入，不暴露给渲染进程。

设计首轮复核：范围为设备基础数据与模块，无UI/常驻/链式任务扩展；最小登记PUT用于让设定表有设备可标注，不新增注册平台。
