# 绯月简报累积与旧闻归档设计

2026-11-21 JST · 用户在[交互原型](../prototype/news-weekly/index.html)迭代后指示「开发」。已完成开发区接线和隔离检查，见[开发复核](reviews/NEWS_WEEKLY_IMPLEMENTATION_REVIEW_2026-11-21.md)。

用户原话及由两天延长为七天的决定见[需求变更](REQUIREMENT_CHANGES.md#累积阅读与本机旧闻归档)。本次解决后台成刊覆盖整个旧刊的问题，保留已有纸质报面、分类、来源展开、原文切换和半日取材。

## 七天总览与事件时间线

- 以 `Asia/Tokyo` 计算今天及往前六个自然日。11 月 21 日 JST 的范围是 11 月 15 日至 21 日，11 月 14 日及以前进入归档。入库继续用 UTC 毫秒。七天按本机已收录内容计算。RSS 的三天补查上限沿用已有取材规则。
- 打开简报直接阅读整个七天窗口。同一个事件只占一个卡片，即使它跨了日期或来源。所有事件按最新实质进展时间从新到旧排列，重要性可以改变卡片样式，排序仍以时间为准。栏目筛选沿用现有控件。刷新会读回新增进展，空轮也保留已有记录。
- 首页是紧凑的多列事件卡片，显示标题、分类、最新进展时间和一句提要，整体从左到右、从上到下保持时间倒序。选中事件后，首页缩为左侧单列，仅保留标题、分类和时间。右侧详情保持单一选中，可直接切换事件，也可点「收起详情」、再点已选项或按 Esc 恢复总览。桌面两栏分别滚动。窄窗使用单列总览和可收起的右侧抽屉。
- 详情先显示最新进展和 JST 时间，再以独立「现状」区写带日期的较详细总结，交代起因、关键转折、当前影响或仍待处理的事项。之后按从旧到新列出关键节点，附对应来源和原文。单一节点只显示一次。在七天内有新进展的事件，可以在详情保留为理解此轮进展所需的更早节点。
- 有 RSS 报道附图时在现状旁按需显示固定 192×128 CSS 像素的缩略图并注明来源。点击在当前窗口放大，完整展示图片比例，关闭后返回详情。缺少附图或加载失败时现状直接显示文字。渠道图标沿用既有排除规则。原型使用已有 NASA/JPL-Caltech 资料图模拟 RSS 附图。
- 详情最下方显示「情报来源」和篇数，默认折叠。展开后汇集当前事件各节点的报道，按报道发布时间从新到旧排列，展示标题、媒体和 JST 发布时间，正式接入时点击标题打开对应报道。节点仍可展开其对应来源。
- 滚动离开顶部后，总览与详情分别显示「回到顶部」。桌面分栏时各自返回所属栏顶部，窄窗抽屉打开时使用详情的按钮。
- 首屏读取事件标题、分类、更新时间和一句提要，打开详情时再读取总结及时间线。来源清单、原文和非首屏缩略图按需加载。日界切换后，移出窗口的记录在已有后台检查中办理归档。
- 归档通过同一窗口的「打开归档目录」进入本机目录。保留主题、来源及日期，可用系统文件管理器按日期查找。

展示示例采用虚构事件。首页显示「沿海铁路恢复通车」及最新动态，点「查看」后右侧显示「11/21 09:00 JST · 全线恢复运行」。事件总结写「11/18 因暴雨停运，11/20 先恢复北段，11/21 全线恢复」。时间线依次显示 11/18、11/20、11/21 的节点和各自出处。

## 收录与事件归并

沿用 `desktop/news-briefing.mjs` 与 `desktop/reminder-checks.mjs` 的本机 SQLite 和半日轮询。现有 `news_briefing` 单行保留检查进度、栏目补查位置和最新期次兼容数据。近期事件单独以稳定事件编号存储，包含短标题、最新实质进展时间、简要综述、按时间归并的关键节点及各篇原始资料。索引按最新实质进展时间读取七天范围。节点优先用来源明确的事件发生时间；来源只给发布时间时采用报道时间，并在界面标明。

同一 URL 重放只记一次。事件归档后，已有来源索引以网址指纹继续去重，完整网址与摘要保留在各自的归档文件。同标题若来自不同媒体，仍各自保留来源。沿用已完成的标题清理和行情同事件判断，并以标题或已有摘录里的主体、动作、事件时间或地点比对其他主题。对当事方不变、有证据支持前后关联的后续进展，沿用原事件编号并新增节点。仅转载或补充同一事实的来源并入已有节点，保留原链接及发布时间，排序不因转载而提前。证据不足时各自存放。现有公开 RSS 工具和额度边界沿用。

首次运行先在同一 SQLite 事务中把旧版仍保留的最新一期导入，成功后写迁入标记，重启时不会重复导入。旧记录本身若已超出七天，照常生成本机归档。已经被旧版覆盖的整期内容无法直接从存储恢复，仍可按既有补查规则收录公开来源继续提供的报道。

## 本机归档

每个事件保存为独立 UTF-8 Markdown 文件，路径为 `<现有资料目录>/news-archive/YYYY-MM-DD/<事件编号>.md`。目录日期使用事件最后一次实质进展的 JST 日期，重试沿用同一路径。文件正文包含标题、事件进展日期范围、50–200 字按时间归纳的中文摘要，以及各篇来源的媒体名、原始发布时间 JST 和原文链接。归档不包含图片或整篇原文。打开归档目录前不扫描或加载旧闻。

近期报面和归档共用已保存的时间节点和来源。摘要优先复用多来源摘录，必要时沿用现有公开正文读取器补取证据，再用本机模型归纳。数字检查分开匹配日期、时间和带单位的数量，常见涨跌表述还按方向和来源中的日期核对。未通过时回退到摘录。来源分歧注明口径或数据有出入。近期摘要尚未生成时先显示可核对的最新要点。归档摘要的长度按去除空白后的可见字符计，短于 50 字或缺少可靠证据时将事件留为待归档，可随下次后台检查重试。报面可提示待归档数量。

沿用已有托管后台检查执行归档，资料读取及本机摘要安排在空闲时段。归档文件先写同目录临时文件再原子改名。只有文件成功落盘且 SQLite 中的事件资料未变化，才移除待归档原始记录。单个文件写入失败时保留原记录，其余事件继续归档。程序中断或期间出现新来源时也保留可重试原记录。重复执行沿用同一文件名，成功的记录不会额外生成副本。归档中的来源文本转义为 Markdown 可显示的文本，出处链接使用校验后的地址。

## 核对与验收

设计对照[现有报面](DEVELOPMENT.md)、[桌面界面说明](DESKTOP_UI_GUIDE.md)、[项目备忘录索引](TASK_TEMPLATE_PREVIEW.md)及全局 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md`。在已有索引中未找到单独的全局或本项目开发设计备忘录。本设计落实既有的东京时间、紧凑布局、按需加载和最少组件约定，沿用本机 SQLite、现有轮询、原报面和本机模型。以新闻汇总开发候选为技术基线，准备安装时再对照实际安装版本。

| 检查 | 验收条件 |
| --- | --- |
| 七天临界 | 以 JST 跨午夜与跨月为例，前六个自然日的事件仍在总览，第七个过去日期中没有更新进展的事件转入归档，七天阅读与 RSS 补查上限互不影响。 |
| 累积及迁入 | 同日多轮、重启、空轮与失败重试后均能读回旧条目。旧版仍存的最新一期迁入一次；迁入和写入均使用隔离资料。 |
| 跨来源归并 | 两家媒体同题及异题同事件各只显示一个事件，可展开各来源。相似标题但明确不同的事件各自可见。冲突数字不写成共同结论。 |
| 事件顺序与进展 | 相互独立的事件按最新实质进展倒序排列。一则连续多天的事件只占一块，首段是最新进展，展开节点按旧到新排序，综述带日期。纯转载不会改变卡片排序。同一节点可对应多篇来源。 |
| 本机归档 | 相同日期的两个事件得到两个 Markdown 文件，跨日期写入不同目录。摘要在 50–200 字内，并包含日期和来源。无法取得可靠摘要或无法写入时原资料仍在。写入后重启重试按原路径处理。 |
| 面板 | 同屏七天排序、首页多列、选中后左窄单列与右侧详情、切换与收起、两栏各自滚动、窄窗抽屉、分类、刷新、来源与原文切换、归档入口通过隔离 Electron 检查。 |

第一轮设计复核发现，已有 `news_seen` 对标准化同标题直接去重会丢掉不同媒体的来源，须在收录阶段保留来源并在事件层去重。原始资料须保存到归档成功，避免重现刷新造成的丢失。第二轮对照用户追加的连续阅读要求，调整为七天同一报面、事件间倒序和事件内时间线顺序，并以实质进展时间取代单纯的最新报道时间，防止转载将旧事顶到前面。已执行[原型验证](reviews/NEWS_WEEKLY_PROTOTYPE_REVIEW_2026-11-21.md)和[开发验证](reviews/NEWS_WEEKLY_IMPLEMENTATION_REVIEW_2026-11-21.md)。正式安装使用的数据、实际摘要效果和运行验收仍待确认。
