## 2. 共用规则

**闲时。** 指用户没在和她聊天，她也没在执行任务、作业或处理待补传的记录。沿用现有“空闲时查云端待领任务”的忙碌判断。不设静默时段，也不加其他勿扰条件。

**三件后台事。** 补评价、写日记、念叨三件事：

- 补评价和念叨只在闲时做；
- 写日记到了定时时间，也等到闲时才开始；
- 三件事一次只做一件；
- 用户一开口，就停下来先回应。

**模型。** 一律使用本机 Qwen3.5 4B，补评价也用 4B，不参与现有的自动换档；显存不够时就在 CPU 上运行。本机模型上下文只有 2048 token，所以按事件分批调用。

**存储。** 日记和念叨记录以云端为准，本机各留一份备份。时间存 UTC，显示用东京时间。

- 行动评价、已覆盖范围这类工作状态只存本机。
- 本机日志至少保留 7 天。
- 本机备份全部保留，不设清理期限。

## 3. 行动与评价

- **行动**：只算和用户相关的事，即回复用户、替用户执行任务、问用户、向用户播报、提醒用户。她自己写日记、补评价和待机动作都不算。
- **补评价**：闲时翻 7 天内的行动记录，给还没有评价的行动逐条补一句评价，存在本机，挂在对应的行动记录上。
- **口径**：只用那条记录当时已有的信息。后来才知道的结果交给日记和悬念追问去写，不回头改旧评价。

## 4. 日记

### 4.1 每次触发的流程

桌宠自己定时触发，预期一天 2 次。全程在本机完成，写好后提交云端。云端原样保存，不重写，也不经过现有的每日日志接口；日记也不进入用户自己的主站日记。

1. **取材料**：从近 7 天的本机日志里，找出还没被日记覆盖的部分。用户最初说的是“近 2 天”，后来选择放宽到 7 天。这一步同时补上整天没写的日子和漏写的段落。
2. **清洗**：去掉废话、代码内容、没有意义的任务执行记录，以及密码、令牌等凭据。
3. **精简**：保留对话。用户的话原样保留，只改明显的错别字。绯月的回复可以精简，但答错、纠正和改口要保留。同时提取检索要素：摘要、标签、对象、金额、决定。
4. **补背景**：加上日期和天气。天气取那一天本机记录里的天气播报或查询结果，注明地点，区分实况和预报；没有记录就写“无记录”。
5. **定情绪**：汇总这些行动的评价，缺的当场补上，得出一个情绪，整篇只用这一个。
6. **风格化重写**：带着这个情绪，以她的立场、身份和设定写成她自己的日记。每件事单独成段，段末写她的评价和私语。
7. **提交**：
   - 正文、检索要素、情绪、天气和悬念追问一起提交，每批带一个批次键。
   - 写好但还没提交成功的内容先留在本机，断线后用同一个批次键重传，云端不会写入两次。
   - 云端确认保存后，本机才把这段材料记为已覆盖，并更新本机备份。

### 4.2 篇幅与追加

- **追加位置**：新段落追加到所属日期最后一篇的末尾。补写往日的材料，就追加到那一天。
- **篇幅上限**：每篇最多 5000 字，放不下时另开当天的下一篇。
- **已有段落**：一律不改动。
- **篇首**：追加时重新生成摘要和标签，并按这一篇全部的评价重新汇总情绪。

### 4.3 悬念追问

- **内容**：日记里的独立字段，存放还没处理完、她认为明确还会有下文，或者需要弄清楚的内容。
- **记录项**：每条悬念记两项：状态（未解或已解），以及是否已经拿来念叨过。
- **跟进时机**：每次触发、写完新内容后，拿新材料逐条对照 7 天内各篇的未解悬念。
- **有了下文**：写进当天日记，注明“接某月某日的悬念”；原篇只把这条悬念改成已解，正文不动。
- **超过 7 天**：不再跟进，原篇保持“未解”，不另做标记。

### 4.4 可见范围与防循环

- **可见范围**：用户在主站网页上只读查看日记。绯月不主动复述私语。
- **防循环**：日记本身、评价和写日记的动作，不会在下一轮被当成新的生活事件写进日记。用户主动谈起旧日记时，这段新对话照常记入。

## 5. 念叨

### 5.1 挑哪一件

- **名额**：每两小时有一次主动提问的名额，消费和悬念合用。名额可以不用；连续错过几轮，恢复后也只问一件。
- **接着问**：被突然中断、等着接着问的念叨占用名额，并且优先于新候选。同一时间最多只有一件这样的念叨。
- **候选**：
  - 消费：最近 36 小时内命中条件的消费，按金额从高到低取前五笔。
  - 悬念：7 天内未解、也还没拿来问过的悬念。
  - 两类合在一起随机挑**一件**，这一轮只针对这一件开口。
- **排除**：
  - 已经问过的事项不再进入主动候选；之后标题、排名、日期或统计窗口有变化，也不会让它重新进来。
  - 念叨收尾时没问清、转成悬念的内容，只在写日记时跟进，不再拿来念叨。

**消费数据。** 读主站从 Salesforce paylogs 同步来的消费记录（主站 `GET /api/v1/expenses`），桌宠不直接连 Salesforce。

- **进入候选**：单笔达到 3500 日元，或者带游戏、娱乐倾向。退款和负额记录不算。
- **判断倾向**：先看分类和标签。分类未识别时，由 4B 读商户名和描述来推断，并在念叨记录里标“推测”。
- **问法**：
  - 分类未识别、又没有备注的，算用途不清楚。用途清不清楚只影响问法。
  - 一笔消费同时命中多个原因，合成一个自然的问题。
  - 用户以前解释过、能明确对上的，沿用那段解释，不再问。

**比较作为背景。**

- **比较范围**：用同一个接口，按触发分类比较前 1–7 天和前 8–14 天的笔数和金额。以 11 月 20 日为例，比较的是 11 月 13–19 日和 11 月 6–12 日。
- **计数**：一笔消费命中两条原因，仍只算一笔；已经问过的事项照样计入统计。
- **资料不全**：注明缺口。

例句：“上周游戏消费比前一周多了几次，昨晚这笔是买了什么呀？”话题始终围绕这次选中的那一件。

### 5.2 怎么进行

- **上限**：一次念叨最多 3 个核心问题、6 个回合，被打断后接着问的回合也算在内。
- **被打断两次后**：第三次接着问时，她要按 3 个回合内问完来安排，把剩下的核心问题合在一起问，必要时请用户一次说完。
- **收尾**：问满上限，或者核心问题都问完，就收尾，写下听完后的评价和情绪。没问清的部分转成悬念追问。

| 情况 | 处理 |
|---|---|
| 用户回答 | 解释的原话、时间、她的回复和听完后的评价都接在这次念叨下面，下次写日记时写进去。用户可以隔天自己接着聊。 |
| 用户没有动作，气泡超时消失 | 算等待回应，不算拒绝。不催，也不重新问。 |
| 突然中断：桌宠退出或崩溃、电脑睡眠、被其他弹窗或气泡挤掉 | 不算问完，转为本地待处理。她闲下来后，从原来的回合接着问。 |
| 用户点气泡上的关闭按钮 | 表示“不想说了”。立即结束，已有的互动保留，记下 **“老公闷闷的不理我了”**。这句话只由关闭按钮触发。 |

### 5.3 念叨记录

- **识别**：一次念叨只围绕一个来源对象。消费按“模块 + 原记录 ID”识别，悬念按“日记篇目 + 悬念序号”识别。提问时保留当时的标题。
- **问出口时记录**：来源、ID、当时的标题、触发原因、一句统计摘要、提问时间和原话，以及她开口前的评价和情绪。只有真正显示给用户的提问才算“已问”。
- **保存**：
  - 每次有变化，包括开口、回答、中断、结束，都把整条记录保存到云端，成功后更新本机备份。
  - 断线时先记在本机，联网后再补存。
  - 去重和接着问时读本机备份。
- **与日记的关系**：日记引用念叨记录，按实际发生的日期写入互动和评价。同一件旧事进入后续统计时，不会让她再追问，也不会因为重复扫描而再生气。
- **用途边界**：念叨记录只用于陪伴和复盘。业务是否完成，仍以实际回执为准。

## 8. 验收要点

1. **答错与纠正**：当天同一话题出现提议、改口、绯月答错和用户纠正。能搜到这一篇，读回用户原话、她的错误与改口、最终决定和段末评价，全篇情绪一致。
2. **一天两次**：第二次只处理第一次之后的新材料，追加到同一篇里，篇首摘要、标签和情绪随之更新，已有段落不变。代码、废话和凭据都已清除。超过 5000 字时生成同日续篇。快搜不加载正文。
3. **补写缺失的那一天**：某天桌宠全天没有运行，7 天内能补写那一天；没有天气记录的，天气标“无记录”。
4. **断线重传**：提交时断线，按同一个批次键重传，同一内容不会出现两次。
5. **悬念跟进**：3 天前的一条悬念有了下文，下文写进当天日记并注明来源，原篇只把这条悬念改成已解。
6. **补评价**：闲时逐条补评价，用户一开口就停下来回应。评价只用当时已有的信息。
7. **挑一件来问**：昨晚一笔游戏消费在 36 小时内，同时还有未解悬念。这一轮只对一件开口，并能用该分类前两周的真实统计说明为什么问。
8. **念叨的四种结局**：分别验证用户回答、气泡超时、被突然中断两次后接着问、用户点关闭按钮。
   - 气泡超时后不重新问；
   - 被中断后从原来的回合接着问，第三次在 3 个回合内收尾；
   - 全程不超过 3 个核心问题、6 个回合；
   - 只有点关闭按钮，才写下指定的那句话。
9. **不再追问**：念叨收尾时转成悬念的内容，不会再被拿来念叨。
10. **主站日记页**：
    - 按东京日期分页，每页最多 20 条，每条最多显示 3 行；
    - 能按关键词和标签搜索；
    - 点开才加载正文，私语和悬念单独标出；
    - 念叨列表按时间分页，显示来源、触发原因、结束方式和当时的情绪，点开能看整段对话；
    - 桌面和手机宽度、两套主题下都能正常使用。
11. **断网的念叨**：断网时念叨先记在本机，联网后补存到云端，云端与本机内容一致，不会重复。

| 行动评价、已覆盖范围、未提交的日记批次 | 本机，挂在现有的对话和任务归档上 |
| 日记（正文、检索要素、情绪、天气、悬念及其状态） | 云端 D1 一张表；本机备份 |

**接口。** 挂在主站 `/api/companion/` 之下，桌宠沿用绯月连接现有的认证：
1. 写入日记：新开一篇或向已有篇目追加，同时更新摘要、标签、情绪和悬念。带批次键。
2. 按索引字段快搜，不返回正文。
3. 读取单篇正文。
4. 更新悬念状态。
5. 整条保存念叨记录：按 ID 覆盖写入。
6. 分页列出念叨记录，带单条详情。

主站页面沿用 Access 登录，复用第 2、3、6 号接口。路径、字段和错误码留到设计阶段确定。

**界面。**
- **念叨**：沿用头顶气泡，另加一个关闭按钮。
- **日记页**：主站新增一个只读页面，分“日记”和“念叨”两个标签页。
  - 使用主站外壳，支持雅致、赛博两套主题，配线性图标，导航和总览里各放一个入口。
  - 列表每页 20 条、每条最多 3 行，正文点开才加载。
  - 用徽标和配色区分情绪、天气、私语和未解悬念。
- **流程**：先出视觉预览，再做 HTML 原型，两步都需要用户确认。

**最简检查。**
- 不设半小时时段，也不按来源分别记录四种状态；判断缺口只靠“已覆盖范围”。
- 补缺篇、补漏段并入取材这一步，不另走一套流程。
- 不保存当时排在前五的候选的快照。
- 不新建调度器或常驻服务。
- 云端只新增两张表、6 个接口。
- 日记正文只追加；念叨记录整条覆盖写入。
- 网页复用桌宠用的读取接口。
