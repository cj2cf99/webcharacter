# 绯月临时登记任务链上线设计

2026-11-19（JST）。发布范围及临时链节点规则经用户确认。

## 原始需求与确认决定

本批最终范围修订（2026-11-19 JST）。用户决定「麦克风转录暂不需要，后面会加入。其他的立即处理，完成后三轮自审。」语音转录安排到后续版本。本批支持文字和操作系统已转成文字的输入。

用户需要在精灵里输入一段话，让精灵自动理解并登记吃喝、运动、随手记、日记、一键事件和提醒。样例应形成一条吃喝、一条一键事件、一条次日提醒、一篇主站日记和一条保留原链接的资源类随手记。运动缺席时不生成该项。

后续确认使用临时任务链和 AI 解析，先用模拟接口，正式版本使用 Cloudflare Workers AI 免费额度。桌面精灵经 `subscriptions-api` 复用已有 Access Service Token。主站合并任务链管理。桌面提供「云端连接」配置界面，发布自动更新连接配置并保留当前 PC 设置。用户最新决定「除去素材包，其他的都上线」。

AI 范围后续修订为「先把那边的ai接口都接过来，包括收费的deepseek接口，且不需要收费认可，默认可用，每次失败后就去找下一个，但是调用失败的过程需要以log形式记录，并保证可以被查看或者客户端能接收到，另外任务本身要在本地留下log，收发都要，要不然没法调试了。」同轮补充「天气接口……应该走服务器的接口的，而不是直接本地去问对面api了。」AI 使用范围以此次修订为准。

用户追加「上一次ai路由成功的那一家，会成为一小时内的默认对象，过一小时再开始这个循环。」路由按使用者记住最近选中的供应商一小时。命中同一首选不延长窗口。首选失败后按原始优先级尝试其他供应商，新成功者开始新窗口。期间全部失败时保留原窗口状态，到期后从完整优先顺序开始。付费 DeepSeek 成功时也适用这条规则。

网页版精灵保持关闭。素材包在本次发布清单里明确排除。今后 Agent 需要读取的文件按用户要求放私有 R2，通过 Worker 绑定按需读取。任务状态、登记回执和文本所带的资源链接存 D1。六类文字登记及主站任务链界面没有媒体读取依赖。

## 接线与数据

| 位置 | 本次实现 |
|---|---|
| 桌面精灵 | 接受文字和语音转写后的指令，建链成功后主动领取这条链中已就绪的节点，显示逐条结果。一次操作只领一个随机提交号，将编号与解析结果一起保存，断线或重启后重发原请求。设置页显示云端状态并提供连接测试。发布管理的地址配置和本机偏好分别保存。首装时由授权的凭据来源配置当前 PC，迁移时保留设备 ID、任务库、动画音量、导入资源与既有凭据。 |
| `subscriptions-api` | API 边界复用现有 Access 认证。桌面和经主站已验证的本人使用同一套任务数据。通过私有 Worker 服务绑定调用既有 AI 供应商；每家返回后由绯月 Worker 校验结构化步骤，失败顺序尝试下一家。加载六类正式模板并绑定精灵任务库。天气提供固定地点和类别的读取接口。 |
| `myapp` | 接入同源任务链页面和操作，经现有服务绑定调用 `subscriptions-api`。首屏取少量链摘要，展开时再读节点和回执。失败节点展示继续、跳过、停止及待核对状态。增加私有命名登记入口，让 `subscriptions-api` 调用已经存在的六类业务登记逻辑。两条路径分别在自己的入口结束。 |
| D1 | 精灵任务库应用缺失的迁移，含建链防重 009、临时链节点位置 010 和临时链标记 011。迁移 011 为旧链保留默认值，能够通过原提交号和原请求摘要识别旧临时链。六类业务复用现有主站表。业务写入复用稳定节点 ID，目标库内原子保存登记与回执，并支持查证回执。正式 SQL 编号和结构差异以隔离开发及生产结构前检为准。 |

用户补充「我的精灵接到任务语音转任务后开始新建任务链后，自己去领下任务」。按此明确桌面精灵负责推进自己发起的临时登记链。语音先转写，和键盘输入共用 AI 解析与建链接口。用户提交指令即发起该链，建链成功或以原号取回原回执后，精灵主动请求领取当前可执行节点。`subscriptions-api` 校验节点仍待处理、任务链状态与前置条件，原子领取并调用已有业务登记逻辑，回执保存后精灵再推进下一节点。普通待办清单轮询继续沿用只读和显式领取规则。

节点默认互相独立，用户明确先后关系时记录同链前置，拒绝循环。登记成功后显示目标记录。一项缺分类或字段时只挂起该项。写入结果未知时先核对原节点回执，最终失败由用户决定继续、跳过或停止。相对日期以 Asia/Tokyo 解释，展示时间为 JST。

**一段输入生成一条临时链。** 用户最新明确「一般不会超过10个。不需要拆分。5个的上限是给任务模板用的」。临时登记按原文顺序保存全部有效节点，十项作为常见规模的验收样例。任务模板保留五项上限。整条链共用一个提交号和一份回执，同号重试取回原链。

## AI 回退、日志和天气接口修订

- 私有 `RegistrationAi` 入口复用主站的 AI 参数校验、各供应商适配器、凭据解析器和付费 DeepSeek 传输。顺序沿用 Cloudflare、Gemini、Groq、BigModel、SiliconFlow、Z.ai、PLaMo、Sakura，随后尝试主站另有定义的 OpenAI，最后自动尝试 DeepSeek。限制每家一次，结果必须通过登记方案校验。用户中止时不再切换后续供应商。主站原有 AI 操作和额度配置无需修改。登记单独允许 2,048 输出 tokens，避免通用文字入口的 512 上限截断整链。
- 集成时由主站导出命名 RPC 入口，从绯月的 `agent/host/registration-ai.mjs` 调用 `createRegistrationAiEntrypoint(WorkerEntrypoint, {...sharedAi, runPaidProbe})`。在 `subscriptions-api` 发布配置将 `REGISTRATION_AI` 指向该入口，并启用 Workers Logs，使用完整采样留存尝试明细。供应商密钥留在主站的 Worker 绑定环境。
- 登记解析的成功和失败都返回 `ai.trace_id` 及按顺序记录的 `ai.attempts`。Worker 以 `registration_ai_attempt` 记录每家供应商、可用模型名、失败码或成功状态、耗时和可用的上游状态。桌面将返回的诊断和任务收发保存为 profile 内的 `task-traffic.jsonl`，达到 2 MiB 时轮转为 `task-traffic.previous.jsonl`。托盘「查看任务日志」打开日志。日志用东京时间，含本地请求号、链号、任务/操作状态和网络错误。请求头、密钥、私密任务正文及供应商原始响应不写入日志。
- 迁移 `012-registration-ai-preference.sql` 为精灵 D1 新增按 owner 保存的首选供应商和 UTC 毫秒到期时间。旧数据无需回填。客户端诊断记录本轮是否从首选供应商开始。任务日志按顺序异步写入，收发网络路径不等待磁盘，打开日志及退出时刷新队列。
