## 2. 对话线与发言

| 对象 | 保存内容与用途 |
| --- | --- |
| 对话线 | 稳定 `threadId`，起因、来源引用、绯月的欲求和交流目的，创建及最近发言时间，以及是否明确结束。开始后保持原编号。结束时记录哪方表达、对应发言及时间。 |
| 发言 | `messageId`、所属对话线、提交顺序和时间、角色、原文，以及回应覆盖的一组用户发言编号。模型回复始终写到请求发起时的 `threadId`。 |

窗口只表示当前关注。对话线分为「可继续」和「已结束」，从发言与推理进度显示等谁回复、处理中或可重试。模型输入预算和单次超时只影响本次处理。

一组用户发言得到一次回复算一轮，便签和气泡共用计数。主动首问、开关窗口、重复交付和后台整理均不计轮。第 50 轮正常回应；仍开放且已完成 50–100 轮时，下一次续答保留已提交的内容，只追加一次换话题的结束语并结案。已结束线继续回看。

**超过 100 轮的旧线。** 在构造对话上下文或恢复续答前检查已完成轮数。超限线供用户回看，隐藏「简单回复」并拒绝旧视图留言。前台、后台续答和重试都不加载旧线或其摘要、近轮，也不调用绯月收尾。点「继续聊天」时只打开零轮的新线，等用户发第一句；旧线的来源、原文、摘要和未答组都留在原处。此规则也适用于已结束的超限线。

提出采用现有 `conversations.sqlite` 和 `conversation-history.mjs` 的加密存储方式，补充对话线及发言关联。保留既有记录编号和来源身份。历史列表的时间及排序字段可索引，正文、目的和摘录沿用现有受保护的负载方式。采用本机 SQLite 事务保存已接受的发言和待回应标记。同一消息重试、崩溃恢复或重复结果交付沿用原编号，每个发言只保存一次；可重试失败保留已提交内容。重启后从已落盘的发言构造下一次请求。数据存储保持原时间语义，展示统一换算 JST。

### 关闭与转换

1. 发送后先写本地，再显示已提交并进入推理。关闭或切线后解除原视图订阅。手动关闭、闲置收起、切线时丢弃未发文字、附件选择及截屏开关，重开时输入框为空。仅失焦时保留输入。宿主与界面都取消对话入口的 `idleDraft` 保存及恢复，仅已提交发言触发回复和整理。在途回执照常落盘，只有视图仍对应同一条线时才刷新当前气泡。
2. 用户提交即标记本线待整理。关窗后在途回复照常写回原线，并关联本轮所回答的发言。主动悬念沿用原问题的完成与同步路径。后台处理见第 3 节。
3. 你明确结束时，在同一条线记下表达和终态。输入中的引用、假设及含糊的暂时离开照常理解。绯月收尾时把结束语和终态一起保存。提交终态前核对本线是否已收到更新的用户发言；针对旧发言生成的结果不得结束仍有新话待处理的对话线。已有终态时，迟到结果不能覆写结束语或重新打开该线。下一次直接查看旧线是回看；新话题可从普通入口开始。

## 3. 每轮推理与优先级

| 入参 | 内容 |
| --- | --- |
| 起因和来源 | 这条线的开端、来源类型和相关材料。引用按资料输入，保留原发言者与来源身份。 |
| 欲求和交流目的 | 绯月想交流的原因，以及可据本轮发言判断的目标。主动发起时从已有悬念或自主行动依据保存，例如欲求是亲近，目的是问你是否愿意下次一起听雨。普通对话可从已知的交流用途填写；缺乏记录时用中性的理解与回应目的。保留已经问清的结论，避免重复追问。 |
| 之前的发言 | 只选同一条线，短线按时序传完整原文，标注「你」和「绯月」。超预算时分为较早历史的简明总结和最近 2–5 轮的详细原话。历史中的来源引用保留身份。 |
| 最新发言与推进方式 | 将本轮尚未回应的一组原话按序单列一次，历史部分排除这组编号。结果提供回复文本和清晰的下一步意向，可自然回应、问一个仍需要的点，或明确收尾。结束意向与结束语应一致。 |

在现有的对话推进提示里加入同线参考：根据双方已经说过的话回应最新进展，适当避开高度相似的说法和交流意向。用户已经答清时可简短接住或收尾，换措辞也不应再问同一个问题。引用原话有助于理解时保留引用，必要的指代和简短确认也保留。这项倾向复用当轮已经载入的同线历史，无需单独做文本查重或跨线比较。

允许续答时，点「继续聊天」立即按提交顺序处理本线尚未回应的一组。已排队则提权，已开工则接续原请求，后来提交的发言留到下一组。无待答发言就只打开气泡。前后台共用续答入口和同线记录，按现有 AI 调度优先处理前台；重复打开不重复执行。模型卸载、重启或切档后从已保存记录重建输入。

本机失败时，可独立理解且允许外发的请求沿用现有云端回退。依赖本机材料时保留原任务等待恢复；用户可选「补充后交给云端」，自行填写独立问题。预览确认后从空参数构造纯文本请求，消息数组为 `[{role:'user', content:确认文字}]`，仅传必要控制参数。旧对话、手记、来源摘录、文档、图片及复审反馈留在本机。取消则继续等待。发送前核对原任务仍待答；结果只写回原线和对应发言组一次。

### 续答重试与历史引用

用户点重试时，从所选线重新读取最新发言及已有回复覆盖的消息编号。把仍未回应的内容按序交给同一续答入口，已发送原话在历史中只保留一次。已有同组在途请求时接续原请求，已全部回应或已明确结束时只展示现状。新回复追加在线尾；若外发补充文字需要随新进展修改，展示更新后的文字并重新取得确认。后台转录失败时仍按既有批次恢复。

当用户要求用「上次」「上一条」等引用查找旧内容，先在原线问一句能缩小范围的问题，等用户给出时间、主题或关键词后才启动此次查找。A 线的追问及答复一直属于 A；在 B 线说的话不作为 A 的提示。

先用提示查当前线已能定位的记录。唯一命中就直接生成提醒预览，多个命中就问一个能区分它们的问题。若需要翻旧 JSON 且线索缺少日期，先问「大概是哪天聊的？」。只读用户线索指向的东京日期，只采用归属当前线的可靠原文。仍未找到则请用户补充。用户确认预览后才执行登记。

生成预览时，引用里的相对日期以原发言时间（JST）为基准。用户明确改期时，改用改期发言的时间（JST）。预览显示具体日期，供用户确认。

### 后台分析与转录

1. 用户提交的输入由原入口先处理，便签归原对话线。供整理的是已提交的用户文字及有用的上下文，含提交的语音转写，附件与截图在范围之外。后台判断哪些内容值得整理；请求办事的输入仍由原入口执行，整理阶段只引用记录或回执。
2. 保存新输入时，在同一次本机事务里更新该线的待整理位置，包括在复盘里提交的「简单回复」。提交后唤醒现有队列；重启或定时轮询只回读已标记的待办，省去遍历完整对话。取得可用时隙后合并同线相邻的新材料，并固定本批发言范围。若刚保存新输入便退出，待办仍可恢复。气泡从未打开或一直开着也能处理。处理中到达的新话留给后续批次。回复晚到时照常写回原线；此前批次已固定的新发言范围保持。
3. 按[自主任务通用规则](DESIGN.md#自主任务的-ai-拆分快照和恢复)把分析和转录拆为两项 AI 任务，每项只含一次模型调用。两项各保留调用前快照及实际输出或失败状态。转录引用已校验的分析结果。失败时保留已有产物，失败步骤重新入等待队列；新增模型复核时按独立调用留痕。最终由同一批次汇总。即时对话按[前台 6 级规则](DESIGN.md#自主任务重入队与前台-6-级回退)先走本机，回退使用本节的资料边界。每次调用仍有独立截止时间。
4. 分析和转录异步排队，有可用时隙时排在一般本地任务之前，前台和高优先级工作仍优先。保留现有转录结果和登记确认入口。有待确认成果时按本次处理结果汇总提醒，能直接打开清单。闲聊、空结果及单条便签的聊天回复留在原线，便签的回复无需即时通知。相同成果重试或回读沿用原作业，避免重复提醒或登记。
5. 分析输入区分「本批新发言」和「历史参考」。历史用于理解指代、补足背景及识别原事项。候选必须能追溯到本批新发言，历史原句不能独立产生新候选。按原线和发言编号固定批次；重开、轮询重复触发、失败重排或重启时沿用原批次。转录结果或空结果持久化后，才把本批发言标记为已整理；转录失败时沿用有效分析。相同事项已存在时，复用现有事项和来源编号去重；新发言确实补充或纠正该事项时记录差异，仍按原确认流程处理。升级保留已有转录结果及待办，旧历史不自动重放。
6. 现有轮询检查已登记的待办，从最早未处理发言的提交时间起超过 24 小时仍未完成整理时，发一次手动处理提醒，关联原待办或批次。提醒后后台继续按原调度及重试规则排队；你也可以打开原待办接手。手动与自动沿用同一个任务编号和已保存进度。后续轮询沿同一标识去重。该时限针对整个待办，单次 AI 调用仍独立计时。

## 4. 来源与界面

- **来源引用。** 原有 `source`、`source_id` 优先复用。手记保留篇号和悬念号，旧对话保留可定位的线号或消息号，其他来源沿用原记录标识。列表显示简短来源，详情显示相关摘录和可用的原入口。原件不可用时展示留存的摘录及状态，缺失时写「来源未保存」。需要 Access 的入口保留原访问方式。
- **本地复盘。** 通用入口默认进入「对话 → 待确认」。T5 原型展示「对话」内的三个并列页签，前两项各显示本类开放数。「待确认」列出绯月主动发起且尚未结束的提问，标明「等你回」或「等绯月回」。「进行中的对话」单列尚未结束的普通对话。「对话历史」仍可回看本期范围内已记录的各类线。三个分类共用同一份对话线详情，显示短标题、最新进展、来源和等谁的状态，详情按发言顺序连续显示，时间以 JST 展示。历史选中某日可定位当天有发言的跨日线，展开仍可看更早的前文。顶层沿用任务复盘、提醒检查、提醒、待确认业务和任务日志的原入口。指定线或指定功能的直达入口直接定位到目标。
- **回复入口。** 可续线点「继续聊天」打开原气泡，「简单回复」在详情内提交留言。已留言只给提交回执，绯月的后台回复留在原线，稍后回看。收尾和超限旧线的处理见第 2 节。
- **气泡。** 沿用透明外形及「对话记录」。已结束时保留最终回复和历史入口，输入框与发送功能隐藏，普通聊天与主动质问使用相同的收窗规则：结束语实际显示后按字数留出 5–24 秒阅读时间，再自动关闭该气泡；朗读期间暂停计时，结束后恢复。「对话已结束」按钮及右上角关闭均可提前关窗。关闭、切线和打开历史时取消旧倒计时；回调只对仍显示该次结束语的原视图生效。历史详情可持续阅读。键盘或语音入口对已结束线同样不再提交。
- **加载。** 首屏只读当前页摘要或当前气泡最近一轮。窄屏点选对话后再读详情，短对话按顺序展示，来源按需读取。列表复用现有分页及状态组件。提供读入中、空列表、来源缺失、读取失败与重试。

### 已确认的范围与入口

- 旧普通对话复用 `desktop/memory-archive.mjs` 的按日读取入口。打开某日时逐条解析当天的旧 JSON，遇到无法解析的记录直接跳过，继续展示其余记录。保留原文件，按可靠旧编号与同线已有记录去重。升级时无需全量扫描或预建目录。

- 普通入口已确认：菜单「问绯月」默认续上最近一条仍开放且允许加载的普通对话，提供显式「新对话」入口。没有可续的普通对话时打开新对话。从待确认或历史可查看指定原线；点「继续聊天」时优先检查第 2 节的 100 轮限制。
- 同源分线已确认：自然延伸和追问留在原线。用户显式选择「新对话」或绯月另行发起独立问题时可建新线，两条线各自保留共同来源。
- 专聊范围已确认：独立专聊的邀请、语音、舞台及其记录本期沿用现有流程。新对话线覆盖普通气泡、便签和「待确认」主动提问。
- 可加载的同线历史超过模型预算时，较早部分用简明总结保留已确定事项、未解问题和关键来源。按原线和覆盖范围复用总结，较早范围增加时才更新；需要模型时复用 AI 队列和调用快照。总结与最近 2–5 轮原话分段，完整历史仍可回看，实际输入预算待隔离样例测定。
- 主动提问容量沿用原入口；普通开放线不占其名额。已结束线退出开放分类，在历史中保留。
