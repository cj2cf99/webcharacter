# 第九组任务获取交接

2026-11-20 更新。启动后及以后每次扫描结束满 15 分钟，本地空闲时轮询。PC 可自动领取指定本机或目标为 `all` 的一项可执行任务。任意一台有匹配处理器的 PC 可以竞争 `all`，成功领取时绑定设备。查询对话、执行和待核对回执占用本机时跳过。截止、依赖、容量和中断重做的确认仍然生效。

### 电脑业务登记与严格串行

目标沿用 all 或指定电脑。「服务器任务：派给 all，串行：创建提醒「喝水」；把提醒「喝水」移到明天」会在一次确认后签发一个提交号，原子创建带顺序依赖的链。使用中文分号或逐行列出事项，引号内保留原文。日记提供标题、正文；随手记提供分类名称、正文；吃喝提供正文；撸管登记一次；提醒可新建或按完整名称改到东京今天、明天、明确日期，改日期保留原时分。登记长期任务提供今日计划派发的完整名称与实际小时数。多项同名或来源锁定时，业务端拒绝写入。

电脑串行委托使用 `POST /api/chains`、`serial_pc:true` 和提交号，服务器按数组顺序绑定紧邻前项。失败、回执未知或放弃会阻断后继；用户可停止整条链。旧模板链保留原有策略。每台电脑最多持有两项执行中的任务，自动扫描只在本机空闲时一次领取一项。每个需要写入的业务节点通过领取编号核验，只在业务回执核实后完成，重放沿用相同逻辑节点。服务端需要迁移 015 和重新加载 PC 模板种子。

验收运行 `node tools/test-serial-pc.mjs`，本地集成副本可加 `--integrated`。使用两个临时电脑身份、隔离主站与任务库，测试结束清理。

## API

GET /api/devices/:pcId/pending?after=cursor，沿用已认证Worker入口。返回`{tasks:[{task_id,type}],next_after:string|null}`，一次最多50条。首次省略after，后续使用上页next_after；稳定task_id升序，不用会被领取动作改变的offset。只返回指定本机或派给 all、PENDING、未超过截止后7天、非暂停disk.query且executor=pc的任务。无截止可领取；满7天排除。只读不产生任务活动/心跳，不推断在线状态。

主站候选挂载后路径为/api/companion/devices/:pcId/pending。本轮未实际挂载主站。

## 桌面

shell启动调用tasks.startPolling()。有配置时用原固定PC ID与hostname登记/更新，空闲时启动即查；之后每 15 分钟检查一次，本地有工作则跳过。查询、对话、后台图像任务、执行、待恢复指令和未确认回执均计入。分页间忙起来就停止本轮，保留上次完整清单。取消退出、取消重启或工作结束后等下个周期。用户仍可在菜单手动查看和接取。无已安装handler的任务保留PENDING，不误报失败。

中断RUNNING不在自动清单，已有recovery中的replacement ID也排除，保留第七组“继续执行”入口。确认退出期间阻止新执行，取消确认立即恢复检查，确认退出停止计时器并取消请求；隐藏只是隐藏，不停止任务。网络失败不改任务状态，下一普通周期再获取，不新建队列/重放平台。

原请求工厂支持可选`task-config.json`字段`api_prefix`：默认`/api`用于子项目独立Worker；主站扩展候选使用`/api/companion`。base_url仍为根源地址，不含token/query。此项只映射路径，不代表取得主站Access机器身份。当前桌面开发Bearer不能替代主站登录，正式机器通行及同源调用策略留第十组。
