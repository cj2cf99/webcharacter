# 绯月任务管理页

## 原始需求

> 吧任务这一套内容做成一个菜单页，具体可以再页内细分，准备挂上入口和菜单加入主站，方便管理和查看。

主站「待办事项」提供一个「绯月任务管理」菜单，总览提供同一入口。页面包含任务链、单条任务、任务模板。旧链链接继续打开任务链标签。单条任务包含链内节点与独立任务，可按状态过滤。详情展示执行对象、参数、进度、结果及尝试历史。未领取的独立任务可取消，按已有执行器分配规则创建的云端任务可手动执行。模板列表兼作独立任务创建入口，暂按现有模板定义只读展示。

## 接线及验收

- 任务链、任务详情、模板、设备、签发提交号、创建和取消沿用服务端契约。新增分页读取 `GET /api/companion/task-overview?status=&after=`，省略空筛选参数，每页三十条，按创建时间和任务 ID 倒序。旧任务仍可查看，已有归属记录的任务按账户筛出。详情展开后才请求完整数据。
- 浏览器经主站 Access、同源检查及私有 `OwnerGateway` 访问任务库。浏览器取消只作用于链外任务。可单独执行的模板继续由既有执行器及服务端校验决定。遇到不确定的创建回执时，保留表单和同一提交号。
- 入口默认加载单条任务。任务链和模板在切换后才加载，所有时间展示使用 JST。取消和执行后重新读取服务端状态。沿用主站东方雅致及赛博科技主题，移动端与桌面使用相同控件。
- 未增加表、种子、回填、凭据、绑定或桌面素材。预计先发布 subscriptions-api，再发布 myapp；旧链接口兼容该顺序。
- 验收检查菜单、总览、旧链接、懒加载、分页筛选和状态读取、新建去重、取消和拒绝越界操作。可用 `node tools/release-preview.mjs --visual-check` 自测隔离双 Worker 和真实 Chrome。用户本地验收用同一脚本的 `--serve` 模式。

设计查阅了 [任务链设计](AGENT_CHAIN_DESIGN.md)、[任务总览交接](TASK_OVERVIEW_HANDOFF.md)、[发布设计](RECORDING_CHAIN_RELEASE_DESIGN.md)、项目开发指南、主站开发设计备忘录 `G:/cloudflare/myapp/docs/design/development.md` 和全局 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md`。遵循单人自用、现有原生模块、紧凑布局和真实 workerd 验证。先前索引检索未找到独立的全局、绯月或订阅 API 开发设计备忘录。

## 本地验收修订

> 图标就用一轮简化的弯月做图标，格式参考首饰铺子的图标，然后需要图标动画。另外页内菜单采用左侧竖排，而且我没看到任务链的新建功能，真题布局也需要重新打磨，需要考虑加载对象较多时候的展示方式。每个子菜单都需要 执行中/已完成/全部的过滤项

- 总览、任务菜单、任务页标题统一使用 SVG 遮罩弯月。页内导航从顶栏改为左侧竖排，窄屏收紧而保留布局。每个分区均有执行中、已完成、全部筛选。
- 浏览器分页按服务端游标读取，链每页 20 条，单条任务和模板每页 30 条。切换分类时才请求列表，任务与链详情只在展开时加载。
- 执行中包含待领取和执行中的任务。已停止链中尚未领取的节点可在全部看到。模板按关联任务状态筛选，可同时满足执行中和已完成，并在卡片显示各状态的数量。
- 「任务链」新增创建入口。手动选择电脑或云端登记，填 1 至 5 个模板节点，每个节点可无前置或选择前序节点。电脑链沿用设备领取，网页可停止继续领取。云端登记链沿用网页执行下一项与回执。创建沿用任务提交号，可在原请求结果未知时重试。
- 本轮沿用上文设计备忘录和数据库结构，参照主站 `src/client/styles/theme.css` 中饰品铺子的图标格式。验收用 `--visual-check` 的附加合成样本覆盖 35 条链、40 项任务、51 个模板。
