## 第一轮　需求和日记内容

- 按更新后的需求核对了每日两次、昨日优先、七个东京自然日、空篇、5000 字续篇、篇首与正文分开检索。单篇追加和悬念状态独立更新有 SQLite 用例覆盖。原需求提到半小时时段，定稿第 9 节明确取消独立时段。当前记录每项事实的来源、发生时间和覆盖状态。
- 发现对话清洗完成后，正文仍使用清洗前的对话，且当时的行动评价只作为生成提示。已修改 `desktop/personality-diary.mjs`，保留清洗后的双方发言，将当时评价与段末私语分别写入。遇到旧缓存只有第三人称摘要、说话人标记丢失时，回退到脱敏的原对话。已有云端正文保持原样。
- 修正了带引号且含空格的密码可能只清除前半段的问题。专项用例用虚构凭据核对，未使用私人对话。

## 第二轮　故障恢复与念叨

- 归档原先只检查盘符。盘符存在但归档目录丢失时，目录读取会返回空列表。改为检查实际归档目录，明确读取失败，留待重试。已验证缺目录时云端日记数为零，成功读取且确无材料时仍能生成空篇。
- 念叨原允许模型返回 160 字情绪，服务端字段上限为 40。已统一生成上限，兼容以前尚未传成功的长情绪草稿。测试以 50 个双码元字符创建旧草稿，补传后按原事项读回 40 个字符。
- 核对了 Paylog 两个东京自然日、金额前五、相邻两周比较、一次一个问题对象、超时续同件、两次中断后的回合上限和主动结束语。已使用桌宠气泡入口和独立存储验证单桌宠流程。多台桌宠同一时刻开口的情况未实测。

## 第三轮　身份、回链与真实运行

- 发现主站页面只读，但直接访问 API Worker 的用户身份也能提交手记。已在 `agent/host/subscriptions.mjs` 和 API 接线补丁中限制直接手记接口使用桌宠的服务身份。主站页面继续使用经验证的用户身份和只读 RPC。手记数据使用既有单主人归属，当主站允许多个账户、无法确定主人时，手记页面拒绝展示。
- `agent/tests/personality-memory.test.mjs` 验证直接用户提交被拒、服务身份可提交、网页可读，以及归属不唯一时拒绝展示。两份接线补丁从各自 Git 顶层带目录前缀执行 `git apply --verbose --check`，主站六个文件和 API 两个文件均实际参与检查。
- 使用现有 Electron 运行 `tools/test-personality-model-electron.mjs`，本机 Qwen3.5 4B 通过 Vulkan 生成虚构书店日记。隔离库读回有双方发言标记、书名、当时评价、私语、篇首和情绪。单个场景不能验证所有自由对话都能被模型逐字保留。
- `node tools/personality-memory-preview.mjs --visual` 通过。隔离 workerd 和 D1 使用主站消费读取代码，在桌面、手机宽度和两套主题中验证按需读取、Paylog 原编号、改期账目、悬念序号定位和返回原念叨。
