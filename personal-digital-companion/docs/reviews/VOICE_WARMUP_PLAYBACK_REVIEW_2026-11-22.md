# 绯月后台听写预加载与气泡语音耗时复核

## 用户原话与试验范围

> 首次识别要等90秒太久了，能不能让绯月启动后在后台预加载，点麦克风就能正常边说边出字？你先测一下会不会拖慢启动。

> 试试**MeloTTS**   实际再精灵发言时加载有多慢，

该阶段为隔离性能试验。沿用已发布的连续录音、手工触发回复朗读及自然分段。依据桌面语音说明、桌宠开发指南和 `TASK_TEMPLATE_PREVIEW.md` 的备忘录查找记录，查阅全局 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md`，沿用最简和按需加载。全局与项目索引未找到独立开发设计备忘录。仅使用本机已有依赖与 32 GB 设备。

## 听写与启动

从实际安装树复制代码和页面到独立树。两组以相同的 Electron 桌宠入口及临时资料启动，保留聊天模型的既有启动流程。预加载组在桌宠显示约 750 ms 后以低优先级启动已有 CPU Paraformer、VAD、标点模型进程。录音继续用同一个进程，抢先录音时音频可以先入队，点击后恢复识别进程的正常优先级。预加载动作不触发采音，实际验证预加载后未点击麦克风时浏览器权限拒绝。

以下为同一台电脑连续新进程对照，系统文件缓存和内存压力未重置。首屏数据是 Electron 启动计时到真桌宠 renderer 就绪并完成两次刷新回调。短跑两组各两次，另有完整听写试验。当前首段样本输出周期约为 8 秒。

| 场景 | 首屏（秒） | 模拟麦克风点击至首段出字（秒） |
| --- | --- | --- |
| 无预加载短跑 | 2.83 / 1.24 | 未录音 |
| 预加载短跑 | 1.02 / 1.05 | 未录音 |
| 无预加载听写 | 1.83 | 42.9 |
| 预加载完成后开始听写 | 0.97 | 8.7 |
| 预加载过程中开始听写 | 0.88 | 13.6 |

预加载本身实测 14.2～20.4 秒，进程工作集峰值约 3.6 GiB，含模型加载过程的瞬态内存。首屏都先于预加载开始，未测到首屏变慢，小样本不用于声称变快。启动前可用内存不一致，暂不将模型就绪时差归因到预加载。长期空闲驻留、开机后系统冷缓存、真实物理输入和低内存策略未实测。上一版正式目录的 90 秒为另一次不同系统负载的记录。本轮未更改识别、分段或 AI 校对产物。

## 回复朗读

在实际安装版的问答气泡中使用同一段固定中文回复，现有气泡自动分为 33 / 29 字两段。GPT-SoVITS 走正式版工作进程配置，MeloTTS 用既有本地 sherpa-onnx 中文 ONNX 模型及默认音色，仅在隔离进程替换合成适配。每次重开语音进程。实际生成 WAV，经气泡解码调用 Web Audio 开始播放。声音在测试窗口静音，计时从点击「朗读」起，回复文字本身已准备好。点击前无音频播放。

| 实验 | 首响（秒） | 后端首段（秒） | 后端第二段（秒） | 两段间隙 |
| --- | ---: | ---: | ---: | ---: |
| reply-melo-1 | 16.4 | 16.2 | 2.2 | 0 ms |
| reply-melo-2 | 8.4 | 8.0 | 1.6 | 0 ms |
| reply-gpt-1 | 88.8 | 88.4 | 3.2 | 0 ms |

第二段耗时发生在第一段播放期间。首次结果包括导入、模型加载、合成及解码。此组未检验实体扬声器听感和音色接近程度。

## 复核记录

1. 实际首屏、短跑和首轮可见录音。可见试验气泡在首段返回前关闭，记录为窗口生命周期干扰，不计入语音速度。改用相同气泡的离屏窗口，桌宠首屏仍按常规入口测量。
2. 离屏复测收齐三种听写场景。最初工作集采样整数宽度不足，修正为 64 位以完成两组预加载测量。原基线点击时延可用，基线完整工作集峰值无记录。确认背景加载后的录音仍需主动点击。
3. 使用正式安装模块测量气泡 GPT-SoVITS 和 MeloTTS。核对两段合成、首响和播放时序。逐项核对实际安装清单的 34 个 SHA-256 与发布时一致。未执行发布、Git 推送或花园变更。本轮状态为试验完成，待用户确认下一阶段。
