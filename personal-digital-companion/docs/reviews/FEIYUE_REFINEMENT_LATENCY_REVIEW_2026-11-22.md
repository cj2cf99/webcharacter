# 绯月本机修订延迟和模型驻留复核

2026-11-22 JST。用合成手记与补充证据测试隔离 Electron 和本机模型。范围为日记与唠叨修订的单次核对、拟稿和复核，以及高频调用期间的模型驻留。用户目标为单次 AI 调用尽量压到 15 秒、连续调用间复用已加载模型。对照[原始需求和后续变更](../../REQUIREMENTS.md#2026-11-22-jst--绯月逐条修订日记和唠叨)、[修订设计](../DESIGN.md#2026-11-22-jst--绯月逐条修订日记和唠叨)、[备忘录索引](../TASK_TEMPLATE_PREVIEW.md)及 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md`。沿用现有模型选择、独立进程、取消和 SQLite 检查点。索引中未找到独立的全局或项目设计备忘录。

## 同一合成手记的延迟

| 路径 | 冷启动核对 | 已加载后正文拟稿 | 已加载后摘要拟稿 |
| --- | ---: | ---: | ---: |
| 原 9B CPU | 约 100.2 秒 | 未测 | 未测 |
| 当前 4B Vulkan | 7.07 秒 | 1.31 秒 | 2.26 秒 |
| 当前 2B CPU | 5.28 秒 | 3.51 秒 | 3.53 秒 |

原 9B 的 GPU 准入门槛为 6656 MiB，实测空闲显存约 5900 MiB，于是退到 CPU。原核对从请求开始到首 token 为 21.0 秒，生成总计 401 个 token，从首 token 到结尾又用 73.9 秒。表中当前路径的冷启动核对含加载，热调用沿用同一进程。冷启动加载部分分别约 4.34 秒及 1.79 秒。当前严格摘要校验在拟稿后拦截，两条实际路径均未进入最后复核或提交。

## 三轮复核

1. 找到固定使用 9B CPU 的慢路径。为修订单独选轻量模型，缩短阶段提示及输出，长记录分段，每次调用含等待、加载及生成共 15 秒。保留 SQLite 断点、七天限频、一个在途任务及本地历史与云端原版／最新版边界。
2. 2B 实测把有改动的稿件误判为无改动。改由程序比较可写字段，有改动时仍由模型复核。允许显存合适时用 4B GPU。该版实测 4B GPU 复核用 2.16 秒，2B CPU 复核用 4.02 秒。
3. 最终检查发现两个真实模型都可能把整篇格式或正文写进摘要。已分开正文和摘要提示，并拦截多行摘要或正文新增的篇首字段。正文明显重复句和末尾已知空栏目的清理仅作用于可写片段。第三轮实测的进度停在摘要，正文稿仍在 SQLite，云端样本无提交。真实模型摘要质量仍待解决。

## 模型驻留

普通对话的 60 秒用于当次推理。模型空闲期间保持就绪。修订单次超时先取消生成，并等进程确认已停止后复用同一模型。取消超过一秒无响应才关闭该进程，供后续重建。换档、专聊让出资源、进程异常和关闭桌宠仍按原流程执行。

测试模拟空闲 61 秒后调用，模型仍只加载一次。隔离 Electron 的 2B CPU 合成问答实测冷启动 2.46 秒，在中间一次调用被取消后，下一次用时 0.61 秒。三次调用只启动了一个模型进程。无响应时的清理和下一次重建由专项测试覆盖。

## 并行实验

在 RTX 4060 Laptop 上使用同一 9B Aggressive 权重、4 个计算线程和两个独立生成序列。实验给分层装载预留 768 MiB 显存，Vulkan 装入 33 层，权重占约 4810 MiB。模型和上下文准备后送入两条合成核对请求。

| 方式 | 第一路 | 第二路 | 两条完成 |
| --- | ---: | ---: | ---: |
| 一个 9B 串行 | 5.20 秒 | 6.58 秒 | 11.78 秒 |
| 一个 9B 双序列并行 | 10.03 秒 | 11.57 秒 | 11.59 秒 |
| 9B GPU 和 2B CPU 并行 | 5.36 秒 | 3.93 秒 | 5.37 秒 |

一个 9B 双序列只小幅缩短两条合计时间，首次提交的单条完成变慢。9B GPU 和 2B CPU 可以同驻并交叠计算，合成核对样例都返回所需字段。这一轮验证设备分工的可行性。长时间驻留、实际前台和后台交错、显存压力及完整修订仍需进一步验证。开发版原有单模型调度保持。

### 9B 空闲驻留开销

隔离 Electron 用 Vulkan 装载 33 层，采用 2048 token 上下文、单序列和 2 个计算线程。加载约 4.59 秒。显卡整机空闲显存由约 6380 MiB 降到 1710 MiB，卸载后回到约 6390 MiB。进程工作集由约 280 MiB 增至 6198 MiB，系统可用内存同期少约 5.8 GiB。工作集可能包含可回收的文件映射页。驻留期间没有推理，进程短窗口的 CPU 采样约为 0%。显卡功耗快照波动，无法据此估算长期耗电。长上下文和并行任务的峰值另需实测。隔离测试用显存余量自适应分层装载。现有常规 9B GPU 准入要求 6656 MiB 空闲显存，本次加载前低于该数值。

按相同上下文、序列和线程数补测 4B Vulkan 与 9B CPU。4B 就绪用 3.65 秒，系统空闲显存由约 6350 MiB 降至约 3112 MiB，可用系统内存少约 2.9 GiB。直连档实际使用 Qwen3.5 Aggressive 9B，即前述 9B 权重。退到 CPU 时模型显存开销为零，3.16 秒就绪，系统可用内存少约 5.8 GiB。用合成问句生成一个 token 再回到空闲，内存差约 7.8 GiB。系统内存值含可能可回收的映射和缓存。当前桌面调度同一时间只保留一个模型，直连换档沿用原规则。

2B 同口径实测。Vulkan 加载 25 层、3.24 秒就绪，系统空闲显存由约 6356 MiB 降至约 4602 MiB，可用系统内存少约 1.3 GiB。CPU 1.54 秒就绪，模型显存占用为零，可用系统内存少约 1.2 GiB。用合成问句生成一个 token 后回到空闲，可用系统内存少约 1.9 GiB。对 2B 的这些驻留数值只验证了单路隔离环境。

## 扩展样例与 4 线程上限

用户要求扩大样本并把上限设为 4。本机为 Ryzen 9 7940H（16 个逻辑处理器）和 RTX 4060 Laptop（8188 MiB）。仓库中的模型进程配置了最多 4 个计算线程，每个模型进程一次处理 1 个请求。本次 CPU 计算线程和 GPU 并发请求分别测试 1 到 4。用相同的 4 个合成任务测单次核对、拟稿或复核，正文片段为 16 至 131 字。计时从已加载的模型收到请求起算，15 秒内返回结构合格的数据算通过。

| 9B Vulkan 的同时请求数 | 15 秒内完成 | 完成样例中的最慢耗时 | 超时 |
| --- | ---: | ---: | ---: |
| 1 | 3/4 | 11.92 秒 | 1 |
| 2 | 2/4 | 14.58 秒 | 2 |
| 3 | 2/4 | 12.04 秒 | 2 |
| 4 | 1/4 | 10.78 秒 | 3 |

四个序列可以在同一 9B 上建立并启动。这批任务中，单路也有一条核对超过 15 秒，因此没有测到 9B 自身能稳定覆盖这批任务的并发档。大模型可在适合它的任务中保留单路，修订单次时限沿用轻量模型路径。

| 2B CPU 每条请求的计算线程 | 15 秒内完成 | 中位耗时 | 最慢耗时 |
| --- | ---: | ---: | ---: |
| 1 | 4/4 | 7.72 秒 | 10.96 秒 |
| 2 | 4/4 | 4.80 秒 | 7.15 秒 |
| 3 | 4/4 | 4.23 秒 | 6.21 秒 |
| 4 | 4/4 | 3.97 秒 | 5.85 秒 |

2B CPU 每次仍处理一条请求。对这批样例，4 个计算线程的中位和最慢耗时都最低。未改动实际调度，也未扩大到 4 以上测试。

### 完整修订验收

另用 3 篇合成日记和 3 条合成唠叨运行真实修订入口。每条使用单独的 SQLite 检查点和独立的模拟云端数据库，模型进程复用。分配器自然选中 4B Vulkan。总计 20 次推理全部在 15 秒内，含模型加载的最慢单次为 7.12 秒，已加载后的最慢单次为 3.08 秒。

| 样例 | 结果 |
| --- | --- |
| 书桌日记、改约日记 | 两份正文草稿已保存。模型把原话和多行正文写进摘要，两条均被摘要格式校验拦截。 |
| 空日记 | 正确跳过，零次模型调用。 |
| 车票唠叨 | 7.35 秒完成核对至提交。保留原对话和未购买回程的事实，SQLite 中有前版、备注和精确时间。评价中重复复述了部分原话。 |
| 图书唠叨 | 复核发现后记截断。补做一次后仍待修正，检查点保留。 |
| 搬家清单唠叨 | 模型原样返回含重复的段落，程序记录无改动。 |

5 条有效记录有 1 条提交。6 条的既有原文和对话均保留。这批结果把单次推理时限和整条修订质量分别验证。完整质量仍待处理摘要越界、后记截断和剩余重复。
