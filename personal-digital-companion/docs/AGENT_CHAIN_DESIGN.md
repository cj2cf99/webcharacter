# 本轮链式任务：详细设计与验收

2026-11-18，Asia/Tokyo。用户已确认建议并指示“开发吧”。本线负责非界面能力及现有桌面壳最小接线，不制作新的管理网页。

## 原始需求与变更依据

> 本轮需要链式任务，加入开发，主要是连续指定最多5个任务，每个任务默认没有前置节点，如果设置了，就是强制链式先后执行。
>
> 当前终端任务已满就不能再接取新任务，且接取任务是显式主动接取。强直接取也不能超过2，只是可以接取原来不能接取状态的任务。强制接取会更新终端，但是备注中需要记录这个切换。
>
> 任务最终失败需要向我报告，继续，停止，跳过由我决定。
>
> 不绕过前置，但是会重新执行。
>
> 每个子任务暂且认为都是等冥可以重做的。

最新决定覆盖此前链式暂缓、自动领取和无数量上限的约定；单用户、同账户多终端、无负载压力不变。暂按所有单元幂等可重做。历史文档保留为当时依据，不继续执行被覆盖约定。

## 三个细任务

1. D1 保存最多五个节点的任务组、前置关系和执行轮次；统一普通/强制领取、失败决定、两个名额以及旧中断恢复的规则。
2. 桌面清单刷新改为只读；提供显式领取、完整链查询和确认操作的非界面接口，接现有托盘/原生提示。显示领取终端与切换备注，最终失败提示用户选择。
3. 隔离数据库与真实本地执行线程验证，独立检查 bug、需求偏移、最简设计，记录实际结果；不启动常驻 Worker 或访问生产数据。

## 规则与例子

原子写入依据：[Cloudflare D1 batch 文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)，2026-11-18 查阅。使用现有 DB.batch 的事务回滚能力，条件在 SQL 写入时复核，不新增锁服务。

- 一组 1–5 个节点，每节点最多一个同组前置；默认无前置。创建拒绝缺失节点、自引用、循环。稳定节点指向当前 task_id，重做产生新 task_id，原 task 与 executions 保留。
- 例：A 花园登记、B 随手记，默认都可选；只有给 B 指定 A 后，B 才等待 A 成功或用户明确跳过。这是流程示例，不意味着本批实现这两个业务处理函数。
- 每终端最多持有两个尚未结束的已领取任务，计算所有单任务和链任务；领取用 D1 原子条件更新。待领取 PENDING 不占名额。领取立即写 RUNNING 和终端归属，因此另一终端不能重复普通领取。
- 例：homepc 已领取 A、C，B 即使前置满足也不可再领。结束其中一个才释放名额。强制接取不能拿第三个。
- 强制接取重新执行，保留旧轮与备注（旧/新终端、时间、原因/操作）。旧运行轮停止作为当前轮，但其迟到结果可保存为旧轮历史，不推进后继，也不覆盖新轮。终端切换不等同于远程物理停止旧进程。
- 强制也检查前置、名额、暂停类型、截止后七天及任务组停止条件。重做前置使尚未领取后继重新等待；正在执行后继允许完成；已完成后继不自动重做。
- 每轮第一次失败立即再试一次；第二次失败结束并报告，等待用户决定。继续＝为失败节点建立新轮（最多再执行两次），跳过＝明确放行依赖，停止＝本组不再接受新的领取，已执行节点可正常结束回报。没有自动继续或自动跳过。
- 组未结束但无可领取节点，返回全链与明确原因：名额满、其他终端已领取、等待前置、失败待决定、取消/超过期限、用户停止等。不能全部标成执行故障。
- 重开后的中断处理继续由用户决定；重做与其他入口使用相同前置和名额检查。断网保留本地结果，恢复后只补传。领取回执不明时不得盲目另开新轮。
- 展示默认 JST，存储 UTC。任务类型说明、JSON 参数、如何执行和报告沿用 tasklist，不引入流程脚本语言。

## 验收大纲与标准

| 场景 | 通过标准 |
| --- | --- |
| 组创建 | 1 和 5 节点有效，6 节点/循环/跨组或缺失前置拒绝；失败不留半组数据 |
| 默认独立 | 两个无前置节点都可选，设置前置后严格阻挡；失败不作为成功放行 |
| 显式接取 | 启动/轮询只读清单，无自动 claim 或执行；按钮/调用明确后才领取 |
| 两个名额 | 单任务和链任务合计最多 2；重复点击/不同领取入口不能超过；结束后释放 |
| 多终端 | 普通重复领取拒绝；强制后当前归属切换、备注可读；旧轮迟到回执不改当前轮 |
| 强制重做 | RUNNING/COMPLETED 可按规则新轮重做；不得越过前置、名额与截止边界 |
| 前置重做 | 未领取后继等待新轮；已运行可结束；已完成不自动重跑 |
| 最终失败 | 一轮只试两次；报告失败并提供继续/停止/跳过；不自动推进 |
| 无可选节点 | 全链包含状态/归属/原因，能显式选择允许的强制接取 |
| 中断与断网 | 退出二次确认仍在；重做不绕过限制；旧结果只补传，新轮历史不被覆盖 |
| 回归 | 原身份、登记、任务参数、截止七天、AI 建议显式确认、桌面生命周期通过相关测试 |

测试用隔离 SQLite D1 适配器和 mock handler；真实 Cloudflare D1、Access、原生弹框观感及业务登记效果未测试必须明确列出。子代理先审计再开发；主审核按本线已确认流程最多四轮，无问题即停止，超限由主会话接手最多两轮后报告。实际验收结果写独立复核报告，不把本大纲当成通过证据。

## 实现过程中确认的衔接点

原单任务中断“放弃”意为 CANCELLED，没有链式后继。用户明确选择“视为跳过该节点，后续可继续”。据此当前链节点中断后放弃，保留任务CANCELLED及未知快照，原子地将当前节点标为已跳过，使后继可以继续。被force替代的旧轮放弃仅保存历史确认，永远不能改变新轮及当前依赖。独立任务放弃仍只取消，不虚构链关系。
