# 绯月抽卡 · 需求

状态：2026-11-28 JST 用户确认界面原型定稿、阅后回复“开始开发”。开发区已实现，正式版未安装。见[设计](CARD_DRAW_DESIGN.md)。

## 1. 用户原话（按提出顺序）

1. “我在试图做一个抽卡功能，作用是临时消费我的api额度来指定一个意向性内容来让ai接口随机作图。主要功能就是用掉我基本不怎么用的openai的apikey额度，目前似乎只能用来画图，其他地方用不上”
2. “那就低精度抽卡，高精度修图，我的额度本身也不多，可以一试。抽的卡全放本地，我基本不看，让绯月自己抽卡，可能的抽卡对象只有chatgpt，这俩访问地址是固定的，这个直接写在piclist，然后apikey我会执行时，手动填写，填写后第一次执行成功就保存本地，简单加密就行。抽的卡我基本不会立刻看，而是想起来的一起找找，然后看哪张合适了，然后勾选，绯月自动去访问接口高清化。抽卡的图和高清返图需要分开放，没必要产生任何联系。然后所有我没有勾选的图，都会是一键清理的对象。”
3. “抽卡界面做人物，服装，动作，提示词4重输入，但是我也可能只输入一部分内容，这个提示词部分你需要自适应。这个我配置完成后，绯月要能记住输入，每次都是一样的。”
4. “自动抽奖吧，1分钟1张，有高清重置要求就插队下一个循环优先处理。”
5. “就是奔着4天以内花光去的，而且我也只有晚上能用，没问题。不用限制。”
6. “高清就2048，不要1024，看不清”
7. “给个原型我看看界面再说”
8. “你自审结束后先来一轮优化和最简化合规检查”
9. “这三个都是图片，只有提示词是文字”（指人物、服装、动作）
10. “定稿，写文档”
11. “开始开发”
12. “另一个问题，我要怎么停止这个循环”（开发中提问；现有停法：关开关停抽卡，取消勾选停排队的高清。未改规则）

过程中的两处提问（非新增规则，R8、R10 的背景）：第 1 条之后问“低画质有多低”“能根据图返修精细化吗”。

后续变更在本节追加原话，不覆盖旧内容。

## 2. 目标与范围

单人自用。让绯月在后台自动用 OpenAI 生图接口抽卡，把基本闲置的额度在几天内用掉；用户事后挑图，勾选的重绘为高清。

## 4. 与框架默认的差异

按本次要求：图片只存本机，不用主站、D1、KV 和 GitHub 图库；图片入口不含 HTTPS 网址。

## 5. 不包含

稀有度、分类、Tag、图鉴、蒙版涂抹、逐张修改要求、其他服务商、多套配置、抽卡图与高清图对照、余额查询、定时开关、手机查看、导出。

## 6. 费用与前提（开发前需知）

- 带参考图时每张抽卡按图片输入 token 另外计费。此前口头给出的“每张约 $0.006、每小时约 $0.36”只是旧型号纯文字的参考，**不适用于现方案**，实际以接口返回为准。
- 能否 4 天花光取决于余额和实际单价；单价明显偏低时，是否提高抽卡画质另行决定，本期固定低画质。
- OpenAI 可能要求先完成组织验证才能用生图模型，需用户在 OpenAI 后台处理。
- 2.6 系列输出 2048×2048 官方说明不一致，需首次实测；失败不自动降为 1024。

## 7. 验收要点

1. 菜单进入，冷启动首次点击可见窗口。
2. 四项任意组合都能抽出图；有参考图走改图接口，没有走生图接口。
3. 开关开着时间隔 60 秒一张；勾选后下一轮先做高清；两者不并发。
4. 5 秒内撤回不产生请求；高清完成的卡重新勾选不再请求。
5. 重启绯月后输入、开关、勾选、累计花费仍在；在途高清显示失败。
6. 首次成功后重启无需再填密钥；密钥不出现在日志、状态文件和页面。
7. 清理只删确认时清点的未勾选卡，高清目录不变。
8. 认证、额度错误立即暂停并提示；连续 3 次其他失败暂停。
9. 浅色、深色、360 宽无横向滚动。
