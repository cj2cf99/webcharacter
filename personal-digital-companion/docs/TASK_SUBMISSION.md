# 普通任务一次性提交号

用户要求：

> 我需要在服务器维护一个随机种子，每次被调用就会导致随机种子改变，通过这个方式，获取和维持短期内同一个任务不会被重复新增，每个任务都需要提交前获取本次提交的种子编号，有且仅有种子编号不重复才能提交任务。
>
> 把这个功能做出来，看起来不是很难的内容，但是我不确定每个现有表都有可以记录编号的地方，这个内容可以考虑作为同名称列给必要的数据库表一个个加，不急于一次全部加上。
>
> 不用限制时间，取消时间到了重新领这部分的需求，这是无效的多于设计

每次签发独立随机 UUID，已经签发的提交号无有效期，可按任意顺序提交。本轮覆盖普通任务的 POST /api/tasks，包含手工任务和助手确认后的任务。

依据 WebCharacter CLAUDE.md、根和子项目开发指南、TASK_TEMPLATE_PREVIEW.md、AGENT_CHAIN_DESIGN.md、ASSISTANT_API_HANDOFF.md，以及 `G:/selftool/resourceforlater/docs/FRAMEWORK_PREFERENCES.md`。项目和全局索引未发现独立设计备忘录。沿用单人同账户多终端及 D1 条件写入，签发简化为单条记录插入。

1. **签发。** POST /api/task-submissions，当前认证账户可申请，主站挂载时沿用现有同源验证。返回 201 和 `{submission_id}`。每次申请单独得到一个号。
2. **提交。** POST /api/tasks 额外要求 `submission_id`。D1 的条件 INSERT 核对签发账户，唯一索引让一号只能对应一条任务。首次创建返回 201，同号同任务内容返回 200 及当前任务状态。JSON 字段顺序及等价截止时区不构成冲突。缺失或格式错误为 400 INVALID_SUBMISSION_ID，未为当前账户签发为 409 SUBMISSION_UNAVAILABLE，同号对应不同内容为 409 SUBMISSION_CONFLICT。错误参数不占号。
3. **接入。** 助手在用户确认时获取并保存提交号。创建回执未知后，再次确认继续用同一编号和同一数据。HTTP 调用方在需要跨重启恢复时保留原编号及请求数据。跨设备核对同一次提交也用同一个号。两个不同号可以分别创建内容相同的任务。

例。手机获取编号后提交一条提醒任务，服务器插入成功但响应丢失。手机重发原编号和原内容，收到同一个任务 ID。电脑先前领取的另一个号仍有效，可以用于创建另一条任务。

## 数据库

`agent/migrations/007-task-submissions.sql` 在 006 后单次应用。仅在现有 `tasks` 追加可空的 `submission_id` 外键列及唯一索引，旧记录保持 NULL。新增 `task_submissions` 保存编号与签发账户。本次直接修订尚未应用的 007 迁移，去掉有效期列和索引。

目标业务的去重仍由目标端处理。任务创建使用提交号；同一任务登记业务记录的重试沿用任务标识或目标业务键。这一轮未给业务表加列。
