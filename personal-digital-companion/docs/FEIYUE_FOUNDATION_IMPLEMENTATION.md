# 绯月的记忆、情绪与欲求：实现说明与需求溯源

核对日期为 2026-11-21 JST。对象是桌宠开发工作区，Git 基线为 `3b55903d8830`，包含核对时已有的未提交改动。本文解释当前程序会做什么、这项行为从哪里来、为什么这样实现。正式安装包、用户个人资料和线上页面不属于这份源码核对的证据。

最值得复查的是三个决定。第一，桌宠记下了哪些**事实**已写入日记，却无法回答某来源的哪个**半小时**已查遍。第二，强制欲望具体选谁、如何暂存原欲望、等待多久，由程序定了规则。第三，用户指定了“爱情和理智”的判断原则，六种转移名称和部分触发判据由设计者补写，运行时只对其中一部分作强制校验。

## 一、依据和读法

下表给后文每项功能提供可追的出处。**原定**指有明确用户用语。**采纳**指设计者先提议，能定位到用户对该提议的答复。**自定**指为了实现所选的做法，找不到该细节的逐项确认。**差异**表示源码与原话或设计不完全相符。一个功能可以同时有原定目标和自定做法。文中的“理由”解释实现取舍，不代替用户授权。

| 代号 | 用户决定与证据 |
|---|---|
| R1 手记 | “专门给桌宠翻记忆用”“每段后面都应该跟一个ai模拟的妻子的评论”“绯月的直接回应也要记下来”。同日允许多篇，每篇上限 5000 字，检索和正文分开。后续指定尽量保留原话、纠正明显笔误、全篇情绪一致。见[记忆需求 §1、§4](FEIYUE_PERSONALITY_MEMORY.md)。 |
| R2 取材、补缺与核验 | 本次会话有“范围按半小时处理”“优先补充昨天”“成功与否看结果”。留档原话另有“预期一天2次”“当天没材料就写一个空内容日记”，以及个人日记、花园部署、当日 Paylogs 三种可缺省的素材。见[记忆需求 §1、§4、§9](FEIYUE_PERSONALITY_MEMORY.md)及[半小时口径审核 §12](reviews/FEIYUE_EMOTION_DESIGN_REVIEW_2026-11-21.md)。 |

| R4 相处和情绪 | “活照干，气继续生”，一个情绪词加一句含欲求的状态。当前、历史、具体事件共同影响态度。历史两组各最多十条，最新一条占半。用户优先、自身第二，意见同向加强、相反减弱。工作和交流档位有“用推荐方案”的明确回复。见[人格需求 §1–3](FEIYUE_EMOTIONS.md)。 |
| R5 欲求和周骰 | 满足当前欲求立即拉满，稳定 3 次刷新，可累计。七个骰面及其方向由用户给出。周一首次念叨前换面，必须异于前次，连续重掷十次仍相同则顺移一位。见[人格需求 §1、§4–5](FEIYUE_EMOTIONS.md)。 |
| R6 主动行为和池 | “根源应该出自欲望然后被情绪影响方向”“只取一个欲望实现和反馈”。按登记时七罪分类，同类有效在池数达到 100，强制指定一个，清本系、其他随机清半并向上取整。最新裁定“欲望是具体行动，躲清闲整理是倾向，具体行动优先权高于倾向”。见[人格需求 §1、§4、§6](FEIYUE_EMOTIONS.md)及[最后一次纠偏记录](reviews/FEIYUE_EMOTION_IMPLEMENTATION_REVIEW_2026-11-21.md)。 |
| R7 好奇和专题 | 对话触发本机查旧账，未知内容空闲时查，争取五条、最多三次。确认后分享、登记并写日记。专题有本机目录，可长期更新、精简，更倾向保留用户亲述或偏爱的原文。喜好可以凭经历改变。最新要求主件外最多三份备份，全损先留坏样本、重新整理并求助。见[专题要求 §7](FEIYUE_EMOTIONS.md)及[恢复规则](FEIYUE_EMOTION_STORAGE.md)。 |
| R8 闭环与资料边界 | 用户命名“爱情和理智”，要求情绪和欲望两个变量，每轮说清结论、行动和下一轮倾向。复盘细节本机可查、方便打包。后续要求用 Aggressive 9B 全面替代原 4B 职责。见[闭环设计](FEIYUE_LOVE_AND_REASON.md)、[技能设计](FEIYUE_EMOTION_SKILLS.md)、[存储设计](FEIYUE_EMOTION_STORAGE.md)。 |
| R9 后续采纳与修订 | 记忆需求 §7 的 a–h 有“全部同意”，包括闲时写、补评七天、金额排序、历史天气取本机记录等。“可以晚点哄”“误会后主动改口”有针对两项的“都加”。“去掉助理身份”覆盖了最早的“妻子＋助理”。七天手记质问还有独立的后续需求。见[记忆原话及补充](FEIYUE_PERSONALITY_MEMORY.md)、[相处原话与未单独确认项](FEIYUE_EMOTIONS.md)。 |

## 二、一段互动如何留下记忆

日记、逐事项评价、当前心情是三种记录。用户纠正绯月时，日记应保留双方当时说过什么，事项评价可以说她对误报感到懊恼，全局心情则按这次交流实际发生的事情结算。三者有各自的日期、出处和修订方式。

| 功能 | 需求来源 | 现行行为与改动 | 实现理由及边界 |
|---|---|---|---|
| M01 定时写与手动补写 | R1、R2、R9 | 新建配置默认每 720 分钟写日记、60 分钟补评价。已有轮询用持久化配置。写作按东京日期依次查昨天、今天、再查前 2 至 6 日。菜单也可触发。 | 先补最容易漏的昨天，写作避开前台。早期聊天说每小时写，留档探索说每日两次。源码采用后一个数值，没有证据表明用户本机当前配置就是默认值。 |
| M02 本地事实和可选外部来源 | R1、R2 | 读归档对话与双方原文、任务标题／动作／结果、天气播报、念叨问答与评价、已核实专题版本。可按日再读个人日记、各项目部署、消费。天气优先用当天已记录的播报，也可取天气对话，没有则写“无记录”。 | 知道她为什么有这个感受，也能查到她当时实际做了什么。外部来源读失败留待补读，不能用虚构条目补齐版面。 |
| M03 清洗与原文 | R1、R2 | 保留“你说”“绯月当时回复”。旧清洗结果缺说话人标识时回退脱敏原段。过滤凭据、代码及明显噪声。单个长字段超过 500 字走概要与脱敏 TXT 原文，合并附件超过 1 MiB 留本机并提示。 | 防止清洗后只剩第三人称转述，也控制篇幅。长文概要／附件改变了原话的展示位置。此处能证明现行行为，未在本次人格原话中找到附件阈值的逐项出处。 |
| M04 行动评价与补评 | R1、R2、R9 | 对有有效正文的行动保存当时评价。补评与写作复用同条材料和已有评价，手动补任务评价直接查本地任务归档。已判空的正文跳过，字段丢失可重试。 | 任务做完但尚未写日记时仍有生活材料。防止重复评价改写旧态度，也避免把读取失败当作“没干过活”。 |
| M05 写前定情绪与段末私语 | R1、R4、R9 | 先汇总既有段落评价与待写素材，再按该底色生成事实经过、当时评价、绯月私语。按来源附摘记，篇首单独生成。追加时可更新篇首与情绪，保留旧段当时的原文。 | 读者能分清发生了什么、她当时怎么想、写日记时怎么回看。这里的写作情绪来自该日素材，不等于写作当刻桌宠的全局档位。 |
| M06 防止捏造用户动机 | R1 的忠实记录目标，具体判据自定 | 模型若无原文支撑却写“特意给我买”等，部分固定措辞会触发回退，改成摘引材料并表达好奇。 | 来自实际买书样例的误判。逐字匹配与固定回退句是我的补法，会漏掉别的措辞，也会把某些真实感受写得雷同。 |
| M07 分篇、快搜、空篇 | R1、R2 | 相同东京日期下按篇号累加，追加正文和分隔换行超过 5000 字符就另开一篇。查询只用日期、篇首摘要、标签、情绪等轻字段，支持 `@#` 查标签，正文点开再读。来源成功查完又无有效内容才创建“无所事事的一天”。 | 允许一天多篇且快搜不用读长正文。默认空篇情绪“平静”是程序填的，用户指定了占位文字，未指定它当时的心情。 |
| M08 来源覆盖与防重复 | R2，**差异** | 材料保存业务来源、时间戳、材料 ID、清洗结果和覆盖位。云端读回成功后标该材料已覆盖。运行库没有“来源 × 半小时时段”的已查清单。 | 我用逐事实去重简化写入，能回答“这条事实写过吗”，不能回答“昨天某半小时的任务记录查过且确实为空吗”。后续设计写了取消时段，但没有找到用户专门同意取消的原话。 |
| M09 离线草稿、上传、结果核对 | R2 | 先存本机草稿，传同一批次，再按返回的日期和篇号发起独立读取，核对完整段落才清草稿。旧空篇和并发追加有独立处理。念叨按发布字段重新构造载荷并回读对应记录。 | “接口成功但服务端看不到”要求把成功判据落在已存成品。源码可证明读回协议，主站用户实际能否看到这一版仍要以线上页面为据。 |
| M10 悬念与旧正文 | R1、R3 | 每篇悬念有编号，“已问”和“已解”分别登记。后来的事实追加在对应日期，关联原悬念再标已解。正文和旧私语留着。 | 问过一次仍可能没解决。用两个标志能在保留当时不确定性的同时告诉读者后续结果。 |
| M11 挑选念叨对象 | R3、R9 | 消费查东京今天及昨天，排除退款、负额、已问及可对应的既有解释。单笔 ≥3500 日元或游戏娱乐，金额降序取最多五笔；分类不明可推测并标记。另取七日内可问的悬念。基础模式合并后随机选一，接入主动内核时由模型在当前材料内选。 | 36 小时旧消费口径已被“两天”覆盖。普通小额且非娱乐的未知用途没有单独逐笔询问入口。动态内核取代均匀随机，改变了哪些事情更常被提起。 |
| M12 翻旧账的统计窗口 | R3 | 按选中消费的分类分别统计前 1–7 日和前 8–14 日金额、笔数，今天不在两段统计内。已问账目仍算在统计里，来源不全时带缺口标记。 | 两小时控制多久可以开口，两天控制挑哪笔，两个七天解释她为什么关心。月、年、同比是后续设想，当前入口没有通用跨板块比较器。 |
| M13 一次一件、何时算已问 | R3 | 同一来源和原 ID 绑定念叨，题目、触发理由、统计摘要、开口前评价与心情随记录保存。显示回调才写“已问”。有待续项继续原件，即使有新高额消费也要等。 | 防止隐藏气泡误占对象，也避免排名变化导致再次提问。主站详情按原 ID 打开消费、悬念原篇或质问主篇，原件不存在会显示查找失败。 |
| M14 回答、拒绝和意外中断 | R3 | 保存用户解释、绯月回复、听后评价与情绪。无操作转等待；突然中断可恢复；明确点结束收口，记“老公闷闷的不理我了”。最多三核心问题、六回合，两次意外中断后压缩剩余回合。未问清可留日记悬念。 | 用户能停止，沉默不被登记为拒绝。回合限制能对到用户后续原话。关闭、回复、显示分别有状态，重启能从已保存的解释续办。 |
| M15 七天手记质问 | R9，单独追加的功能 | 从近七天绯月自己的手记挑一条关键矛盾、逻辑错或过程缺失。关联一个主篇，可有多篇原文作证。问过的主篇与引篇排除。稍后答至少隔一小时再提醒，补问总计至多两次。 | 用户要求的是核查绯月自己写过的东西。单独约束引文、主对象及答复，可以回查她为何质疑；这套上限不能套给普通消费念叨。 |

## 三、情绪如何变化，哪些变化会被执行

| 功能 | 来源 | 现行行为与改动 | 实现理由及边界 |
|---|---|---|---|
| E01 两个连续变量 | R4、R8 | 情绪保存方向、强度、一个主词和一句内心话。当前欲求保存身份、内容、满足条件与生效时间。程序初始为正 1、“平静”、“我在这儿。”、无欲求。 | 允许“仍想被夸，但今天已经累了”。两个变量是用户指定；初始台词、初始档位以及无欲求时允许内心话不带期待，由实现选择。 |
| E02 三种情绪来源 | R4 | 评价输入包括当前状态、本次事件、喜好、周倾向，以及两组历史。手记按日期和同日篇号排序，念叨按创建时刻排序，各最多十条，只给日期、情绪词和已有强度。最新占半，其他均分，一条独占，缺值留空。权重规则给模型理解。 | 避免念叨数量大就吞掉手记影响。用户定“最新一半”，余下均分、只给这三列由设计补齐。没有可复算的“当前×系数＋历史×系数＋事件×系数”总分。 |
| E03 谁的立场优先 | R4、R8 | 评价技能提示先顾用户的实际处境、感受，再看绯月的偏好、好奇心与欲求。同向加深、反向缓和。节俭写入评价提示，大额或游戏本身不足以判定乱花钱。 | 同一笔消费可以同时带来喜欢与担心。主词和增减由模型选，源码没有对“同向必加一档”作数值强制，也没有为每个维度另建分数。 |
| E04 工作、交流与确定事实 | R4、R5 | 十档从负 5 至负 1，再从正 1 至正 5。任务终态一次 −1，完整对话经评价取 −1／0／+1，待评先以 0 参与排序。成功任务及可辨认的最终失败有入口。核验的桌宠功能更新可另记 +1，同一事件键去重。 | “工作 −1、交流最多一档”有推荐方案采纳。**独立改善 +1、独立损失 −1** 是我为方向补的幅度。内核接受损失事件，但本次没找到业务侧直接提交独立损失的调用，用户上进也没有通用的成果收集入口。能通过对话评价反映。 |
| E05 满足和满值保护 | R5 | 奖励针对事件发生前已生效的同一欲求。模型判满足，并须在用户原话或事实标题中找到逐字引文。核实后升正 5，保护次数累加 3，该事件不再重复算普通增减。保护中每次完整交流或工作消耗一次，最后一次仍正 5。 | 拉满、三次、累加来自用户。“逐字引文＋欲求 ID＋事件键”、按核实时间补发是我的证据设计。模型忙时奖励会等核实，且逐字命中本身不能证明语义正确。 |
| E06 延迟结算、情绪表达 | R4、R5，机制自定 | 历史回读、待机、开新周不扣分。迟到事件按时间与顺序重算受影响的后段，防止迟到旧表达覆盖较新的内心话。无需模型时可能用“疲惫／担忧／平静／开心”等固定词，评价到达后可换词。 | 修复重试重复领奖、乱序扣次。这些固定词和回退句是实现者写的，不能用它们证明每句话都是从角色经历推出来的。 |
| E07 放下、换回和新欲求 | R5、R8，判据自定 | 模型可建议保留、满足或放下。当前欲求匹配且评价仍适时才清除；放下不给奖。有被指定欲望暂存的旧愿望就恢复，否则可按本轮有效的新愿望和条件生成下一项。 | 防止旧愿望永久堵住位置。提示把“误会消除”列为可放下的理由，容易把某件事得到澄清误当成另一个愿望也消失。这里没有用户逐项授权。 |
| E08 爱情和理智 | R4、R8、R9 | 评价阶段读 assessment，决定阶段读 nextStep。设计把事项走向归成延续或等待、加深、缓和、改判与修复、满足与收束、停止追问或放下。运行提示只给原则，模型不用返回六选一，宿主实际执行的是算档、领奖、关闭、派发等可验证动作。 | 六个名字和划分由我提出。“用户优先”“误会后改口”“可以晚点哄”有依据。没有独立的“发现曾误会→安排道歉→确认已送达”的通用队列，也不能以提示存在证明它每次都会主动改口。 |
| E09 七面周骰 | R5 | 东京周一为边界，使用本周第一次创建的记录。与上一条有记录的周相同则重掷，最多再掷十次，再相同就顺移，七回到一。换周不会把旧欲求、保护次数清空。 | 从每轮随机改为一周一致。骰面与重掷回退都有用户明确来源；换周时保留其他状态是实现取舍。 |
| E10 对话、登记、工作继续 | R4、R8 | 普通本地对话把当前状态交给草拟、复核、改写；登记时保留当时心情和结果引用；念叨开口可取当前词与强度。任务按业务回执结算，低落不阻断执行。前台介入会让后台推理让位。 | 语气可以生气，工作仍要完成。快速固定回复、各业务报告没有全部逐句经过情绪技能。情绪评价 1.2 曾沿用早期双重身份，1.3 统一为妻子身份，1.4 按用户补充写明她是丈夫心爱的妻子、贤内助，是他口中“可爱的心尖肉肉”。 |
| E11 她可以想要什么 | R5、R7 | 用户给了三类例子：希望自己得到功能改进，希望被关爱陪伴，想尝试一种可行的改进或冒险。交流评价可自由生成期望文字和满足条件，主动阶段再受已有动作入口限制。例如她可以提出想获得某项能力，后来用真实的核验结果判断有没有得到。 | 给愿望定具体条件才能区分“想获准尝试”和“想实际完成”。代码没有为三类愿望分别计分，也没有让她自行安装功能的动作。交流生成的当前欲求只有 ID、内容、条件和时间，单看状态快照不能读出完整缘由，须回查对应评价。 |

七面内容本身也有出处。**1 贪婪**分享结论求评价，**2 色欲**想拉近关系，**3 傲慢**查证或请用户代查，**4 暴怒**敏感、冷言、等哄，**5 嫉妒**想被主动关心，**6 怠惰**整理反省，**7 暴食**好奇用户往事。这是用户给的映射。代码多数时候只把当周的一句倾向送进模型。傲慢周有明确的公开查询门槛；暴怒的运行值是“敏感、直率，想被安抚”，没有一个能保证“未哄持续冷言、被哄后退出”的独立状态机。

## 四、欲求如何成为一个动作

| 功能 | 来源 | 现行行为与改动 | 实现理由及边界 |
|---|---|---|---|
| D01 观察与两次判断 | R6、R8 | 先由程序汇集上次关注、当前欲求、周倾向、待问事项、最近事实与专题。第一次模型调用提出欲求，不显式输入当前情绪；第二次才加入情绪、喜好、可用动作，生成结论、行动、下轮关注。 | 满足用户纠正的先后顺序。固定为一次观察加两次模型调用、轮转一小批材料是工程方案。上轮关注是自然语言，没法由此保证第一层完全不含间接情绪线索。 |
| D02 多候选中挑一件 | R6 | 每轮最多提五项，须指定事实索引、来源罪名、类型、所求和满足条件。模型标记愿意行动时取排首位的普通候选，其他有效项存池。程序还会先看有无可执行的强制项。 | 用户要求只落实一个，却没有要求第一项一定代表最重要的一项。模型排序、五项上限、每次从哪些材料里挑，都会改变一件事被想到的概率。 |
| D03 欲求分类与去重 | R5、R6 | 每项都有用户要求的七罪系列。代码另外造了七种用途：问清、分享、求陪伴、问往事、整理、改喜好、求证。用“来源引用＋用途”作唯一键，原项已办结或清掉时同键不再入池。 | 用途是为了把愿望交给现有执行入口。它和七罪是两套分类；同源、同用途但满足条件不同的两项愿望可能被合并。后者是实现造成的损失。 |
| D04 动作可行性 | R6、R8 | 选定欲求后只允许对应动作或等待。念叨来源能提问，专题能排入本机查证，分享／陪伴／往事通过发言，整理／改喜好通过写专题。傲慢周且有可公开检索词才可查 Web，保存来源标题和链接。 | 保证说要分享就不能转去整理并记成分享成功。按七类绑定动作和“可行时仍能选等待”是设计取舍；程序没有判定每个等待理由在心理上都必要。 |
| D05 低落时躲清闲 | R4、R6，后续纠正优先 | 已选具体事情时，负 5 仍按那件事情推进。没有新候选时才查可做的池项。仍无可办项、有普通来源时，代码可直接生成“整理这条记录／已保存带出处的摘记”，归入第 6 系。 | 修正了低落时偷偷把分享换成整理的偏离。**固定生成这条愿望并归为怠惰**是我额外写的，可能计入池，与“更倾向整理”仍有区别。没有材料就不凭空写摘记。 |
| D06 有效计数与达标时机 | R6 | 统计同罪名、仍在池中的有效项。本轮选中准备执行的项不算入阈值。满 100 后登记该系待执行资格，在可用名额挑一件。 | 门槛及分类来自用户。把“触发”与“有条件实际派发”分开，是为了前台忙、用户在回答原事时不再冒出一件新事。 |
| D07 强制选谁与抢占 | R6，自定取舍 | 多系列按触发顺序尝试，各系选最早入池且当前可执行的一件，暂不可行的系列可让路。代码沿用池中那条欲求及原满足条件，再生成行动决定。已触发的资格在其他清池导致本系跌破 100 后仍可保留。 | 便于在重启后选回同一件。先来先办、保留资格及沿用旧愿望是我的选择。用户说“生成”指定欲望；当前复用旧愿望。早期设计还建议优先有多份独立证据的主题，代码实际按入池顺序找可执行者。 |
| D08 清池、重试与证据 | R6 | 实际领取时，指定项移入执行中，本系其他在池项全部清退。其他系列合在一起随机无放回抽取总数的一半，向上取整。记录抽中的 ID。派发失败可重试同一指定项，不再抽第二次。 | 用户定了清谁和向上取整。**把其他系列合在一起抽**是现有设计对原话的解释，未见用户亲自比较过逐系与合并两种算法。事务和固定重试名单用于避免重复清池。 |
| D09 反馈与当前欲求 | R5、R6 | 一般开口已展示可结本轮，原本没有当前欲求时才采纳新项。强制开口则可暂存旧欲求、占位等反馈，用户回应或结束后关轮；满足与拒绝走不同结算。明确拒绝对应项可恢复暂存的愿望。 | 避免丢掉旧愿望并尊重拒绝。**强制项挂起旧愿望、反馈优先阻塞下一轮、随后恢复**均是我的规则。普通主动发言没有与强制发言相同的跨轮等待锁；“一件直到反馈”在两种路径上的力度不同。 |
| D10 轮次结束与恢复 | R6、R8 | 前一轮距今不足两小时可不再启动；等待及有记录的中断也可占该窗口。派发结果不明时先查同轮对话、念叨或专题落盘回执；没有证据就等待。前台抢占、模型输出无效、公开搜索失败分别记下断点。 | 用户要求一次一个，未要求一次失败也用掉机会，或不确定时一直阻塞。这是我偏向避免重复打扰的恢复策略，代价是可能少开口或长时间卡在待核实。 |

## 七、三条可复查的转移

1. **她在等陪伴，你说“晚上陪你”。** 用户亲自规定满足才拉满，也采纳可以晚点哄。按设计，承诺可缓和心情，盼实际陪伴的欲求继续存在。程序要求模型判断和原话命中；它没有独立核实“承诺／已发生”的语义，仍可能误判。以后一次实际交流确实满足旧条件，才应当正 5、剩余次数加 3。若当时剩 2 次，结算后为 5 次，下一项工作完成后为 4 次。
2. **负 5，已选把画稿给你看，旁边还有待整理记录。** 画稿具备分享条件时，第二阶段能选发言或等候，不能拿整理回执结清画稿。没有新意图且没有能推进的池项时，程序才可能给自己造一条第 6 系整理欲求。前一个优先级是你的决定，后一个“造出一条怠惰欲求”是我的决定。
3. **某系 100 项，其他两系分别余 1、3 项。** 强制派发取得同系一个可行对象，其余同系候选清退。当前程序将异系合为 4 项，随机清 2 项。如果逐系向上取整则会清 1＋2＝3 项，两者会留下不同欲望。展示回执不明时，当前实现停在原轮核实，重试不会再清一遍。这说明哪一半被清、什么时候还能行动，并不都能直接从用户一句“随机清一半”推出。
