## 4. 怎么运行

```bash
node tools/dev-server.mjs 8780
```

浏览器（Chrome/Edge）打开 `http://localhost:8780/site/?cycle`。点击画面开始；WASD 移动、Shift 跑、鼠标看、E 开关门（站在中门前）、P 自动时间、`,` `.` 拨时间、H 提示、Esc 释放鼠标。`?t=9` 指定时间；`?debug` 打开调试钩子（`__go`、`__look`、`__setTime` 等）。

注意：开发服务只提供 `site/` 和 `vendor/`。

## 5. 怎么重建资源（Blender MCP，Blender 5.2）

脚本里写死了 `G:/selftool/Cathedral/...`（`build_all.py`、`massing.py`、`lighting.py`、`bake.py`、`bake_ext.py`、`collision.py`、`preview.py`、`materials.py`）。并入仓库后目录是 `cathedral/`，换机器或换位置时要改这些路径。

1. 在**单独的一次调用里**清空场景：`bpy.ops.wm.read_homefile(use_empty=True)`（和建模放在同一次调用会因上下文未刷新而报错）。
2. `STEP='model'` 再 `exec(build_all.py)`：建模、材质、光照、分组展 UV、射线分类（外部网格里朝向室内的面归室内）。约 20 秒。
3. **`STEP='int'` 必须在任何导出步骤之前**：导出会把玻璃换成不透明单色材质，之后再烘室内窗户全被堵死（`bake_group()` 已加断言）。约 1–2 分钟。
4. `STEP='ext1'`（外部颜色）→ `STEP='ext2'`（外部遮蔽、编码、导出到 `site/assets_next/`）。导出会替换材质，之后要重新清空并建模。
5. `STEP='export'` 是旧的整体导出（碰撞网格、旧的外部和室内），现在只用于重新生成碰撞网格；它会写入 `site/assets/` 的旧文件。
6. MCP 单次调用超过约 2 分钟会提示 “No data received”，但 Blender 在后台继续跑；以输出文件的时间戳为准。
